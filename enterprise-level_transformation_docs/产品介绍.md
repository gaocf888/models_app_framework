# 大模型在线应用平台 — 产品介绍

> **文档性质**：面向业务方、产品规划与客户推介的产品说明，介绍平台定位、基座能力与业务应用价值。  
> **技术细节**：架构实现、接口契约与代码对照请参阅 [系统白皮书v1.md](./系统白皮书v1.md) 及同目录专项文档。

## 一、产品概述

**大模型在线应用平台** 是一套面向能源、电力等工业场景的企业级 AI 应用基座。平台将大语言模型推理、知识检索增强（RAG）、自然语言问数（NL2SQL）、多轮会话管理与全链路可观测性沉淀为可复用能力，并在此之上交付智能客服、综合分析、检修报告解析等开箱即用的业务应用。

平台不绑定单一业务场景——新业务可通过配置 Prompt 模板、RAG 知识域与 LangGraph 编排节点快速接入，无需重复建设底层 AI 基础设施。

### 核心价值

| 价值维度 | 说明 |
|----------|------|
| **统一基座** | 推理、检索、问数、会话、观测收敛为一套服务，避免各项目重复造轮子 |
| **生产可控** | SQL 只读校验、知识库命名空间隔离、Prompt 版本治理、全链路 Trace 审计 |
| **场景可扩展** | 智能客服、综合分析、文档抽取等应用共享同一套 RAG / NL2SQL / LLM 基座 |
| **编排可演进** | LangGraph 状态图编排，支持灰度发布与 Legacy 一键回退 |

### 典型用户与场景

- **运行/检修人员**：现场拍照缺陷识别、超温原因分析、泄爆事故溯源
- **知识管理与客服**：规程问答、台账统计、多轮澄清引导
- **数据分析人员**：自然语言问数、多指标并行取数、结构化分析报告
- **文档处理人员**：检修报告 Word/PDF 自动抽取为标准缺陷记录

## 二、系统基座能力

基座能力是平台的技术底座，被所有上层业务应用共享复用，构成相对「单点 LLM 封装」的系统性优势。

### 2.1 混合 RAG 知识检索

**能力介绍**

将企业文档、规程、案例、Schema 说明等非结构化知识转化为可检索的知识库，在问答与分析时按场景自动召回相关片段，为大模型提供有据可依的上下文，有效抑制「幻觉」。

**技术亮点**

- **多路召回**：语义向量 + 关键词/BM25 + 可选元数据过滤，并行召回后 RRF 融合
- **精排增强**：CrossEncoder（如 bge-reranker）二次重排，显著提升 Top-K 相关性
- **分层封装**：支持向量检索、图知识检索（GraphRAG）及混合路由；Agentic RAG 支持多步子问题规划
- **场景隔离**：按 `scene`（客服、分析、问数等）与 `namespace` 隔离知识域，避免跨域污染
- **知识运维一体化**：异步文档摄入、多格式支持（PDF/Word/Markdown 等）、索引迁移、检索调试与运营统计

### 2.2 NL2SQL 自然语言问数

**能力介绍**

将用户的自然语言问题转化为安全、可执行的只读 SQL，从业务数据库中查询台账、测点、缺陷、检修记录等结构化数据，并以自然语言总结返回。与 RAG 并列，构成平台「非结构化知识 + 结构化数据」双轮驱动能力。

**技术亮点**

- **Schema 认知增强**：数据库反射 + 三命名空间 RAG（表结构、业务知识、QA 样例）融合，提升复杂问句理解准确率
- **安全执行边界**：只读 SQL 校验、表白名单、列–表绑定，多层防护杜绝写操作与越权查询
- **质量闭环**：EXPLAIN 预检、执行失败自动 refine、校验通过后自动沉淀 QA 样例
- **多入口同源复用**：独立问数 API、智能客服查库、综合分析取数、看图诊断问数臂共用同一套 NL2SQL 服务，逻辑与安全边界一致
- **智能后处理**：时间窗程序解析、实体范围识别、SQL 占位符改写，适配工业场景复杂时间语义

### 2.3 大模型推理（LLM）

**能力介绍**

统一对接 vLLM 等 OpenAI 兼容推理服务，承载文本生成、多模态看图、流式输出等全部大模型调用需求。

**技术亮点**

- **双轨调用**：LangChain `ChatOpenAI` 优先，失败自动回退原生 HTTP 客户端，保障可用性
- **流式 SSE**：全业务场景支持 Server-Sent Events 流式响应，提升交互体验
- **Prompt 治理**：YAML 集中管理 Prompt 模板，支持按场景/分析类型/用户 A/B 分流
- **多模态支持**：看图诊断、客服图片预处理等场景原生支持视觉模型调用
- **可选观测**：集成 LangSmith 链路追踪，便于 Prompt 调优与问题定位

### 2.4 多轮会话管理

**能力介绍**

为智能客服、通用推理等需要上下文记忆的场景提供统一的多轮会话能力，支持跨请求、跨实例的会话共享与长期归档。

**技术亮点**

- **热冷分层**：Redis 热层保障低延迟读写；EasySearch 冷层归档，热层 TTL 过期后仍可回查
- **全业务复用**：客服、LLM 推理等模块共用 `ConversationManager` 抽象，会话目录、条数上限、TTL 统一治理
- **可选对象存储备份**：支持 local / S3 增强会话持久化
- **强校验治理**：`user_id` / `session_id` 强校验，防止会话串扰

### 2.5 可观测性与安全

**能力介绍**

贯穿全链路的指标采集、日志审计与安全防护，满足企业生产环境的合规与运维要求。

| 类别 | 能力 |
|------|------|
| **指标监控** | Prometheus `/metrics`；HTTP 延迟/计数；各业务域专属 counter |
| **结构化日志** | JSON 格式，支持文件滚动与压缩 |
| **分析 Trace** | 综合分析全链路节点级 Trace，支持列表/回放/统计/趋势 |
| **统一鉴权** | Service API Key（Bearer），常量时间密钥比对 |
| **内容安全** | RAG 远程 URL 拉取 SSRF 防护；NL2SQL 只读 SQL 多层校验 |

## 三、业务应用

### 3.1 AI 问答（智能客服）

**应用介绍**

面向终端用户的企业级智能客服，统一承接知识问答与结构化查库两类需求。用户可用自然语言提问规程条文、操作指南、历史案例，也可直接查询台账统计、设备状态等数据库信息，系统自动识别意图并选择最优应答路径。

**典型场景**

- 「#3 机组过热器最近一次超温发生在什么时候？」→ 结构化查库
- 「锅炉四管泄漏的应急处置流程是什么？」→ 知识库问答
- 「它的检修周期是多久？」→ 多轮指代消解后继续作答

**技术与实现亮点**

| 亮点 | 说明 |
|------|------|
| **意图三分支** | 自动识别 `kb_qa`（知识问答）、`data_query`（结构化查库）、`clarify`（澄清引导），分流至 RAG 或 NL2SQL |
| **人机协同 HITL** | 意图边界可确认；补充后仍模糊则给候选问法点选；查库 SQL 生成失败可重试或改知识库 |
| **LangGraph 编排** | 状态图化多步流程，支持 Checkpoint 与 Legacy 顺序回退，灰度无忧 |
| **上下文指代消解** | 规则判型 + 检索 query 融合 + 对话锚块 + 会话槽位，解决「它」「上次那个」类多轮指代 |
| **本厂知识范围解析** | 按业务规则限定 RAG 命名空间，避免跨机组/跨系统知识污染 |
| **流式 SSE 响应** | 主答流式输出，支持 `stream_id` 显式中断 |
| **关联推荐问** | 主答后自动生成关联问题，引导用户深入探索 |
| **相似事故案例** | 可选二次检索，主答后追加相关历史案例 |
| **多模态预处理** | 支持图片上传，自动缩放/压缩后送入多模态模型 |

---

### 3.2 检修报告解析

**应用介绍**

将非结构化的检修报告（Word/PDF）自动转化为标准化、可入库的缺陷记录 JSON。解决传统人工录入效率低、格式不统一、表格语义难以机器理解等痛点，为缺陷台账、统计分析、检修决策提供结构化数据基础。

**典型场景**

- 上传锅炉四管检修 Word 报告 → 自动抽取缺陷位置、类型、壁厚、检测方法等字段
- 扫描版 PDF 检修记录 → 可选 MinerU 解析后 LLM 结构化抽取
- 带颜色标注的壁厚检测表格 → V2 管线按单元格颜色校正检测类型

**技术与实现亮点**

| 亮点 | 说明 |
|------|------|
| **文档解析路由** | docx / pdf 自动路由；扫描 PDF 可选 MinerU 深度解析 |
| **LLM 三阶段抽取** | parse → classify → repair 分块处理长文档，兼顾准确率与完整性 |
| **V2 颜色语义校正** | 识别表格单元格颜色标注，与壁厚检测类型联动校正，显著提升工业表格抽取准确率 |
| **规则后处理** | 缺陷归一、阈值绑定（位置匹配 + 段落近邻 + 谨慎全局回退），输出可追溯 warnings |
| **结构化契约** | Pydantic 强校验输出，直接对接下游入库系统 |
| **对象存储集成** | MinIO 持久化 + 预签名 URL，支持大文件异步处理 |
| **V0 独立管线** | LangGraph + PaddleOCR 版面侧车，适配复杂版式文档 |

### 3.3 超温分析

**应用介绍**

针对锅炉受热面超温事件，自动从运行数据库中取数，结合业务知识库，生成结构化的超温原因分析、影响评估与处置建议报告。帮助运行人员快速定位超温根因，缩短事故响应时间。

**典型场景**

- 输入机组、受热面、时间范围 → 自动取测点曲线、历史超温记录、关联运行工况
- 输出多槽位结构化报告：超温概况、趋势分析、可能原因、处置建议、运行监护要点

**技术与实现亮点**

| 亮点 | 说明 |
|------|------|
| **NL2SQL 多任务并行取数** | 分析计划驱动 9+ 项 SQL 并行执行，一次请求覆盖多维度数据 |
| **规划前 RAG** | 分析前自动检索相关业务知识与历史案例，丰富分析上下文 |
| **synthesis 多槽位编排** | v2 模板支持 14 槽 narrative 结构化输出，报告格式统一可控 |
| **质量门控** | 取数结果质量校验，数据不足时降级提示而非强行编造 |
| **全链路 Trace** | 节点级执行摘要，支持排障、审计与效果分析 |
| **流式报告输出** | synthesis 阶段 SSE 流式，用户实时看到报告生成过程 |

### 3.4 缺陷识别（看图诊断）

**应用介绍**

检修/运行人员在停机或巡检场景上传现场照片，配合自然语言描述（机组位置、管段、时间等），系统自动完成视觉缺陷判定、历史数据关联与知识库检索，输出缺陷风险等级与分风险处置方案。

**典型场景**

- 上传受热面管壁裂纹、腐蚀、磨损等现场照片
- 描述「#2 机组高温过热器第 3 管排，上周巡检发现」
- 输出：缺陷类型判定、风险等级、打磨补焊/换管/运行监护等分风险处置建议、历史相似案例

**技术与实现亮点**

| 亮点 | 说明 |
|------|------|
| **三路并行分析** | 视觉臂（多模态 LLM 看图）‖ NL2SQL 臂（历史缺陷/测点取数）→ 业务 RAG 臂 → 合成报告 |
| **人机协同 scope 确认** | LangGraph HITL 子图：机组/受热面解析不确定时中断确认，库表 existence 校验保障数据准确 |
| **专用视觉 Prompt** | `analysis_img_diag_vision_defect_ident` 针对缺陷场景优化视觉理解 |
| **9 项数据计划** | q1 + q2a～q2e + q3～q5 覆盖缺陷历史、壁厚、运行工况等多维数据 |
| **时间锚点回溯** | 从事故/巡检描述中解析时间语义，自动改写 SQL 时间占位符 |
| **流式 SSE + Trace** | 支持流式报告输出与全链路节点 Trace 回放 |

### 3.5 泄爆分析（看图诊断）

**应用介绍**

针对锅炉受热面泄漏、爆管等事故场景，结合可选现场照片、自然语言事故描述与运行数据库，进行泄爆溯源分析。按五大类方向（设计制造、安装检修、运行操作、燃料品质、外部环境）× 三层逻辑（直接原因、中期原因、根因）输出结构化溯源报告与防控建议。

**典型场景**

- 事故发生后录入「#1 机组水冷壁东侧第 5 管排于 2025-03-15 14:30 发生泄漏」
- 可选上传爆口、相邻管段等现场照片
- 输出：泄爆溯源五类分析、事故案例对照、规程条文引用、运行防控建议

**技术与实现亮点**

| 亮点 | 说明 |
|------|------|
| **图片可选** | 无图时跳过视觉臂，仅凭问数 + 知识库完成溯源分析 |
| **五类×三层 synthesis** | 专用合成模板，输出符合事故调查规范的结构化报告 |
| **业务 RAG 专项检索** | 检索泄爆溯源、事故案例、规程条文、防控资料等专项知识 |
| **时间语义强化** | 强烈建议 query 含事故发生时刻；支持锚点向前回溯取数 |
| **与缺陷识别共用编排** | 同一看图诊断框架，按 `img_diag_subtype` 切换子场景，降低维护成本 |

### 3.6 其他综合分析能力

除上述核心场景外，平台综合分析模块还支持以下专项（共享同一套 LangGraph 编排与 NL2SQL 取数基座）：

| 分析类型 | 说明 |
|----------|------|
| **检修策略** | 基于设备状态、缺陷记录与检修规程，生成检修策略建议 |
| **四管健康报告解读** | 对四管健康检测数据进行智能解读与趋势分析 |
| **通用 payload 分析** | 调用方直接提供分析载荷，灵活适配定制化分析流程 |
| **独立 NL2SQL 问数** | BI、低代码、运维脚本直接调用问数 API，无需完整分析流程 |

## 四、平台架构一览

```
┌─────────────────────────────────────────────────────────────┐
│  业务应用层                                                  │
│  智能客服 · 超温分析 · 缺陷识别 · 泄爆分析 · 检修报告解析    │
├─────────────────────────────────────────────────────────────┤
│  编排层：LangGraph 状态图 · LangChain 多步链 · Prompt 治理   │
├─────────────────────────────────────────────────────────────┤
│  基座能力层                                                  │
│  混合 RAG · NL2SQL · LLM 推理 · 会话管理 · 可观测性          │
├─────────────────────────────────────────────────────────────┤
│  基础设施：FastAPI · Redis · EasySearch · vLLM · MySQL       │
└─────────────────────────────────────────────────────────────┘
```

**接入方式**：REST API + SSE 流式；OpenAPI 文档；统一 Bearer 服务密钥鉴权。

**部署形态**：容器化多栈互联（应用、vLLM、向量库、Redis、可选 MinerU/Neo4j），环境变量统一配置，便于多环境复制与运维。

## 五、能力对比：为什么选择本平台

| 对比维度 | 单点 LLM 封装 | 本平台 |
|----------|---------------|--------|
| 知识问答 | 通用 Prompt，易幻觉 | 自研混合 RAG + 命名空间隔离 + 指代消解 |
| 数据查询 | 无法查库或手写 SQL | NL2SQL 多入口同源，安全只读校验 |
| 多轮对话 | 无状态或简单缓存 | Redis 热层 + ES 冷层，跨实例共享 |
| 工业分析 | 单轮文本生成 | LangGraph 多步编排 + 并行取数 + 结构化报告 |
| 看图诊断 | 纯视觉模型 | 视觉 + 问数 + 业务知识三路并行合成 |
| 文档抽取 | 通用 OCR + LLM | 三阶段抽取 + 颜色语义 + 规则后处理 |
| 生产运维 | 黑盒 | Prometheus + Trace + Prompt 版本治理 + 灰度回退 |

## 六、快速开始

1. **部署基座**：vLLM + EasySearch + Redis + 应用栈，配置服务密钥与 LLM 端点
2. **导入知识**：通过 RAG 运维接口摄入规程、案例、Schema 说明等知识文档
3. **验证问答**：对接智能客服流式接口，体验知识问答与结构化查库
4. **启用分析**：按需对接超温分析、看图诊断或检修报告解析接口

详细部署与集成指南请参阅 [系统白皮书v1.md](./系统白皮书v1.md) 第 8 节「集成建议」及 [项目整体部署运维手册.md](./项目整体部署运维手册.md)。
