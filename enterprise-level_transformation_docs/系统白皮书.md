## 摘要

本平台是一套 **企业级大模型在线应用基座**，以 **FastAPI** 统一对外暴露 HTTP 能力，以 **vLLM（OpenAI 兼容协议）** 承载大语言模型与多模态推理，以 **自研混合 RAG**（多路召回 → RRF 融合 → CrossEncoder 重排）与 **NL2SQL**（受控只读 SQL）构成可复用的 AI 基础能力，并通过 **LangChain / LangGraph** 将通用推理、智能客服、综合分析、检修报告结构化提取等场景编排为 **可配置、可观测、可灰度** 的生产级服务。

平台不绑定单一业务场景，可在同一套架构上支撑知识问答、结构化问数、多源数据分析、文档智能抽取等上层应用；配置集中于环境变量与 `app/core/config.py`，部署采用容器化多栈互联（应用、向量库、Redis、可选 MinerU/Neo4j），便于在多环境中复制、审计与运维。

## 1. 平台定位与价值主张

### 1.1 是什么

| 维度 | 说明 |
|------|------|
| **产品形态** | 大模型在线应用平台（AI App Platform） |
| **接入方式** | REST API + SSE 流式；OpenAPI 文档；统一 Bearer 服务密钥鉴权 |
| **编排范式** | LangChain 多步链 + LangGraph 状态图（客服、综合分析） |
| **知识增强** | 自研 RAG 检索引擎 + 可选 GraphRAG（Neo4j） |
| **结构化问数** | NL2SQL 子系统，与 RAG 并列的基础能力 |
| **会话与上下文** | Redis 热层 + EasySearch 冷层归档，全业务复用 |

### 1.2 解决什么问题

1. **能力碎片化**：将推理、检索、问数、会话、观测收敛为统一基座，避免各项目重复建设。  
2. **生产可控**：SQL 只读校验、RAG 摄入 SSRF 防护、Prompt 版本管理、Trace 审计与 Prometheus 指标贯穿全链路。  
3. **场景可扩展**：新业务通过新增 LangGraph 节点、Prompt 模板与 RAG 命名空间即可接入，无需替换底层存储与 LLM 客户端。  
4. **编排可演进**：智能客服与综合分析支持 LangGraph 主路径 + Legacy/顺序回退，支持灰度与一键回滚。

### 1.3 典型使用场景

- **智能客服**：多轮知识问答、台账统计类结构化查库、澄清引导、流式 SSE 响应。  
- **综合分析**：超温分析、检修策略、四管健康解读、泄爆分析等专项；支持 NL2SQL 多任务并行取数 + 结构化报告；**看图诊断** 三路并行（视觉 / 问数 / 业务 RAG）后合成。  
- **检修报告结构化提取**：Word/PDF 检修报告 → 标准化缺陷记录 JSON；V2 支持表格颜色语义校正。  
- **独立问数**：BI、低代码、运维脚本直接调用 `POST /nl2sql/query`。  
- **知识库运维**：异步文档摄入、索引迁移、检索调试与运营统计。

## 3. 平台基座能力（核心亮点）

基座能力被各业务模块 **共享复用**，是平台差异化的技术底座。

### 3.1 自研混合 RAG 检索引擎

**亮点**：在线主检索链路为自研 `RAGService`，而非简单封装 LangChain RAG 链，具备企业级召回质量与可运维性。

| 环节 | 能力 |
|------|------|
| **多路召回** | 语义向量 + 关键词/BM25 + 可选元数据过滤，并行召回 |
| **融合** | RRF（Reciprocal Rank Fusion）可调权重融合 |
| **重排** | CrossEncoder（默认 Qwen3-Reranker-0.6B）精排；失败时保留 RRF 序 |
| **分层封装** | `HybridRAGService` 叠图路由（vector / graph / hybrid）；`AgenticRAGService` 支持多步子问题规划与检索预算 |
| **场景化** | 按 `scene`（如 `chatbot`、`analysis`、`nl2sql`）与 `namespace` 隔离知识域 |
| **存储抽象** | `VectorStoreProvider` 对接 ES/EasySearch 或 FAISS |

**知识摄入**：异步 Job 编排（`IngestionOrchestrator`），支持 PDF/Docx/Markdown/HTML 等多格式；可选 MinerU 处理扫描件；任务状态可轮询、可重试；管理写与在线只读分离。

> 详见：[企业级 RAG 文档摄入与检索一体化改造设计稿-20260327.md](./企业级%20RAG%20文档摄入与检索一体化改造设计稿-20260327.md)

### 3.2 NL2SQL — 与 RAG 并列的结构化问数基座

**亮点**：同一 `NL2SQLService` 被 **独立 HTTP、智能客服、综合分析、看图诊断** 等多入口复用，保证问数逻辑一致、安全边界统一。

| 环节 | 能力 |
|------|------|
| **Schema 认知** | 数据库反射（表/列/外键）+ 三命名空间 RAG（`nl2sql_schema`、`nl2sql_biz_knowledge`、`nl2sql_qa_examples`）融合 |
| **生成链路** | LangChain 多步链：规划 → RAG → Prompt → LLM 生成 SQL |
| **安全执行** | `SQLValidator` 只读校验、表白名单、列–表绑定；`SQLExecutor` 受控执行 |
| **质量闭环** | EXPLAIN 预检、执行失败 refine、校验通过后自动写入 QA 样例（五元组去重） |
| **缓存优化** | L1/L2 时间口径缓存，降低重复问数成本 |
| **问句意图** | 时间窗程序解析 + 实体范围 rule/LLM 双模式；SQL 后处理改写 `@t_*` / 锅炉与可选 scope 占位符 |

> 详见：[企业级NL2SQL实现方案.md](./企业级NL2SQL实现方案.md)

### 3.3 大模型调用基座

- **双轨调用**：LangChain `ChatOpenAI` 优先，失败回退 `VLLMHttpClient`（httpx 异步）。  
- **协议对齐**：OpenAI Chat Completions，含 SSE 流式。  
- **Prompt 治理**：`PromptTemplateRegistry` + `configs/prompts.yaml`，支持版本与 A/B 分流。  
- **可选观测**：LangSmith 链路追踪（`LangSmithTracker`）。

### 3.4 多轮会话与上下文管理

**亮点**：热冷分层 + 全业务统一抽象，支撑长会话与跨实例共享。

| 能力 | 说明 |
|------|------|
| **热层** | Redis（ZSET 目录 + Hash 元数据 + List 消息）；独立 asyncio 线程隔离 I/O |
| **冷层** | EasySearch 归档；热层 TTL 过期后仍可回查 |
| **备份** | 可选 local / S3 对象存储增强 |
| **治理** | `user_id` / `session_id` 强校验；TTL、条数上限、会话目录 API |

> 详见：[系统会话管理实现方案.md](./系统会话管理实现方案.md)

### 3.5 可观测性与安全

| 类别 | 实现 |
|------|------|
| **指标** | Prometheus：`/metrics`；HTTP 延迟/计数；LLM 调用专用指标；各业务域专属 counter |
| **日志** | 结构化 JSON，支持文件滚动与压缩 |
| **Trace** | 综合分析全链路 Trace（Redis / ES 归档 / 内存）；节点级 `execution_summary` |
| **鉴权** | Service API Key；未配置时业务路由 503；密钥本地生成，无运行时签发接口 |
| **内容安全** | RAG 远程 URL 拉取 SSRF 防护；NL2SQL 只读 SQL 多层校验 |

## 4. 业务应用能力

### 4.1 通用大模型推理（`/llm`）

**定位**：轻编排的通用推理入口，供不需完整客服/分析流程的场景直接调用。

- 单轮/多轮消息；可选会话落库。  
- 可选 **basic / agentic** RAG 预处理。  
- 与客服、分析 **共享 LLM 客户端、Prompt 注册表与 RAG 基座**。

### 4.2 智能客服（`/chatbot`）— 核心亮点

**定位**：面向终端用户的多轮对话服务，是企业知识问答与结构化查库的统一入口。

#### 编排架构

- **主路径**：`ChatbotLangGraphRunner`（LangGraph StateGraph）  
- **兼容回退**：Legacy 顺序链路，图异常或配置关闭时自动回退  
- **流式输出**：SSE；支持 `stream_id` 显式中断  

#### 意图三分支（核心分流逻辑）

| 意图 | 路径 | 能力 |
|------|------|------|
| **kb_qa** | 文档知识问答 | RAG 检索 → 可选 C-RAG 重写 → 流式主答 |
| **data_query** | 结构化查库 | 内嵌 NL2SQL → 结果自然语言总结（无主链路 RAG） |
| **clarify** | 澄清引导 | 短句/指代不清时固定澄清话术 |

#### 企业级增强特性

1. **本厂专属知识库范围解析**（`rag_scope_resolve`）：按业务规则限定 RAG 命名空间，避免跨域污染。  
2. **上下文指代消解**（P0～P3）：规则判型、检索 query 融合、对话锚块、会话槽位、可选 Coref 小模型（默认关）。  
3. **多模态预处理**：图片缩放/压缩/本地落盘，降低传输与上下文开销。  
4. **关联推荐问**：规则表 + 本轮召回片段种子 + 可选 LLM 补全（`suggested_questions`）。  
5. **相似事故案例**（可选）：限定 namespace 二次检索，主答后 delta 追加。  
6. **大纲索引**（`ChatbotOutlineStore`）：支持「上文第 N 点」类指代旁路增强。

> 详见：[企业级智能客服 LangGraph 框架实现方案.md](./企业级智能客服%20LangGraph%20框架实现方案.md)

### 4.3 综合分析（`/analysis`）— 核心亮点

**定位**：面向运维/分析场景的多源数据智能分析引擎，支持专项分析类型与多模态看图诊断。

#### 运行入口

| 入口 | 场景 |
|------|------|
| `POST /analysis/run-with-payload` | 调用方直接提供分析载荷 |
| `POST /analysis/run-with-nl2sql` | NL2SQL 驱动取数 + 结构化报告 |
| `POST /analysis/run-with-nl2sql-stream` | 同上，synthesis 阶段 SSE 流式 |
| `POST /analysis/run-img-diag` | **看图诊断**（机组位置 + 图片 + 提问） |
| `POST /analysis/run-img-diag-stream` | 看图诊断流式 synthesis |
| `POST /analysis/img-diag/upload` | 看图诊断图片上传 |

#### 专项分析类型

- 超温分析（`overheat_guidance`）  
- 检修策略（`maintenance_strategy`）  
- 四管健康报告智能解读（`four_tube_health_interpretation`）  
- 泄爆分析（`leakage_burst_analysis`）  

#### LangGraph 主编排链（NL2SQL 模式）

```
格式化入参 → 规划前 RAG → 意图识别 & 数据计划 → acquire_data（NL2SQL 并行取数）
    → 质量门 → 主分析前 RAG → synthesis（结构化报告）→ finalize
```

#### 看图诊断 — 平台差异化能力

**三路并行**（`asyncio.gather`）后合成，非第三套 StateGraph，而是继承 NL2SQL 图节点的并行编排：

```
                    ┌─ 视觉臂（多模态 LLM 看图）
用户提问 + 图片 ───┼─ NL2SQL 臂（复用父类节点至质量门）
                    └─ 业务 RAG 臂（scene=analysis）
                              ↓
                         synthesis 合成报告
```

- 同步：`run_with_img_diag` → `_generate_summary`  
- 流式：`iter_img_diag_stream_events` → `_stream_summary_text`  
- Trace 字段含 `data_mode=img_diag`、`parallel_lane_trace`、`evidence.vision_findings`  

#### 企业级特性

- **两套编译 StateGraph**（payload / nl2sql）+ 顺序回退  
- **NL2SQL 计划 LLM** 可选启用；plan 模板驱动（`analysis_plan_<type>`）  
- **同 dependency 层并行** `NL2SQLService.query`，提升多指标取数效率  
- **synthesis v1/v2**：v2 多槽位编排（如超温 14 槽 narrative）  
- **Trace 产品化**：列表/回放/统计/趋势/降级 TopN；Redis + ES 归档  
- **可选 Checkpoint**：memory / redis，支持长分析恢复  

> 详见：[企业级综合分析实现和使用说明.md](./企业级综合分析实现和使用说明.md)、[企业级综合分析-看图诊断实现和使用说明.md](./企业级综合分析-看图诊断实现和使用说明.md)

### 4.4 检修报告结构化提取（`/inspection-extract`）

**定位**：将非结构化检修报告（Word/PDF）转为可入库、可统计的标准化缺陷记录。

#### 生产调用模式

```
upload（MinIO 持久化 + 预签名 URL）→ run（解析 + LLM 抽取 + 规则后处理）
```

#### 核心能力

| 能力 | 说明 |
|------|------|
| **文档解析路由** | docx / pdf 自动路由；扫描 PDF 可选 MinerU |
| **LLM 三阶段** | parse → classify → repair，分块处理长文档 |
| **V2 管线** | docx 表格序列化；**颜色标注语义**（`color_guard`）按壁厚单元格颜色校正检测类型 |
| **规则后处理** | 缺陷归一、阈值绑定（位置匹配 + 段落近邻 + 谨慎全局回退）、可追溯 warnings |
| **结构化契约** | Pydantic 强校验输出 |

#### V0 独立管线（`/inspection-extract-v0`）

- LangGraph 单阶段 LLM + **PaddleOCR 版面侧车**（`paddleocr-layout-deploy`）  
- 异步 Job 队列，Redis 前缀与现网隔离  

> 详见：[企业级检修报告结构化提取实现和使用说明.md](./企业级检修报告结构化提取实现和使用说明.md)、[企业级检修报告结构化提取V0版本实现和使用说明.md](./企业级检修报告结构化提取V0版本实现和使用说明.md)

### 4.5 RAG 知识库运维（`/rag`）

**定位**：知识生命周期管理面，与对话内「自动 RAG」分离。

| 能力 | 接口示例 |
|------|----------|
| 异步摄入 | `POST /rag/jobs/ingest` → 轮询 `GET /rag/jobs/{job_id}`（文档项可选 `namespace_kb_enabled` / `namespace_kb_priority`） |
| 单篇修订 | `POST /rag/documents/upsert`（同上 kb 字段） |
| 命名空间迁移 | `POST /rag/documents/namespace/move` |
| 单篇删除 | `POST /rag/documents/delete`（**单** `doc_name`，非批量） |
| 整库清空 | `POST /rag/namespaces/{namespace}/purge`（`confirm=true`） |
| namespace 配置 | `GET /rag/namespaces`、`PATCH /rag/namespaces/{namespace}/kb-config` |
| 检索调试 | `POST /rag/query`（自动过滤 `namespace_kb_enabled=false`） |
| 索引迁移 | `POST /rag/migrations/chunks/*` |
| 运营统计 | `GET /rag/documents/overview`、`/rag/knowledge/trends` |
| NL2SQL QA 运维 | `GET/PATCH /rag/nl2sql-auto-qa` |

> namespace 启用/优先级详见：`docs/RAG基于namespace的状态和优先级的改造实现方案.md`

## 5. 核心技术亮点总结

以下能力构成平台相对「单点 LLM 封装」的 **系统性优势**：

| # | 亮点 | 价值 |
|---|------|------|
| 1 | **自研多路 RAG + RRF + CrossEncoder** | 检索质量可控、策略可配置、与 LangChain 解耦便于演进 |
| 2 | **NL2SQL 多入口同源复用** | 客服查库、分析取数、独立问数、看图诊断 NL 臂共用安全边界与 Schema 认知 |
| 3 | **LangGraph 企业编排** | 客服/分析状态图化，支持 Checkpoint、Legacy 回退、节点级 Trace |
| 4 | **看图诊断三路并行** | 视觉 + 问数 + 业务知识同请求汇合，适配工业多模态分析 |
| 5 | **会话热冷分层** | Redis 热层 + EasySearch 冷层，长会话不丢、跨 Worker 共享 |
| 6 | **Prompt 版本治理** | YAML 集中管理，按场景/分析类型/用户分流，支持 A/B |
| 7 | **摄入与检索一体化** | 异步 Job、幂等键、索引 alias 迁移、管理写/推理读分离 |
| 8 | **全链路可观测** | Prometheus + 结构化日志 + 分析 Trace + 可选 LangSmith |
| 9 | **检修报告 V2 颜色语义** | 表格单元格颜色与检测类型联动，提升工业文档抽取准确率 |
| 10 | **容器化多栈部署** | 应用、vLLM、ES、Redis、MinerU 分栈 Compose，环境变量统一配置 |

## 8. 集成建议

### 8.1 最小集成路径

1. 部署 vLLM + ES + Redis + 应用栈，配置 `SERVICE_API_KEY` 与 `LLM_DEFAULT_ENDPOINT`。

## 10. 结语

本平台以 **统一基座 + 场景编排** 的思路，将大模型推理、混合 RAG、结构化问数、会话管理与可观测性沉淀为可复用能力，并在此之上交付智能客服、综合分析（含看图诊断）、检修报告结构化提取等企业级应用。架构强调 **生产可控**（安全校验、灰度回退、Trace 审计）、**知识可运维**（异步摄入、索引迁移、命名空间隔离）与 **场景可扩展**（LangGraph 节点、Prompt 模板、分析类型插件化）。

后续演进可沿 **GraphRAG 增强**、**Agentic 工作流深化**、**分析 synthesis 多槽位模板化**、**会话语义标题与产品化目录** 等方向继续扩展，基座层无需重复建设。
