### 1.1 综合分析LangGraph图节点链路

```
normalize_request
  → plan_context_rag      （规划前 RAG，scene=nl2sql）
  → intent_llm
  → plan_llm              （生成/合并数据计划 tasks. intent_llm/plan_llm 目前通过环境变量默认关闭）
  → acquire_data            （按 dependency 分层，同层 asyncio.gather 并行 NL2SQL）
  → data_quality_gate     （质量评估，不改 gathered_data）
  → rag_enrichment        （结论前业务 RAG，scene=analysis）
  → synthesis               （v1：_build_summary_messages 单次 LLM；v2：多槽位 → 串行流式，见 analysis_synthesis_v2.py）
  → finalize
```

#### 1.1.1 两次 RAG 分别干什么
① plan_context_rag（取数之前）
命名空间：nl2sql_schema / nl2sql_biz_knowledge / nl2sql_qa_examples
每库 top_k=3，合计最多约 9 条 snippet
用途：喂给 intent_llm / plan_llm，或写入 plan task 的 question 引导（_apply_plan_context_guide）
不写入 synthesis 的 user 消息（RAG参考片段）
② rag_enrichment（取数之后）
查询：{analysis_type} {query}
scene=analysis，top_k=8，排除 nl2sql 三个命名空间
用途：写入 context_snippets，在 synthesis 的 user 消息中拼入「RAG参考片段」
受 req.options.enable_rag 控制（默认 true）

| 策略 | 入口 | 说明 |
|------|------|------|

#### 1.1.3 最终生成报告 LLM 调用的提示词说明（v1 路径）

实现位置：`app/llm/graphs/analysis_graph_runner.py`（`_build_summary_messages`、`_generate_summary`、`_stream_summary_text`）。

**调用方式**：通过 `VLLMHttpClient.chat` / `stream_chat` 发送 **两条消息**（OpenAI 兼容 `messages`），不再把 system 模板与事实数据拼成单条 `user` prompt。

| 消息 role | 内容来源 | 说明 |
|-----------|----------|------|
| **system** | `_resolve_stage_template(stage="analysis_synthesis")` | 优先 `analysis_synthesis_<analysis_type>`（如 `analysis_synthesis_overheat_guidance`），含角色、输出结构、硬约束 |
| **user** | `_build_summary_user_content(...)` | 本轮可变事实：类型、数据模式、用户问题、可选规划意图、gathered_data、业务 RAG |

**user 消息内各块：**

- **gathered_data**（`acquire_data` 产出）：`dict[item_id, rows]` 整包 `json.dumps` 后截断，默认 **`ANALYSIS_SYNTHESIS_GATHERED_JSON_MAX_CHARS=16000`**（与 per-query `max_rows_per_query` 是两层限制）
- **synthesis 输出**：`ANALYSIS_SYNTHESIS_MAX_TOKENS=8192`（默认；六章+附录四表时 3072 易 `finish_reason=length` 中途截断）
- **业务 RAG**（`rag_enrichment`）：每条为 chunk 全文；最多 **8** 条，以 `- ` 列表拼入 user
- **规划意图**（可选）：`nl2sql_llm_planner_enabled` 时附带 intent JSON，**[:2000] 字符**

报告结构以 **system 模板**为准；代码中已移除旧的「请输出：1) 核心结论；2) 关键依据；3) 可执行建议。」硬编码结尾。

```python
# _build_summary_messages：system + user
messages = [
    {"role": "system", "content": system_prompt},  # analysis_synthesis_overheat_guidance 等
    {"role": "user", "content": user_content},     # _build_summary_user_content(...)
]

# 非流式 synthesis
summary = await self._llm.chat(
    model=None, messages=messages,
    timeout=..., max_tokens=ANALYSIS_SYNTHESIS_MAX_TOKENS,  # 默认 8192
)

# 流式（run-with-nl2sql-stream / run-img-diag-stream）
async for chunk in self._llm.stream_chat(
    model=None, messages=messages,
    timeout=..., max_tokens=ANALYSIS_SYNTHESIS_MAX_TOKENS,
):
    yield chunk
```

```python
# _build_summary_user_content（user 消息正文，节选）
data_preview = json.dumps(data_blob, ensure_ascii=False, default=...)[:max_chars]  # max_chars 来自配置，默认 16000
rag_text = "\n".join(f"- {s}" for s in context_snippets[:8])
# planning_block：intent JSON，[:2000]
return (
    f"分析类型: {analysis_type}\n"

```


#### 1.1.4 acquire_data 中 NL2SQL SQL 问答对自动写入 RAG
> 这个是NL2SQL基础能力模块的能力

- 针对NL2SQL生成成功且校验通过的sql问答对，自动写入RAg知识库(namespace=nl2sql_qa_examples)
- 自动写入时逻辑：
    - 按 (namespace, ingest_source, analysis_type, plan_item_id, plan_template_version) 五元组只保留一条，若存在不再写入（也不是覆盖）；plan_template_version 与 acquire_data 使用的 analysis_plan_* 模板 version（v1/v2）一致
    - 仅综合分析且 **analysis_type + plan_item_id** 均非空时写入；直连 `POST /nl2sql/query` 无 plan_item_id 则不写
    - 运维：**`GET /rag/nl2sql-auto-qa`**（可按 `analysis_type` / `plan_item_id` / `plan_template_version` 筛选）、**`PATCH /rag/nl2sql-auto-qa`**（按 `doc_name` 修正问句/SQL，勿改五元组换槽位）
