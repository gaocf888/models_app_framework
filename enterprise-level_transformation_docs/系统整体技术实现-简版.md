

## 1. 综合分析

### 1.1 综合分析LangGraph图节点链路

```
normalize_request
  → plan_context_rag      （规划前 RAG，scene=nl2sql）
  → intent_llm
  → plan_llm              （生成/合并数据计划 tasks. intent_llm/plan_llm 目前通过环境变量默认关闭）
  → acquire_data            （按 dependency 分层，同层 asyncio.gather 并行 NL2SQL）
  → data_quality_gate     （质量评估，不改 gathered_data）
  → rag_enrichment        （结论前业务 RAG，scene=analysis）
  → synthesis               （拼 prompt → 单次 LLM 生成 summary）
  → finalize
```

#### 1.1.1 两次 RAG 分别干什么
① plan_context_rag（取数之前）
命名空间：nl2sql_schema / nl2sql_biz_knowledge / nl2sql_qa_examples
每库 top_k=3，合计最多约 9 条 snippet
用途：喂给 intent_llm / plan_llm，或写入 plan task 的 question 引导（_apply_plan_context_guide）
不写入 _build_summary_prompt 的 RAG参考片段
② rag_enrichment（取数之后）
查询：{analysis_type} {query}
scene=analysis，top_k=8，排除 nl2sql 三个命名空间
用途：写入 context_snippets，在 synthesis 里拼进 prompt
受 req.options.enable_rag 控制（默认 true）


#### 1.1.2 最终生成报告LLM调用得提示词说明
主要包括：系统预制提示词(analysis_synthesis_overheat_guidance)、acquire_data（gathered_data（q0/q1/…））、业务 RAG(rag_enrichment)

- **系统预制提示词**: 全文作为 prompt 开头
- **gathered_data**: 整个 dict json.dumps 后 只取前 4000 字符(严重截断)
- **业务 RAG**: 每条为 chunk 全文（入库 chunk_size 默认约 500 字）；最多 8 条，拼接无总长度上限


#### 1.1.3 acquire_data中NL2SQL sql问答对自动写入逻辑
> 这个是NL2SQL基础能力模块的能力

- 针对NL2SQL生成成功且校验通过的sql问答对，自动写入RAg知识库(namespace=nl2sql_qa_examples)
- 自动写入时逻辑：
    - 按 (namespace, ingest_source, analysis_type, plan_item_id) 四元组只保留一条，若存在不再写入（也不是覆盖）
    - 只有综合分析中analysis_type + q1…q4才写入 ，若直连 POST /nl2sql/query 未传 plan_item_id（或analysis_type为空）等情况时，不自动写入nl2sql_qa_examples 问答对
