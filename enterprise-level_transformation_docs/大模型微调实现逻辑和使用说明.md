## 2. 实现逻辑（怎么串起来的）

### 2.1 总链路

```
LabelStudio 标注（可选，独立 compose）
        │ 导出 JSON
        ▼
data_pipeline（转换 / 校验 / 合并）
        │ 统一 JSONL
        ▼
LLMTrainingService → LLMTrainer（PEFT LoRA + HF Trainer）
        │
        ├── modality=text  → Causal LM
        └── modality=vision → Qwen2.5-VL + Processor
        ▼
outputs/llm_train/<job_id>/
  adapter/  metrics.jsonl  train.log  config.snapshot.yaml
```

入口有三条，**共用同一套训练核心**：

1. **CLI**：`run_llm_training.py`  
2. **HTTP**：`POST /train/llm/start`（`LLMTrainingOrchestrator` 后台线程）  
3. **Web UI**：`tests/web/train-llm-console.html`（调上述 HTTP）

### 2.2 模块职责

| 模块 | 路径 | 做什么 |
|------|------|--------|
| 训练器 | `app/train/llm/trainer.py` → `LLMTrainer` | 真正 LoRA 训练、写 metrics、响应 STOP |
| 服务 | `app/train/llm/training_service.py` | 读 YAML、校验 mode=lora、落配置快照、挂日志文件 |
| 调度 | `app/train/llm/orchestrator.py` | 任务生命周期、进度、停止、读日志/metrics/产物 |
| 数据管道 | `app/train/llm/data_pipeline.py` | LS 转换、旧格式兼容、校验、合并 |
| Factory | `app/train/llm/factory_adapter.py` | 占位；未接线 |
| API | `app/api/train_llm_admin.py` | `/train` + `/llm/...` |
| 模型 | `app/models/train_llm.py` | 请求/响应 Schema |
| CLI | `run_llm_training.py` | 运维命令行入口 |

### 2.3 统一数据格式（训练侧只认这一种）

```json
{
  "id": "sample_001",
  "modality": "text|vision",
  "task_profile": "chat_sft|vl_ops|defect_vl",
  "images": [],
  "messages": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "meta": {"source": "labelstudio|legacy|manual", "structured": {}}
}
```

- **真正喂模型的是 `messages`**；`meta.structured` 便于校验与回溯。  
- `task_profile` 决定 LabelStudio 怎么转、默认 user 提示怎么渲染。  
- 样例：`configs/llm_train/samples/sample_chat_sft.jsonl`、`sample_legacy_ops.json`。

### 2.4 任务状态机

`pending → running → succeeded | failed | stopped`

- 进度：`metrics.jsonl` + 内存 `progress`（UI 轮询）。  
- 停止：写 `outputs/.../STOP`，Trainer 回调检测到后结束，状态为 `stopped`。  
- **注意**：任务元数据在**当前 API 进程内存**；多副本/重启后只能靠磁盘上的 metrics/adapter 判断历史结果。

## 4. 使用说明

### 4.1 环境准备

1. GPU 机（推荐）+ CUDA；CPU 仅适合极小试验。  
2. 准备基座模型本地目录，例如 `models/Qwen2.5-7B-Instruct` 或 `models/Qwen2.5-VL-7B-Instruct`。  
3. 安装训练依赖（上一节）。  
4. 应用服务若走 API/UI：正常启动 `models-app`，并配置 `SERVICE_API_KEY`（与其它受保护路由一致）。

### 4.2 标注（LabelStudio，可选）

```bash
cd labelstudio-deploy
docker compose up -d
# 浏览器 http://localhost:8080
```

1. 新建项目 → Labeling Interface 粘贴对应 XML：  
   - 图文作业/风险：`configs/llm_train/labelstudio/vl_ops.xml`  
   - 缺陷：`defect_vl.xml`  
   - 纯文本问答：`chat_sft.xml`（需数据列 `prompt`）  
2. 导入图片或文本任务并标注。  
3. 导出 JSON → 放到 `data/llm_train/raw/`（或任意可读路径）。

### 4.3 转换与校验

**Web**：打开 `train-llm-console.html` →「数据工具」→ 填导出路径 / profile → 转换 → 校验。

**API 示例**：

```bash
# 旧格式（参考项目 image_path + safety_analysis 字段）兼容
curl -X POST "$HOST/train/llm/data/convert" \
  -H "Authorization: Bearer $SERVICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "export_path": "configs/llm_train/samples/sample_legacy_ops.json",
    "task_profile": "vl_ops",
    "legacy": true,
    "out_path": "data/llm_train/converted/ops.jsonl"
  }'

# LabelStudio 导出
curl -X POST "$HOST/train/llm/data/convert" \
  -H "Authorization: Bearer $SERVICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "export_path": "data/llm_train/raw/project.json",
    "task_profile": "vl_ops",
    "image_root": "data/llm_train/images",
    "legacy": false,
    "out_path": "data/llm_train/converted/ops.jsonl"
  }'

curl -X POST "$HOST/train/llm/data/validate" \
  -H "Authorization: Bearer $SERVICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"dataset_path":"data/llm_train/converted/ops.jsonl","check_images":true,"write_report":true}'
```

### 4.4 启动训练

**推荐：先 CLI 冒烟（纯文本样例）**

```bash
# 仅校验
PYTHONPATH=. python run_llm_training.py \
  --config configs/llm_train/train_lora.yaml \
  --validate-only

# 真实训练前请改 yaml：base_model、dataset_path、output_dir、modality
PYTHONPATH=. python run_llm_training.py \
  --config configs/llm_train/train_lora.yaml \
  --base-model models/你的基座 \
  --dataset-path configs/llm_train/samples/sample_chat_sft.jsonl \
  --output-dir outputs/llm_train/demo_text \
  --modality text
```

**API**

```bash
curl -X POST "$HOST/train/llm/start" \
  -H "Authorization: Bearer $SERVICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "code",
    "base_model": "models/Qwen2.5-7B-Instruct",
    "dataset_path": "configs/llm_train/samples/sample_chat_sft.jsonl",
    "output_dir": "outputs/llm_train",
    "modality": "text",
    "task_profile": "chat_sft",
    "config_yaml": "configs/llm_train/train_lora.yaml",
    "num_epochs": 1,
    "batch_size": 1,
    "learning_rate": 1e-5
  }'
```

说明：

- `mode` 请用 **`code`**；`factory` 当前会失败并提示未接线。  
- 未传 `job_id` 时，实际输出目录为 `output_dir/<自动job_id>/`。  
- VLM：设 `modality=vision`（或 `auto` 且数据含 `images`），基座用 Qwen2.5-VL，并保证图片路径存在。

**Web**：控制台「训练配置」填参 → 启动 → 自动轮询状态 / loss / 日志。

### 4.5 监视与停止

| 操作 | API |
|------|-----|
| 状态 | `GET /train/llm/status?job_id=...` |
| 指标 | `GET /train/llm/jobs/{id}/metrics` |
| 日志 | `GET /train/llm/jobs/{id}/logs` |
| 停止 | `POST /train/llm/jobs/{id}/stop` |
| 产物列表 | `GET /train/llm/artifacts` |

### 4.6 产物怎么用

成功后目录大致为：

```
outputs/llm_train/<job_id>/
  adapter/                 # LoRA 权重（PEFT save）
  metrics.jsonl
  train.log
  config.snapshot.yaml
```

后续：按基座厂商方式加载 base + adapter，或合并权重后挂到 `vllm-deploy` / 模型注册表。**本模块不负责自动上线。**

## 6. 审查结论：已知限制与注意点

1. **Factory 通道未接线**：仅占位，生产请固定 `mode=code`。  
2. **任务表不持久化**：API 多实例/重启后 status 列表为空；以磁盘产物为准。  
3. **VLM 实现绑定 Qwen2.5-VL API**：其它多模态基座需改 `trainer._train_vision`。  
4. **显存与 batch**：默认 `batch_size=1` + 梯度累积；7B VLM 需按机器调参。  
5. **图片缺失**：校验可 `check_images=true` 出 warning；训练时缺失图会用黑图占位（应避免进入正式集）。  
6. **assistant-only loss（文本）**：尽量 mask user 段，属启发式，极端 chat template 下可能近似全序列。  
7. **在线镜像**：不要把 `requirements-大模型训练.txt` 强行打进所有在线节点；训练机/训练镜像单独装。  
8. **自动化测试**：`tests/test_llm_train_pipeline.py` 覆盖数据管道与配置，**不拉起真实 GPU 训练**。
