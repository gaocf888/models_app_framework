## 汇报开场（建议 1 页）

### 一句话定位

面向能源电力工业场景的 **企业级 AI 应用基座**：把大模型推理、知识检索（RAG）、自然语言问数（NL2SQL）、多轮会话与可观测能力沉淀为统一平台，并在其上交付智能客服、综合分析、看图诊断、检修报告解析、视频安监等开箱即用应用。

### 核心主张（四句话）

| 主张 | 含义 |
|------|------|
| **统一基座** | 推理、检索、问数、会话、观测收敛为一套服务，避免各项目重复建设 |
| **生产可控** | SQL 只读、知识域隔离、Prompt 版本治理、全链路 Trace，可审计可回退 |
| **场景可扩展** | 新业务优先通过 Prompt / 知识域 / 编排节点接入，少改底层 |
| **双轮驱动** | 非结构化知识（RAG）+ 结构化数据（NL2SQL），而非「只包一层大模型 Chat」 |

### 建议 PPT 结构（10～15 分钟）

1. 定位与价值主张（开场）  
2. **成果积累**：基座能力 + **企业级关键技术能力**（相对「套壳 LLM」的差异化深化）+ 对比  
3. **场景与效果**：客服 → 分析/看图 → 文档抽取 →（可选）视频安监  
4. 可演示与可复制部署  
5. 总结与下一步

## 1.2 技术基座成果（核心积累）

### （1）自研混合 RAG 知识检索与运维

| 维度 | 成果要点 |
|------|----------|
| **能力** | 企业规程、案例、Schema 说明等文档可检索；问答/分析时按场景召回，抑制幻觉 |
| **检索链路** | 多路召回（向量 + BM25/关键词 + 元数据）→ RRF 融合 → CrossEncoder 精排 |
| **企业级增强** | 按 `scene` / `namespace` 隔离知识域；异步摄入；索引迁移；检索调试与运营统计 |
| **进阶能力** | Agentic RAG（多步子问题）；可选 GraphRAG（Neo4j 图知识） |

#### 关键能力深化（摄入侧）

工业知识文档往往「长、杂、图文混排」，简单按固定字数硬切会导致 **跨段语义断裂、图表与正文脱节**。平台在摄入侧沉淀：

| 能力点 | 做法 | 解决什么问题 |
|--------|------|--------------|
| **模块化摄入管线** | 解析 → 清洗 → 切块 → 元数据 enrichment → 异步索引（分步计时/可重试） | 大文档可运营、可观测 |
| **复杂版式解析** | 多格式 + MinerU 扫描件；清洗去页眉页脚/重复段/编码噪声 | 规程类「脏文档」稳定入库 |
| **结构优先切分** | 标题/编号章节 → 语义句簇聚合 | 保持条款语义边界 |
| **滑动窗口 overlap** | 步进 `chunk_size - chunk_overlap`；短尾合并 | 缓解「答案落在切缝」漏召 |
| **三策略可配置** | `structure` / `semantic` / `window` | 按知识域选用切块哲学 |
| **Figure 图文关联** | MinIO + VLM 描述；正文↔附图双向关联；召回扩展 | 「问文字带出图」 |

> 检索侧另含：混合召回 + RRF + CrossEncoder、Agentic 多步、namespace 优先级、查询侧视觉增强等，见 **§1.5**。

### （2）NL2SQL 自然语言问数基座（多入口同源）

| 维度 | 成果要点 |
|------|----------|
| **能力** | 自然语言 → 安全只读 SQL → 台账/测点/缺陷等结构化数据查询与总结 |
| **认知增强** | Schema 反射 + **三命名空间 RAG**（表结构 / 业务知识 / QA 样例） |
| **安全闭环** | 只读校验、表白名单、列–表绑定；EXPLAIN 预检；**生成期+执行期双 refine** |
| **工业语义** | 时间窗/时间锚点程序解析；机组/受热面等范围占位符改写 |
| **自进化** | 校验通过后 **QA 五元组自动沉淀**；分析槽位可严格回放已校验 SQL |
| **复用价值** | 独立问数、客服查库、综合分析取数、看图问数臂 **共用同一套服务** |

**汇报话术**：形成与 RAG 并列的 **「结构化数据智能入口」**——安全边界统一、工业时间/范围语义可程序化、成功问数可回流强化。

### （3）统一大模型推理与 Prompt 治理

| 维度 | 成果要点 |
|------|----------|
| **能力** | 文本生成、多模态看图、全业务 SSE 流式输出 |
| **可用性** | OpenAI 兼容对接 vLLM；**双轨调用**（LangChain 优先 + HTTP 回退） |
| **治理** | `prompts.yaml` 集中注册；按 scene/version 与 **user_id 权重 A/B**；分析报告规格 JSON 可配 |
| **意义** | 新场景优先「加配置 / 调权重」而非「重写引擎」 |

---

### （4）LangGraph 企业编排与人机协同（HITL）

| 维度 | 成果要点 |
|------|----------|
| **能力** | 客服、综合分析、看图诊断、检修抽取、分析智能体等复杂流程状态图化 |
| **生产特性** | Checkpoint、流式中断（`stream_id`）、**Legacy 一键回退**、灰度开关 |
| **HITL** | 客服意图边界确认 → 补充问句后可二次消歧；NL2SQL 生成失败可重试/改知识库；看图 Scope + DB existence；分析智能体分槽失败可确认续跑 |
| **分析深化** | NL2SQL **依赖分层并行取数**、数据质量门、多槽位 synthesis、节点级 Trace |

**汇报话术**：复杂工业分析是 **可编排、可中断、可确认、可回退、可复盘** 的生产流程，而非单轮 Prompt。

### （5）多轮会话：热冷分层 + 指代消解 + 章节大纲摘要

| 维度 | 成果要点 |
|------|----------|
| **存储能力** | 跨请求、跨实例共享；长会话可归档回查 |
| **热冷分层** | Redis 热层 + EasySearch 冷层 |
| **复用** | 客服、通用推理等统一 `ConversationManager` |

工业对话难点不只是「能记住上文」，而是用户常说 **「它」「上次那个」「上面第 3 点再展开」**——需要结构化上下文理解。

#### 关键能力深化 A：上下文指代消解（P0～P3）

| 层级 | 能力 | 作用 |
|------|------|------|
| **P0 检索融合（默认开）** | 规则判型后，检索 query 与上轮摘要融合 | 「它的检修周期」能检索到正确实体 |
| **P1 对话锚块（可开）** | system 注入「对话锚」要点块（模板后、RAG 前） | 约束本轮绑定上文焦点 |
| **P2 会话槽位（可开）** | assistant 落库后抽取 bullets 跨轮持久化 | 为锚块提供稳定话题源 |
| **P3 灰区 Coref（可开）** | 小模型分类 + 短时缓存 | 覆盖规则灰区并控成本 |

类型编码集中于 `configs/chatbot_anaphora.yaml`，可灰度、可观测。

#### 关键能力深化 B：章节/条目级大纲摘要提取与保存

| 能力 | 说明 |
|------|------|
| **回答后异步建大纲** | 抽取「1. / 一、」等为 `{idx, title, gist}` |
| **双层存储** | Redis + EasySearch 大纲索引，与会话 TTL 对齐 |
| **结构化续问旁路** | 「上面第 3 点展开」精确回锚条目 |
| **与指代互补** | 指代偏实体/话题；大纲偏「第 N 点」结构化引用 |

> 客服侧另含：意图多后端分流、C-RAG 质量闭环、FAQ 软直通、本厂 namespace 锁定、相似案例二次检索、流式 citation 等，见 **§1.5**。

## 1.5 企业级关键技术能力（全量梳理）

> **命名说明**：本节原可口语化为「特色技巧」，汇报建议统一使用 **「企业级关键技术能力」** 或 **「差异化技术能力」**——强调相对通用 LLM 封装、已在生产链路落地的工程化能力，而非零散经验技巧。  
> **用途**：技术领导/同行评审可整节展开；对业务领导可只取下方「精选速览」1 页。

### 1.5.1 精选速览（建议 PPT 1 页 · 抓眼球 10 条）

| # | 关键技术能力 | 一句话价值 |
|---|--------------|------------|
| 1 | **上下文指代消解（P0～P3）** | 「它/上次那个」可检索、可绑定、可灰度观测 |
| 2 | **章节大纲摘要续问** | 「上面第 N 点」结构化回锚，与指代互补 |
| 3 | **滑动窗口 + 结构/语义切块** | 长规程切块保连贯，降低切缝漏召 |
| 4 | **Figure 图文双向关联召回** | 问文字可带出附图依据 |
| 5 | **NL2SQL 三命名空间 RAG + 双 refine** | 表结构/业务口径/样例隔离增强；校验与执行失败均可修正且不绕过安全边界 |
| 6 | **C-RAG 质量闭环** | 检索质量门控 → query 重写 → 有限重试 → 超预算转澄清；低质召回不硬答 |
| 7 | **分析依赖分层并行取数 + 质量门** | 多维并行查库；数据不足降级而非编造 |
| 8 | **看图三臂并行 + Scope HITL** | 视觉+台账+规程合成；范围不确定可人确认 |
| 9 | **检修三阶段分块并行结构化抽取** | parse → classify → repair；长文档分块并行 LLM 解析为标准缺陷 JSON |
| 10 | **Prompt A/B + 配置化扩展** | 版本可控、场景可扩展，少改核心引擎 |

#### 精选能力简要说明

| # | 能力 | 简要说明 |
|---|------|----------|
| 1 | 指代消解 P0～P3 | 规则判型后融合检索 query，并可叠加对话锚块、会话槽位与灰区 Coref，让多轮弱指代仍能答到正确实体与话题。 |
| 2 | 章节大纲摘要续问 | 助手回答后异步抽取条目大纲并保存；用户按「第几点」追问时可精确回锚对应要点，与指代消解互补。 |
| 3 | 滑动窗口切块 | 知识摄入按结构/语义切分，超长段用 overlap 滑动窗口保留相邻上下文，缓解答案落在切缝导致的漏召。 |
| 4 | Figure 图文关联召回 | 正文与图块双向关联入库；正文命中后可扩展召回附图，支撑规程/案例类「问文字、见附图」。 |
| 5 | NL2SQL 双闭环 | 生成校验失败与 EXPLAIN/执行失败均可自动修正 SQL，且修正后仍须过完整安全校验，不能绕过只读边界。 |
| 6 | C-RAG 质量闭环 | 对检索质量做门控：不足则重写 query、有限次重试；仍不达标则转澄清，避免低质量上下文硬答。 |
| 7 | 分析并行 + 质量门 | 分析计划按依赖分层并行 NL2SQL 取数；数据不足时降级提示而非编造，保障报告可用性与可信度。 |
| 8 | 看图三臂 + HITL | 视觉判定、历史问数、业务知识三路并行后合成；机组/范围不确定时可人机确认，降低取错数风险。 |
| 9 | 检修分块并行抽取 | 长检修报告分块后走 parse→classify→repair 三阶段并行 LLM 抽取，输出可入库的标准缺陷结构化数据。 |
| 10 | Prompt 配置治理 | Prompt 与报告规格集中配置、可按场景/版本分流；新专题优先加配置扩展，少改核心引擎。 |

### 1.5.2 智能客服 / 多轮会话

| 关键技术能力 | 做什么 | 差异点（相对泛化封装） |
|--------------|--------|------------------------|
| **指代消解 P0～P3** | 规则判型 → 检索融合 → 对话锚块 → 会话槽位 → 可选 Coref | 结构化消解链，非整段历史硬拼 |
| **章节/条目大纲摘要** | 回答后抽 `{idx,title,gist}`；「第 N 点」回锚续问 | 条目级记忆，覆盖结构化追问 |
| **意图多后端分流** | rules / 轻量 LLM / BERT；`kb_qa`/`data_query`/`clarify` | 查库 vs 知识 vs 澄清可生产分流、可换后端 |
| **C-RAG 质量闭环** | 检索质量门控 → query 重写 → 有限重试 → 超预算转澄清 | 低质量召回不硬答 |
| **FAQ 软直通** | CrossEncoder 高分 FAQ 近直出，可跳过 history | 降延迟、抑多轮噪声，仍可观测 |
| **本厂知识域锁定** | 「本厂」等指代 → 主 RAG 限定 plant namespace | 防跨厂/跨系统串答 |
| **故障域相似案例二次检索** | 门控后主答追加专属 namespace 案例 | 故障场景知识与主库解耦 |
| **流式停止 + partial 落库** | `stream_id` 中断；断连可配置是否落部分答案 | 生产流控与会话一致性 |
| **客服 HITL（两轮意图 + 查库失败）** | 首轮：查数 / 知识库 / 补充问句；补充后仍模糊则 LLM（可兜底）给出 3 条候选问句（链接点选，按 `route_hint` 直路由）；NL2SQL 生成失败可重试或改 RAG | 混合问不硬切；关键分流可人确认、可续跑 |

| **热冷会话分层** | Redis 热层 + ES 冷归档 + 会话目录 | 长会话可运营、跨实例共享 |

## 2.2 场景详述与效果分享

### 场景一：智能客服 / AI 问答

**做什么**

- 统一承接两类需求：  
  - **知识问答**：规程、操作指南、历史案例（RAG）  
  - **结构化查库**：台账统计、设备状态等（NL2SQL）  
- 自动意图分流（知识 / 查库 / 澄清）；边界不清时可 **人机确认**，补充问句后仍模糊则给出 **3 条更具体的候选问法**（点选后直路由）；支持多轮指代（「它」「上次那个」）；流式回答；关联推荐问；可选相似案例与图片问答。
- NL2SQL 生成失败时可人机选择「重试查数 / 改走知识库」。

**典型问法（演示可用）**

- 「#3 机组过热器最近一次超温发生在什么时候？」→ 查库  
- 「锅炉四管泄漏的应急处置流程是什么？」→ 知识问答  
- 「今天有多少超温数据，什么原因？」→ 意图边界 HITL →（可选）补充问句 / 候选问法点选  
- 「它的检修周期是多久？」→ 指代消解后续聊  

**效果分享（文字）**

- 把分散在规程、案例库、台账里的信息收敛为 **7×24 自然语言入口**。  
- 运行/检修人员少翻册、少找人；统计类问题 **不必手写 SQL**。  
- 多轮澄清与推荐问降低「一次答不全」导致的反复沟通。  
- **人机协同**：混合意图不硬切路径；二次消歧把「又查数又问原因」拆成可点选的具体问法，降低答偏与无效 SQL。  
- **指代消解** 让用户可自然说「它 / 上次那个」，检索与回答仍能锚定正确设备/话题。  
- **章节大纲摘要** 支持「上面第 3 点展开」，像跟专工追问，而不是重新完整复述问题。  
- 本厂知识命名空间隔离，降低跨机组/跨系统答错风险。  

**后续可配素材**：客服对话流式截图 / 录屏；意图 HITL 与候选问法链接点选录屏；「它」指代续问对比；「第 N 点」续问录屏；意图分流示意；推荐问示例。

### 场景二：超温分析

**做什么**

- 针对锅炉受热面超温事件：自然语言或结构化需求 → 多任务 NL2SQL 并行取数 → 结合业务知识 → 生成多槽位结构化报告（概况、趋势、原因、处置、监护要点等）。

**效果分享（文字）**

- 显著缩短超温事件的 **信息收集与初判时间**，把「查曲线、查历史、写分析」收敛为一次请求。  
- 报告结构统一，便于交接与复核；数据不足时 **降级提示而非强行编造**，更适合生产使用。  
- 全链路 Trace 便于复盘「取到了什么数、哪一步影响结论」。  

**后续可配素材**：超温报告流式生成录屏；多槽报告结构截图；Trace 回放页。

**效果分享（文字）**

- 将人工录入从「逐页抄录」转为「上传后复核」，**录入效率与格式一致性显著提升**。  
- 彩色表格等工业特色版式有针对性处理，减少「抽得出但字段错」的返工。  
- 输出可直接对接缺陷台账入库，为后续统计与 AI 分析提供结构化基础。  

**后续可配素材**：原报告片段 vs 抽取 JSON 对照；异步任务进度页；颜色表校正前后对比。

---

### 场景十：独立 NL2SQL 问数

**做什么**

- BI、低代码、运维脚本直接调用问数 API，无需走完整客服/分析流程。

**效果分享（文字）**

- 为各类系统提供统一的 **「自然语言查数能力」**，避免每个系统各写一套 SQL 生成逻辑。  
- 安全边界一致（只读），降低开放问数的数据风险。  

---

### 场景十一：知识库运维

**做什么**

- 文档异步摄入、生命周期管理、命名空间迁移、检索调试与运营统计。  
- 支持复杂版式（含扫描件）、结构/语义/滑动窗口切块，以及可选图文 figure 入库与召回扩展。

**效果分享（文字）**

- 知识资产从「堆文件」变成 **可运营、可隔离、可调优** 的生产知识域。  
- 滑动窗口与结构切分降低「答案落在切缝」的漏召，长规程问答更连贯。  
- 图文关联使带图规程/案例不仅「能搜文字」，还能「带出附图依据」。  
- 支撑客服与分析「答得准、不串域」。  

---

### 场景十二：视频安监 / 行为识别 / 人脸（可选汇报页）

**做什么**

- 多路视频通道：安全帽/PPE、打电话、绊线、禁区滞留、人脸 1:N 等可配置算法策略。  
- 通道式架构：解码 → 队列 → 推理，适配工业现场多路并发。

**效果分享（文字）**

- 与大模型应用形成互补：LLM 侧重知识与分析决策，小模型侧重 **现场实时视觉告警闭环**。  
- 算法策略配置化，便于按厂区规则扩展告警类型。  

**后续可配素材**：告警截帧、通道拓扑、人脸比对示意。

## 2.4 场景效果共性总结（收束页）

1. **提效**：查规程、查台账、写初稿报告、录缺陷——从「人找系统」变为「自然语言驱动系统」。  
2. **提质**：结构化报告模板 + 知识引用 + 只读问数边界，减少幻觉与越权风险。  
3. **可控**：流式可见、HITL 可确认、Trace 可复盘、灰度可回退。  
4. **可复制**：同一基座换知识域/接业务库即可推广到同类型电厂或工业客户。
