# 智能客服整体实现技术说明

> 本文描述当前 `/chatbot/chat/stream`（主）与 deprecated `/chatbot/chat` 的真实实现：以 **LangGraph 编排**为主链路，保留可配置的 legacy 回退链路。  
> RAG 引擎与向量库细节见 `framework-guide/RAG整体实现技术说明.md`；LangGraph 方案总览见 `enterprise-level_transformation_docs/企业级智能客服 LangGraph 框架实现方案.md`。

---

## 1. 当前主链路（LangGraph）

### 1.1 API 与协议

- 路由文件：`app/api/chatbot.py`。  
- 接口：
  - `POST /chatbot/upload`（多模态图片上传 MinIO，返回预签名 URL 填入 `image_urls`）；
  - `POST /chatbot/chat/stream`（SSE 流式，**建议主用**）；
  - `POST /chatbot/chat/resume-stream`（人机协同续跑 SSE；见 **§12**，需 `CHATBOT_HITL_ENABLED=true`）；
  - `POST /chatbot/chat/stop`（显式中断指定 `stream_id`，`terminate_reason=user_cancelled`）；
  - `POST /chatbot/chat`（非流式，**deprecated**，`include_in_schema=false`）；
  - `GET /chatbot/sessions*`（会话列表/消息导出，assistant 可含 `rag_citations`）。
- 请求模型：`ChatRequest`，核心字段为 `user_id`、`session_id`、`query`、`image_urls`、`enable_rag`、`enable_context`；可选 **`enable_nl2sql_route`**（与 `CHATBOT_NL2SQL_ROUTE_ENABLED` 共同控制 `data_query` 路由）；可选 **`enable_fault_vision`** 控制本轮是否用图片参与「故障域/相似案例」判定（见 `CHATBOT_SIMILAR_CASE_*` / `CHATBOT_FAULT_*`）。  
- **图片预处理（入口前）**：`ChatbotService` 在进入图/legacy 链路前会对 `image_urls` 做预处理（下载、最长边缩放、超阈值有损压缩、存储）；默认 **`CHATBOT_IMAGE_STORAGE_BACKEND=minio`**（预签名 URL），可选 `local` 落盘 + `StaticFiles`（前缀默认 **`/chatbot/media`**）。  
- **提示词版本**：`prompt_version` 可选，对应 `configs/prompts.yaml` 中 `chatbot` 的 `version`；不传时使用 **`CHATBOT_PROMPT_DEFAULT_VERSION`（默认 `boiler_v1`，锅炉领域分层模板）**。  
- **结构化路由**：`enable_nl2sql_route`（默认 `true`）与 **`CHATBOT_NL2SQL_ROUTE_ENABLED`** 共同决定是否将问句判为 `data_query` 并走 NL2SQL；关闭后相关问句也走向量 RAG。  
- 流式响应：
  - 启动事件：`{"started":true,"stream_id":"..."}`（首帧返回，供后续 `/chatbot/chat/stop` 调用）；
  - 增量事件：`{"delta":"...","finished":false}`；
  - 引用事件（RAG 路径，可选）：`{"citation_ref":n,"finished":false}`（`n` 与 `meta.rag_citations[].ref_index` 对齐，见 **§11**）；
  - 人机协同中断（可选）：`{"chatbot_hitl_required":true,"finished":false,...}`（见 **§12**；结束后仍有 `finished` 帧，`meta` 可含 `pending_hitl` / `hitl_kind` / `resume_token`）；
  - 完成事件：`{"finished":true,"meta":{...}}`（`meta` 含 **`stream_id`**、**`suggested_questions`**（**`data_query` 流式恒为空**）、**`used_nl2sql`**、**`nl2sql_sql`** / **`nl2sql_failed`** / **`nl2sql_error_code`**（查库路径）、**`intent_label`**、**`rag_citations`**（RAG 路径）、**`faq_soft_direct`** / **`faq_soft_direct_reason`**（若触发，见 **§10**）、**`rag_namespace` / `rag_scope_reason` / `rag_scope_fallback`**（本厂 RAG 范围，若有）、**`processed_image_urls`**、**`original_image_urls`**、HITL 相关字段（若开启）等）；
  - 异常事件：`{"error":"...","finished":true}`。
- **上下文结构化索引增强（新增，旁路）**：可开启回答后异步抽取“第1点/第2点…”索引并写入 Redis 热层（可选同步 EasySearch 冷层），下一轮在不改主链路的前提下对“上文第N点”做引用定位增强。
- **会话引用与 RAG 并存**：不因“指代上文”而默认关闭检索；通过 `configs/prompts.yaml` 中 `chatbot` 模板 + 构图时对「知识片段」段的导语，引导模型**用语义/小节主题对齐上轮助手表述**（不限于「第N点」），并区分检索片段列举顺序与会话内容，由模型在同一上下文内分配注意力。

### 1.2 Service 与图运行器

- 主入口：`app/services/chatbot_service.py` 的 `stream_chat_events()`。  
- 图运行器：`app/llm/graphs/chatbot_graph_runner.py`，状态定义在 `app/llm/graphs/chatbot_graph_state.py`。  
- 典型流程：
  1. 进入图编排：模板加载 → 历史加载 → **意图分类（`kb_qa` / `clarify` / `data_query`）** → **`fault_case_gate`（故障域/相似案例门控，可关）**；
  2. **可选 HITL（意图确认）**：若开启人机协同且命中边界意图，中断并下发 `chatbot_hitl_required`，待 `POST /chat/resume-stream` 续跑（见 **§12**）；否则进入意图条件路由；
  3. **`data_query`**：`nl2sql_answer` 节点调用 `NL2SQLService`（**不写中间轮会话**，`record_conversation=False`），再经大模型将 SQL 与结果整理为自然语言；**SQL 生成失败**时可再次进入 HITL（重试查数 / 改知识库）；**流式路径不下发** `suggested_questions`；
  4. **`kb_qa`**：`select_rag_engine` → **`rag_scope_resolve`（本厂指代 → 锁定电厂专属 namespace）** → **`kb_retrieve`**（指代消解 P0/P2/P3 + 带 namespace 召回，写入 `rag_citations`）→ C-RAG 循环 → **`kb_build_messages`**（可选 **对话锚块 P1**，默认关；**FAQ 软直通**见 **§10**）→ Runner 层流式生成（可选 **`citation_ref`** 事件，见 **§11**）；
  5. **Runner 层**：对澄清 / NL2SQL / 仅固定话术分支直接输出 `answer_text`；否则 `VLLMHttpClient.stream_chat` 流式下发；
  6. 若门控命中且配置开启：主回答（或澄清正文）之后 **`HybridRAGService.retrieve(..., namespace=CHATBOT_SIMILAR_CASE_NAMESPACE)`** 追加「相似案例」块（**`data_query` 路径不追加**）；
  7. 流式结束前：**关联问题推荐**（`kb_qa` / `clarify`；**不含 `data_query` 流式**，见 **§7.4**），写入 `meta.suggested_questions`；
  8. 落库 assistant 时可携带 **`rag_citations`**（与 `finished.meta` 同形）；HITL 确认话术与用户按钮选择也会写入会话；
  9. 断连或显式 stop 时 partial 落库行为取决于 `CHATBOT_PERSIST_PARTIAL_ON_DISCONNECT`。

## 2. 图编排与路由

当前图中已实现节点包含：

- 输入预处理：`load_prompt_template`、`load_history`、`intent_classify`、`fault_case_gate`（相似案例扩展，默认 `CHATBOT_SIMILAR_CASE_ENABLED=false`）；
- **结构化问数**：`nl2sql_answer`（意图 `data_query`）；
- 知识检索：`select_rag_engine`、**`rag_scope_resolve`**、`kb_retrieve`、`kb_quality_check`、`kb_rewrite_query`、`kb_build_messages`；
- 分支占位：`unsafe_guard`、`handoff_human`、`smalltalk_generate`；
- 澄清与收敛：`clarify_build_response`、`finalize`。

**意图与路由（查库 vs 文档）**：

- 统一入口 `app/llm/graphs/chatbot_intent.py`：`CHATBOT_INTENT_BACKEND=rules|llm|bert`（默认 **rules**）。
- **rules**：`chatbot_intent_rules.classify_chatbot_intent_by_rules` — 台账/统计/列表/检修记录等 → `data_query`；原因/机理/标准/预防等 → `kb_qa`；带图固定 `kb_qa`。
- **bert**：`chatbot_intent_bert` — 须微调序列分类模型（暂不推荐）。
- **llm**：`chatbot_intent_llm` — **模式 B**（rules 主判 + 进程内轻量 HF 模型窄触发，CPU）；见 `docs/智能客服意图识别轻量LLM接入说明.md`（生产路径须 **`classify_chatbot_intent_async`**）。
- 意图标签受 **`CHATBOT_INTENT_OUTPUT_LABELS`** 约束；未放量的标签会降级为 `kb_qa`。
- **人机协同（HITL）**：总开关 **`CHATBOT_HITL_ENABLED`**（默认关）；开启后意图边界与 NL2SQL 生成失败可中断确认，策略与接口见 **§12**。开启 HITL 时 Runner 走**顺序执行**（可中断），与编译图语义对齐。
- 低检索质量时走 C-RAG 重写重试，超过预算后转 `clarify`；  
- **本厂专属知识库（RAG 范围）**：`rag_scope_resolve` 根据**本轮**厂别指代（如本厂/本公司/本电厂等）将主检索 **限定为** `CHATBOT_PLANT_KB_NAMESPACE`（默认 `Power_plant_knowledge`）；**多轮延续**须 `CHATBOT_PLANT_KB_HISTORY_CONTINUATION=true`（**默认 `false`**）；结果写入 state 的 `rag_namespace`，**C-RAG 重试**（`kb_rewrite_query → kb_retrieve`）**复用同一 namespace**，不再经过 `rag_scope_resolve`；  
- **`kb_build_messages`**：除模板/RAG/锚块外，可触发 **FAQ 软直通**（§10），满足条件时不注入 `history_messages`；
- 所有分支统一收敛到 `finalize`，保证状态口径与 SSE `meta` 一致。

## 3. 回退与稳定性策略

- `CHATBOT_GRAPH_ENABLED=false` 时，走 legacy 顺序链路（非图编排），并与主链路对齐 **意图分流 / NL2SQL / 关联问题（`data_query` 流式不下发）/ 默认提示词版本**。  
- 图执行异常且 `CHATBOT_FALLBACK_LEGACY_ON_ERROR=true` 时，自动回退 legacy 链路。  
- 端到端图超时由 `MAX_GRAPH_LATENCY_MS` 保护，超时会进入可观测的终止状态。  
- 客户端断连时可按 `CHATBOT_PERSIST_PARTIAL_ON_DISCONNECT` 控制是否落库 partial assistant（`terminate_reason=client_disconnect`）。
- 显式 stop：调用 `/chatbot/chat/stop` 后，Runner/legacy 在下一次流式循环检查点停止输出，`finished.meta.terminate_reason=user_cancelled`。

## 4. 配置项（重点）

除通用 LLM/RAG/Redis 配置外，建议显式配置以下参数：

- 图开关与意图：`CHATBOT_GRAPH_ENABLED`、`CHATBOT_INTENT_ENABLED`、**`CHATBOT_INTENT_BACKEND`（rules|llm|bert）**、**`CHATBOT_INTENT_OUTPUT_LABELS`（默认含 `data_query`）**；轻量 LLM 见 **`CHATBOT_INTENT_LLM_*`** 与 `docs/智能客服意图识别轻量LLM接入说明.md`；BERT 见 **`CHATBOT_INTENT_BERT_*`** 与 `docs/智能客服意图识别BERT接入说明.md`；
- **提示词默认版本**：**`CHATBOT_PROMPT_DEFAULT_VERSION=boiler_v1`**（与 `configs/prompts.yaml` 中 `chatbot` 条目一致）；
- **主答 temperature（可选）**：**`CHATBOT_MAIN_LLM_TEMPERATURE`**；
- **NL2SQL 路由**：**`CHATBOT_NL2SQL_ROUTE_ENABLED`**；
- **人机协同 HITL**（见 **§12**）：**`CHATBOT_HITL_ENABLED`**（总开关，默认 `false`）、**`CHATBOT_INTENT_HITL_ENABLED`** / **`CHATBOT_INTENT_HITL_MIN_CONFIDENCE`**、**`CHATBOT_NL2SQL_HITL_ENABLED`** / **`CHATBOT_NL2SQL_HITL_MAX_RETRIES`**、**`CHATBOT_HITL_RESUME_TTL_SEC`**、**`CHATBOT_HITL_SESSION_BACKEND`**（`memory|redis`）、**`CHATBOT_HITL_SESSION_REDIS_URL`**、**`CHATBOT_HITL_SESSION_NAMESPACE`**；
- **关联问题**：**`CHATBOT_SUGGESTED_QUESTIONS_ENABLED`**、**`CHATBOT_SUGGESTED_QUESTIONS_MAX`**（**流式 `data_query` 不下发**，见 §7.4）；
- **FAQ 软直通**：**`CHATBOT_FAQ_SOFT_DIRECT_ENABLED`**（默认开）、**`CHATBOT_FAQ_SOFT_DIRECT_MIN_SCORE`**（默认 `0.95`）、**`CHATBOT_FAQ_SOFT_DIRECT_SNIPPET_TOP_N`**（见 **§10**）；
- C-RAG：`CHATBOT_CRAG_ENABLED`、`CHATBOT_CRAG_MAX_ATTEMPTS`、`CHATBOT_CRAG_MIN_SCORE`、`MAX_REWRITE_QUERY_LENGTH`、`MAX_GRAPH_LATENCY_MS`；
- 引擎路由：`CHATBOT_RAG_ENGINE_MODE`、`CHATBOT_RAG_ENGINE_FALLBACK`；
- **本厂专属知识库 RAG 范围**：`CHATBOT_PLANT_KB_ENABLED`、`CHATBOT_PLANT_KB_NAMESPACE`、`CHATBOT_PLANT_KB_QUERY_BOOST_NAME`、`CHATBOT_PLANT_KB_FALLBACK_ON_EMPTY`、`CHATBOT_PLANT_KB_HISTORY_CONTINUATION`（多轮延续，**默认 `false`**）；
- 会话窗口：`CHATBOT_HISTORY_LIMIT`（单轮读取窗口）+ `CONV_MAX_HISTORY_MESSAGES`（总保留上限）；
- 结构化索引增强：`CHATBOT_OUTLINE_ENABLED`、`CHATBOT_OUTLINE_ASYNC_ENABLED`、`CHATBOT_REFERENCE_RESOLVE_ENABLED`、`CHATBOT_OUTLINE_ES_ENABLED`、`CHATBOT_OUTLINE_ES_INDEX`；
- 回退与断连：`CHATBOT_FALLBACK_LEGACY_ON_ERROR`、`CHATBOT_PERSIST_PARTIAL_ON_DISCONNECT`；
- Checkpoint：`CHATBOT_CHECKPOINT_BACKEND`（`none|memory|redis`，**无 Postgres**）、`CHATBOT_CHECKPOINT_REDIS_URL`、`CHATBOT_CHECKPOINT_NAMESPACE`。
- 相似案例（可选）：`CHATBOT_SIMILAR_CASE_ENABLED`、`CHATBOT_SIMILAR_CASE_NAMESPACE`、`CHATBOT_SIMILAR_CASE_TOP_K`、`CHATBOT_FAULT_DETECT_ENABLED`、`CHATBOT_FAULT_VISION_ENABLED`、`CHATBOT_FAULT_DETECT_MODE`、`CHATBOT_FAULT_MIN_CONFIDENCE`（说明见 `enterprise-level_transformation_docs/企业级智能客服 LangGraph 框架实现方案.md` 第 14 节）。

## 7. 关联问题推荐（完整处理逻辑）

实现文件：`app/llm/graphs/chatbot_follow_up.py` 中 `build_suggested_questions`；由 `ChatbotLangGraphRunner._fill_suggested_questions`（及 legacy 路径中同等调用）在**主答（含相似案例追加块）拼完之后**执行，结果写入 SSE / 非流式响应的 **`meta.suggested_questions`** 或 **`ChatResponse.suggested_questions`**。总开关与条数上限：**`CHATBOT_SUGGESTED_QUESTIONS_ENABLED`**、**`CHATBOT_SUGGESTED_QUESTIONS_MAX`**。

### 7.1 处理顺序（流水线）

1. **规则预设（代码内写死的关键词表）**  
   - 数据结构：模块内 `_TOPIC_FOLLOW_UPS`（如「爆管、过热、腐蚀、泄漏、检修、台账、标准」等主题 → 若干固定中文问句）。  
   - 逻辑：若**用户当前 `query` 子串命中**某主题键，则按表追加候选，条数上限由 `intent_label` 决定（`clarify` 时较少，其它意图略多）。  
   - 性质：**完全写死**，便于冷启动与可控话术；扩展方式仅为改代码或后续改为读配置/YAML。

2. **基于本轮已召回片段的「种子」问句（非二次向量检索）**  
   - 入参：本轮主链路注入模型前使用的 **`context_snippets`**（与 `kb_retrieve` 结果一致）。  
   - 逻辑：取前若干条片段的**首行文本**，套固定模板生成「结合知识库：…还可以了解什么？」类引导句。  
   - **重要**：此处**不会**再调用 `HybridRAGService.retrieve` 或单独做一轮 embedding；只是**复用本轮已有检索结果**。若本轮未走 RAG 或无命中（如 `data_query`、关 RAG、澄清分支），则该步通常无输出或很少。

3. **去重**  
   - 按出现顺序合并 1、2 的候选，**去重**（保序）。

4. **LLM 补全（可选）**  
   - 触发条件：`intent_label` 为 **`kb_qa` 或 `data_query`**，且去重后条数 **仍小于** `max_total`（函数 `build_suggested_questions` 内逻辑）。  
   - **注意**：Graph 与 **legacy 流式** 在调用前即跳过 `data_query`（`_fill_suggested_questions` / `_stream_chat_legacy_events`），**不会**进入本步；仅 **deprecated 非流式 `/chat`** 仍可能对 `data_query` 调用 LLM 补全。  
   - 输入：用户原问 + 助手回答摘要（约前 1200 字）；**不把完整 RAG 片段列表作为长上下文传入**。  
   - 输出：要求模型仅返回 JSON：`{"questions":["...","..."]}`，解析失败后丢弃该步。  
   - `clarify`：以规则为主，LLM 调用倾向更少（见代码中 `rule_n` / `need_llm` 分支）。

5. **截断**  
   - 最终列表截断为 **`max_total`**（且不超过代码内硬上限 10）。

### 7.2 与流式接口的关系

- 关联问题只在**回答生成结束**后计算，出现在**最后一条** `finished` 的 `meta` 中；**不会**随 `delta` 分片提前下发。

### 7.3 小结

| 来源 | 是否写死 | 是否单独再走 RAG |
|------|----------|------------------|
| 主题词 → 预设问句 | 是（`_TOPIC_FOLLOW_UPS`） | 否 |
| 片段首行种子 | 句式固定，**内容来自本轮 `context_snippets`** | **否**（复用本轮检索） |
| LLM `questions` | 否 | 否（当前实现未为关联问题单独检索） |

### 7.4 按意图路径的差异

| 意图 | 流式 `/chat/stream`（Graph + legacy） | deprecated `/chat` |
|------|----------------------------------------|---------------------|
| `kb_qa` | 规则 + 片段种子 + 可选 LLM → `meta.suggested_questions` | 同左 |
| `clarify` | 规则为主，条数偏少（最多 3） | 同左 |
| `data_query` | **`meta.suggested_questions=[]`**，不调用推荐问 LLM | 仍可能生成（与流式不一致，迁移时以流式为准） |

## 9. 上下文指代消解（简要）

**槽位 / 对话锚 / 清单（与实现对齐）**

1. **槽位**：上一轮 **assistant 落库之后**，规则从该条全文抽要点写入会话维槽位（Redis 优先；无 Redis 为进程内）；**同步写入**，非单独异步摘要任务（勿与 Outline「第 N 点」异步索引混淆）。
2. **对话锚**：本轮组 **system** 时在模板与 RAG 之间按需插入的 **「仅供推理」** 固定格式子块；要点列表 **优先用槽位 bullets**，否则从 **历史中最近一条 assistant** 再抽；**锚块 ≠ 槽位**，不把槽位 JSON 整包进模型。
3. **指代清单**：yaml + 规则得 `anaphora_type`，驱动 P0 检索融合与 P1 是否出锚；灰区可 P3 Coref；**「消解」此处偏工程绑定**；**「上文第 N 点」** 另走 Outline（`CHATBOT_OUTLINE_*`）。

**其余**：与「上文第 N 点」结构化索引互补；**P0 默认开，P1/P2/P3 默认关**；以图路径为主。**配置与流程图**：`enterprise-level_transformation_docs/企业级智能客服 LangGraph 框架实现方案.md` **§15**；专项 `docs/智能客服上下文理指代实现优化方案-20260514.md`；清单 `configs/chatbot_anaphora.yaml`。

## 10. 高分 FAQ 软直通（生成阶段）

**目标**：检索首条 citation 与用户问题高度匹配（如「1000 问」FAQ 库）且本轮无指代续问时，在 **`kb_build_messages`** 阶段**不注入** `history_messages`，避免旧 assistant 回答把模型带偏；**检索阶段**（指代、`rag_scope_resolve`）不受影响。

**实现**：`app/llm/graphs/chatbot_faq_soft_direct.py` → `evaluate_faq_soft_direct`；图内 `_node_kb_build_messages`；Legacy `_build_llm_messages` 对齐。

**触发条件**（须全部满足）：

- `CHATBOT_FAQ_SOFT_DIRECT_ENABLED=true`（默认开）；
- `enable_rag` 且 `intent_label=kb_qa`；
- `anaphora_type` / `anaphora_rule_type` 均为 `none`，问句不以显式指代词开头；
- 首条 `rag_citations[].rerank_score >= CHATBOT_FAQ_SOFT_DIRECT_MIN_SCORE`（默认 `0.95`，CrossEncoder 重排分）；
- 存在非空 `context_snippets` 与首条 citation `text_preview`。

**行为**：

- 跳过 `history_messages` 与对话锚块（P1）；
- 注入 LLM 的片段数裁为 `CHATBOT_FAQ_SOFT_DIRECT_SNIPPET_TOP_N`（默认 `1`）；
- `rag_citations` 展示条数不变；
- `finished.meta` 含 `faq_soft_direct`、`faq_soft_direct_reason`。

详细设计见 `enterprise-level_transformation_docs/企业级智能客服 LangGraph 框架实现方案.md` **§4.4**。

## 11. RAG 结构化引用与 citation 流

**目标**：`kb_qa` 路径将召回片段转为编号引用，供前端展示来源并与流式正文对齐。

**机制**：

1. **`kb_retrieve`** 经 `chunks_to_rag_context`（`chatbot_rag_citations.py`）生成编号 LLM 片段 + **`rag_citations`** 列表（`ref_index`、`text_preview`、`original_content_url` 等）。
2. **流式主答**：若存在引用，`CitationStreamParser`（`chatbot_citation_stream.py`）将正文中的 `[n]` 映射为 SSE **`{"citation_ref": n, "finished": false}`**；对应 `delta` 不再含该字面量。
3. **结束帧**：`meta.rag_citations` 与 `GET /chatbot/sessions/messages` 中 assistant 的 `rag_citations` **同形**；落库 assistant 时一并写入。
4. **`data_query`**：`rag_citations` 为空，无 `citation_ref`。
5. NL2SQL 库表/QA namespace 片段在展示层过滤（`filter_rag_citation_dicts`）。

**前端对接要点**（详见 `app/api/chatbot.py` `chat_stream` 文档注释）：

- 收到 `citation_ref` 即用 `ref_index === n` 在 `finished.meta.rag_citations` 中查找来源；
- 历史消息解析 `answer` 中的 `[n]` 或与 `rag_citations` 对齐。

详细设计见 `enterprise-level_transformation_docs/企业级智能客服 LangGraph 框架实现方案.md` **§4.5**。

## 12. 人机协同（HITL）：意图路由确认与 NL2SQL 生成失败

> 目标：在 **意图边界不清** 与 **结构化查数 SQL 生成失败** 时，暂停自动路由，由用户点选处理方式后续跑，避免误走查库或静默失败。  
> 企业级方案总览见 `enterprise-level_transformation_docs/企业级智能客服 LangGraph 框架实现方案.md` **§17**。  
> OpenAPI / 前端对接细则见 `app/api/chatbot.py` 中 `chat_resume_stream` 文档字符串。

### 12.1 开关与存储

| 配置 | 含义 | 默认 |
|------|------|------|
| `CHATBOT_HITL_ENABLED` | **总开关**；关则两路 HITL 均不触发 | `false` |
| `CHATBOT_INTENT_HITL_ENABLED` | 意图路由确认 | `true`（仍受总开关约束） |
| `CHATBOT_INTENT_HITL_MIN_CONFIDENCE` | 低于该置信度倾向于触发意图 HITL | `0.75` |
| `CHATBOT_NL2SQL_HITL_ENABLED` | NL2SQL 生成失败 HITL | `true`（仍受总开关约束） |
| `CHATBOT_NL2SQL_HITL_MAX_RETRIES` | 允许的「重试查数」次数上限（按 `nl2sql_retry_count`） | `1` |
| `CHATBOT_HITL_RESUME_TTL_SEC` | `resume_token` 有效期（秒） | `1800` |
| `CHATBOT_HITL_SESSION_BACKEND` | `memory` / `redis` | `memory` |
| `CHATBOT_HITL_SESSION_REDIS_URL` | Redis 地址（backend=redis） | 可回落到 checkpoint Redis |
| `CHATBOT_HITL_SESSION_NAMESPACE` | token key 前缀 | `chatbot_graph` |

实现要点：

- 策略：`app/llm/graphs/chatbot_hitl.py`；话术与按钮：`chatbot_hitl_display.py`；token 快照：`chatbot_hitl_session_store.py`。
- 开启 HITL 后，Runner 使用 **`_run_graph_sequential`**（可中途 `pending_hitl` 返回），而非仅依赖编译图一气跑完。
- `resume_token` **单次有效**：续跑成功即删除；过期或会话不匹配返回 SSE `error`。

### 12.2 场景 A：意图路由确认（`hitl_kind=intent_route_confirm`）

**触发时机**：`intent_classify` + `fault_case_gate` **之后**、按意图路由 **之前**（`should_trigger_intent_hitl`）。

**窄触发（不全量弹窗）**，下列情况倾向触发（示意，细节见代码）：

- 置信度 **&lt;** `CHATBOT_INTENT_HITL_MIN_CONFIDENCE`；
- `intent_reason` 含 `mixed_` / `ambiguous_`；
- 标签为 `data_query` 但问句含概念类词，或标签为 `kb_qa` 但问句含数据类词；
- 问句同时命中「数据类」与「概念类」提示词。

**不触发**（典型）：

- 总开关关、`confirmed_route` 已存在、标签已为 `clarify`、本轮带图、续跑标记 `after_intent_confirm`；
- 高置信结构化/概念启发式（如 `structured_query_heuristic` 且 conf≥0.78 等）。

**用户按钮（`ui_buttons`）**：

| action id | 展示文案 | 续跑行为 |
|-----------|----------|----------|
| `route_data_query` | 查实时/台账数据 | `confirmed_route=data_query` → NL2SQL |
| `route_kb_qa` | 基于知识库分析 | `confirmed_route=kb_qa` → RAG |
| `route_clarify` | 我先补充问题 | **必填** `payload.refined_query`；更新 `query` 后**重新意图分类**；若仍满足意图 HITL 触发条件，进入 **场景 A2 消歧**（不再重复本表三按钮） |

### 12.2.1 场景 A2：意图消歧建议（`hitl_kind=intent_disambiguation_suggest`）

**触发时机**：首轮意图 HITL 中用户选择 `route_clarify` 并提交 `refined_query` 后，重新意图分类仍满足 `should_trigger_intent_hitl`，且开启 `CHATBOT_INTENT_DISAMBIGUATION_ENABLED`。

**行为**：调用 LLM（失败则规则兜底）生成简短 `analysis` + **3** 个候选问句（至少 1 条 `data_query`、1 条 `kb_qa`）。`prompt` 为对话引导（**不含**问题编号列表）；`ui_buttons[].label` 为完整 `query`，前端在本 `hitl_kind` 下应渲染为**链接**（其它 HITL 仍为按钮）。`context.disambiguation_source` 标明来源（`llm` / `fallback_rules` / `llm_partial_fallback`）。消歧超时默认 `CHATBOT_INTENT_DISAMBIGUATION_TIMEOUT_SEC=15`。

**点选后**：用选项的 `query` + `route_hint` 写入 `confirmed_route`，**不再跑意图分类 / 不再二次意图 HITL**，直接进入 NL2SQL 或 RAG。意图 HITL 轮次上限见 `CHATBOT_INTENT_HITL_MAX_ROUNDS`（默认 2）。

### 12.3 场景 B：NL2SQL SQL 生成失败（`hitl_kind=nl2sql_gen_failed`）

**触发时机**：`nl2sql_answer` 中检测到 **SQL 生成失败**（`gen_failed`），且 `nl2sql_retry_count < CHATBOT_NL2SQL_HITL_MAX_RETRIES`。

**说明**：执行失败 / 空结果等若非「生成失败」路径，不走本 HITL，仍按既有失败文案与 `nl2sql_failed` meta 处理。

**用户按钮**：

| action id | 展示文案 | 续跑行为 |
|-----------|----------|----------|
| `nl2sql_retry` | 重试查数 | `nl2sql_retry_count++`；`nl2sql_skip_cache=true`；将上轮失败原因注入 `nl2sql_retry_hint` 后再生成 SQL；仍失败且未达重试上限可再次 HITL |
| `fallback_kb_qa` | 基于知识库分析 | 放弃查数，按原问句（或 `refined_query`）走 RAG 链路 |

达到重试上限后：返回固定提示文案，`terminate_reason` 与 `nl2sql_failed` 按生成失败口径结束，不再弹窗。

### 12.5 SSE 与会话

**中断事件**（`/chat/stream` 或续跑中再次触发）：

- `chatbot_hitl_required=true`，`finished=false`；
- 字段：`hitl_id`、`resume_token`、`hitl_kind`、`prompt`、`ui_buttons`、`context`（意图置信度、原问、失败原因等）。

**前端最小对接**：

1. 监听 `chatbot_hitl_required`，保存 `resume_token` / `ui_buttons` / `prompt`；
2. 渲染按钮；`prompt` 一般已作为 `delta` 写入会话；
3. `POST /chatbot/chat/resume-stream`，Body 携带 `user_id`、`session_id`、`resume_token`、`action`；`route_clarify` 时 **必填** `payload.refined_query`（测试页复用上方问句框 `#query`），其它 action 可选 `refined_query` 覆盖问句；
4. 续跑 SSE 与 `/chat/stream` 相同（`started` / `delta` / `citation_ref` / 可能再次 HITL / `finished`）。

**会话落库**：

- 中断时：assistant 写入 HITL 话术（`format_hitl_assistant_message`）；
- 续跑时：user 写入 `[用户选择] …`（`format_hitl_user_choice_message`），再继续正常助手回答。

### 12.6 与 Legacy / 其它 HITL 的边界

- **Legacy 流式路径**：不以本 HITL 中断语义对齐；HITL 以 Graph + 顺序执行主路径为准。
- **看图诊断 scope HITL**、**综合分析章节 HITL** 为其它产品链路，接口与 token 模型不同，勿混用。
