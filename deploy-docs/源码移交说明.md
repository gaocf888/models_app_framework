# 源码移交说明（结项）

> **读者**：接方开发，需要改接口、Prompt、业务配置或排查链路。  
> **部署与验收命令**：见 [整体部署运维手册.md](./整体部署运维手册.md)。本文不重复逐步 `docker compose`。

---

## 1. 交付包与构建约束

### 1.1 交什么

| 路径 | 职责 |
|------|------|
| `app/` | FastAPI 业务；部署编排在 `app/app-deploy/` |
| `configs/` | Prompt 与业务 YAML（改文案优先改这里） |
| `vllm-deploy/` | 大模型推理服务 |
| `rag_db-deploy/` | EasySearch |
| `mineru-deploy/` | 扫描 PDF 解析（检修） |
| `requirements-大模型应用.txt` | 应用镜像 pip 依赖（**必须在仓库根**，Dockerfile 从此 COPY） |
| `requirements-人脸识别-CPU.txt` | 同上；主镜像会安装，结项可不启用 `/face` |
| `deploy-docs/` | 运维与本移交说明 |

应用镜像 **构建上下文是仓库根目录**。只拷 `app/` 而不拷两个 `requirements-*.txt` 和 `configs/`，`docker-nvidia` / `docker-mx` 构建会失败。

### 1.2 不交什么

不交付、也不要按现网去部署：`paddleocr-layout-deploy/`、`monitoring-deploy/`、`face_db-deploy/`、`graphrag_db-deploy/`、`benchmarks/`、`docs/`、`framework-guide/`、`enterprise-level_transformation_docs/`、`memory-bank/`、`tests/` 等。

`app/` 内部仍含未上线模块（见第 5 节）。**整目录可交，但默认不要启动、不要当现网承诺。**

### 1.3 Git 之外

模型权重、ES 数据、MinIO/Redis 盘、业务 MySQL 账号不在源码包内，由运维手册与现网交接清单单独列出。

## 2. 运行时目录怎么对应

```
调用方 HTTP
    → models-app (app/main.py)
        → vLLM          vllm-deploy        LLM_DEFAULT_ENDPOINT
        → EasySearch    rag_db-deploy      RAG_ES_*
        → Redis         compose 内         REDIS_URL
        → MinIO         compose 内         CHATBOT_IMAGE_MINIO_* 等
        → MySQL         宿主机/专库        DB_*
        → mineru-api    mineru-deploy      MINERU_*（检修扫描件）
    → configs/          容器内 /workspace/configs
```

| 要改的事 | 先动哪里 |
|----------|----------|
| 换大模型名 / 卡数 / 量化 | `vllm-deploy/config/models.yaml` + `vllm-deploy/.env` 的 `MODEL_PRESET`，并改应用 `LLM_DEFAULT_MODEL` |
| EasySearch 密码 / 宿主机端口 | `rag_db-deploy/.env`；应用 `RAG_ES_PASSWORD` 同步；**容器内 HOSTS 仍是 :9200** |
| 客服/分析/看图/检修的提示词 | `configs/prompts.yaml`（及业务子目录 YAML） |
| 端口、卷、GPU 可见设备 | `app/app-deploy/.env` 末尾 Compose 段；nvidia 栈再 `cp` 到 `docker-nvidia/.env` |
| 业务开关、超时、表白名单 | `app/app-deploy/.env` → `app/core/config.py` 读取 |

配置分层（Compose 插值 vs 容器内 `os.getenv`）见运维手册第 6 节。

## 3. 结项五条业务线：代码地图

入口统一：`app/main.py`（`create_app` 挂载路由）。业务路由均走 `Authorization: Bearer`（`app/auth/dependencies.py`）。

### 3.1 智能客服（AI 问答）

| 项 | 位置 |
|----|------|
| HTTP | `POST /chatbot/chat/stream`（主用）；`/chat` 已弃用 |
| 路由 | `app/api/chatbot.py` |
| 服务 | `app/services/chatbot_service.py` |
| 编排 | `app/llm/graphs/chatbot_graph_runner.py` |
| 会话 | `app/conversation/`（Redis 热层 + 可选 ES 冷层） |
| RAG | `app/rag/rag_service.py`、`hybrid_rag_service.py` |
| Prompt | `configs/prompts.yaml` 中 chatbot 相关 scene；`configs/chatbot_business/boiler/`（默认 `CHATBOT_PROMPT_DEFAULT_VERSION=boiler_v1`） |
| 关键环境变量 | `CHATBOT_*`、`RAG_*`、`REDIS_URL` |

意图默认 `CHATBOT_INTENT_BACKEND=rules`。`llm` / `bert` 需额外模型挂载，结项未强制。  
客服内嵌查数走 NL2SQL（`CHATBOT_NL2SQL_ROUTE_ENABLED`），与超温共用 `app/nl2sql/` 和业务库。

**改回答风格 / 厂级话术：** 优先改 `configs/chatbot_business/` 与 `configs/prompts.yaml`，不要先改 Graph 节点。

### 3.2 检修报告结构化解析

| 项 | 位置 |
|----|------|
| HTTP | `POST /inspection-extract/upload`、`/run`、`/run/async`、`GET /jobs/{job_id}` |
| 路由 | `app/api/inspection_extract.py` |
| 服务 | `app/services/inspection_extract_service.py` |
| 解析/分类/LLM | `app/inspection_extract/`、`app/services/inspection_extract_llm_orchestrator.py` |
| Prompt | `configs/prompts.yaml` 中 `inspection_extract*` |
| 扫描 PDF | `MINERU_*` → `mineru-deploy` |
| 上传存储 | MinIO（与客服/看图分对象前缀） |

结项路径是 **现网 `/inspection-extract`**，不是 `/inspection-extract-v0`。后者依赖未交付的 Paddle 侧车，代码虽在 `app/api/inspection_extract_v0.py`，**不要接现网。**

**改抽取字段/提示：** `configs/prompts.yaml` 的 inspection_extract 段 + `.env` 里 `INSPECT_EXTRACT_*`。

### 3.3 超温分析（综合分析）

| 项 | 位置 |
|----|------|
| HTTP | `POST /analysis/run-with-nl2sql-stream`（现网流式）；同步为 `/run-with-nl2sql` |
| 路由 | `app/api/analysis.py` |
| 服务 | `app/services/analysis_service.py` |
| 编排 | `app/llm/graphs/analysis_graph_runner.py` |
| 报告合成 | `app/llm/graphs/analysis_synthesis_v2.py`（`ANALYSIS_SYNTHESIS_STRATEGY_OVERHEAT_GUIDANCE=v2`） |
| 取数 | `app/nl2sql/`（计划 RAG → 生成 SQL → 白名单库表） |
| Prompt | `configs/prompts.yaml`：`analysis_*_overheat_guidance` 等 |
| 类型字面量 | 请求体 **`analysis_type=overheat_guidance`** |

payload 模式 `/run-with-payload` 不查库，结项前台若走「自然语言 + 库表」应使用 NL2SQL 流式口。  
`/analysis-agent/*` 为另一套智能体流水线，**不作为本结项五条主路径**。

**改超温章节结构 / 槽位文案：** `analysis_synthesis_v2.py` 对应槽位 + `configs/prompts.yaml` 中 overheat 模板；超窗则调 `.env` 的 `ANALYSIS_SYNTHESIS_V2_SEGMENT_MAX_TOKENS`。

### 3.4 缺陷识别（看图诊断）

| 项 | 位置 |
|----|------|
| HTTP | `POST /analysis/img-diag/upload` → `POST /analysis/run-img-diag-stream` |
| HITL 续跑 | `POST /analysis/run-img-diag-resume-stream` |
| 路由 | `app/api/analysis.py` |
| 编排 | `app/llm/graphs/analysis_img_diag_runner.py`（继承综合分析 runner，并行视觉 ‖ NL2SQL） |
| 范围确认 | `app/llm/graphs/img_diag_scope_graph.py` |
| 视觉 Prompt | `configs/prompts.yaml`：`analysis_img_diag_vision_defect_ident` |
| 子类型 | **`img_diag_subtype=defect_ident`**（图片必填） |

视觉为非流式 `chat()`，首包前页面可能长时间无 SSE。超时：`ANALYSIS_IMG_DIAG_VISION_TIMEOUT_SECONDS`。  
确认范围时若图片未换，仍可能再次调用视觉（`_finalize_state_after_hitl_resume` 在 `vision_first` 确认路径会刷新），运维上表现为「确认后又等数分钟」。

### 3.5 泄爆分析（看图诊断）

与 3.4 **同一套接口和 runner**，仅分流字段不同：

| 项 | 值 |
|----|----|
| `img_diag_subtype` | `leakage_burst` |
| 图片 | 可选 |
| 取数窗口 | 事故锚点向前约 3 天 |
| 视觉 Prompt | `analysis_img_diag_vision_leakage_burst` |
| 结果 `analysis_type` / `data_mode` | `img_diag_leakage_burst` |

不要与综合分析里历史类型 `leakage_burst_analysis`（`run-with-nl2sql` 的 analysis_type）混用；结项泄爆走 **看图诊断** 接口。

## 4. 横切能力（五条线都会碰到）

| 能力 | 代码 | 说明 |
|------|------|------|
| 配置中心 | `app/core/config.py` | 环境变量唯一读取处（应用进程） |
| LLM 客户端 | `app/llm/client.py` | OpenAI 兼容 `/v1/chat/completions` |

| RAG 摄入/管理 | `app/api/rag_admin.py`、`app/rag/` | 知识更新走 `/rag/*`，不要直接改 ES 文档结构除非懂 mapping |

| 鉴权 | `app/auth/` | 密钥用 `app/auth/keygen.py` 生成，写入 `.env` |
| 分析 trace | `app/services/analysis_trace_store.py` | `GET /analysis/traces/{request_id}` |

## 5. 存在于 `app/` 但结项范围内不要当现网

| 模块 | 标志 | 说明 |
|------|------|------|
| 检修 V0 | `/inspection-extract-v0`、`INSPECT_EXTRACT_V0_*` | 依赖未交付的 Paddle 侧车 |
| 小模型 GPU | `--profile small-model-gpu`、`/small-model/*` | YOLO/视频通道 |
| 人脸 | `/face/*` | 主镜像含 CPU 依赖，非五条主业务 |
| GraphRAG | `/graph/*`、`GRAPH_RAG_ENABLED` | 需 Neo4j，未交 `graphrag_db-deploy` |
| 训练 | `app/train/`、`/dajia/*`、`/train/*` | 离线工程 |
| 分析智能体 | `/analysis-agent/*` | 非超温主路径 |
| 地降所等其它业务 configs | `configs/chatbot_business/subsidence/`、`configs/nl2sql_business/subsidence/` | 非本结项锅炉主线；勿改混 |

修改这些模块不纳入结项验收。

## 6. 二次开发最小约定

1. **新 HTTP**：加在 `app/api/`，在 `app/main.py` 挂载；受保护路由走现有 Bearer。  
2. **改模型话术**：先 `configs/prompts.yaml` / `configs/chatbot_business/` / `configs/nl2sql_business/boiler_four_tube/`，再考虑 Python。  
3. **改库表范围**：同步三处——MySQL 实际表、`.env` 表白名单（`ANALYSIS_NL2SQL_TABLE_SCOPE_DEFAULT` 等）、RAG `nl2sql_schema`。  
4. **密钥与 `.env` 不进 Git**；`docker-nvidia` / `docker-mx` 使用各自目录下的 `.env` 副本。  
5. **离线模型**只走 compose 挂载路径（`EMBEDDING_MODEL_PATH`、`RAG_RERANKER_MODEL_PATH`），不要写死开发机盘符。  
6. **验证**：用运维手册第 7 节对应业务线的 curl；看图/超温以 SSE 尾帧和日志为准，不要只看页面「连接中」。
