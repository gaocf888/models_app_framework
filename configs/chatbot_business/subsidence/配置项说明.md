# 智能客服业务配置包说明（subsidence）

> 路径：`configs/chatbot_business/subsidence/`  
> 启用：`CHATBOT_DOMAIN=subsidence`（与 `NL2SQL_BUSINESS_DOMAIN` **独立**）  
> 加载入口：`app/llm/graphs/chatbot_business_profile.py`

## 本目录管什么

本包只影响**智能客服**（`/chatbot`）：问句先判意图（查数 / 知识问答 / 混合 / 澄清），再决定走 NL2SQL 还是 RAG。  
**不**包含库表白名单与 SQL 语义（那些在 `configs/nl2sql_business/subsidence/`）。

## 意图识别怎么配（先读这段）

环境变量 **`CHATBOT_INTENT_BACKEND`** 决定算法（与本包配合）：

| 取值 | 行为 | 本包哪些文件生效 |
|------|------|------------------|
| `rules`（默认） | 仅用关键词/正则启发式分类 | `intent_markers.yaml` 为主 |
| `funnel` | **三层漏斗**（见下），口语换说法更稳 | markers + **`intent_prototypes.yaml`** + 主对话模型 |

**`funnel` 三层含义（文档内简称 L1 / L2 / L3）：**

1. **L1 规则层**：与 `rules` 相同，读 `intent_markers.yaml`；高置信明确查数/概念问可直接定意图。  
2. **L2 向量层**：把用户问句与 `intent_prototypes.yaml` 里各意图下的**示例问句**做成向量，用余弦相似度匹配（嵌入模型复用现有 `EMBEDDING_*`，不另配模型）。规则拿不准（如两侧词表都未命中）时才主要靠这一层。  
3. **L3 大模型层**：L2 仍胶着或低分时，用**现有 vLLM 主对话模型**做极短 JSON 四分类兜底（不用独立 0.5B 意图模型）。

因此表中写「L2 原型问句」= **漏斗第二层用来做相似度匹配的示例问句清单**，不是 SQL/Prompt 模板。

## 目录一览

| 文件 | 用途 | 运行时 |
|------|------|--------|
| `profile.yaml` | 展示名、本市锁库、相似案例开关 | **必读** |
| `intent_markers.yaml` | 查数/概念关键词、强查数正则、硬闸、续问词；兼作 funnel L1，并含 L3 分类示例文案 | **必读** |
| `intent_prototypes.yaml` | funnel **L2**：按意图整理的口语示例问句，供向量相似度匹配 | 仅 `CHATBOT_INTENT_BACKEND=funnel` 时需要 |
| `clarify_texts.yaml` | 澄清 / 混合回答 / 无据等固定话术 | **必读** |
| `follow_up.yaml` | 答后「相关推荐问」种子与生成用 system | 推荐问功能开启时使用 |

## profile.yaml（摘要）

- **locale_kb**：问句命中「本市/本地区」等时，RAG 锁到指定 namespace；地降默认 `enabled: false`（**不含「本厂」**）。  
- **similar_case**：答后是否追「相似案例」块；默认关，`gate_markers` 勿填锅炉爆管词。

## intent_markers.yaml（摘要）

- **data_markers / strong_data_regex**：查询动词、统计指标（如查询、列出、年沉降）；**不要**把行政区名、分层标站名塞进词表（易误伤概念问）。  
- **conceptual_markers**：成因、规范、机理等 → 知识问答意图。  
- **unclear_patterns / history_continuation_markers**：过短句走澄清；续问承接。  
- **intent_llm_examples**：仅在 `funnel` 走到 **L3** 时注入短提示的分类示例（字段名历史遗留，不是单独再挂一个意图 LLM 配置）。

## intent_prototypes.yaml（摘要）

- 按意图 label（如 `data_query` / `kb_qa` / `hybrid_qa` / `clarify`）列出多条**用户可能怎么问**的例句。  
- 只在 `CHATBOT_INTENT_BACKEND=funnel` 时参与 **L2** 匹配；`rules` 模式可忽略本文件。  
- 改文件后进程内向量缓存会按 mtime 自动刷新。

## 维护提示

1. 「哪些区近期沉降偏大」这类**无查询动词**的口语：`rules` 易判成知识问答；开 `funnel` 后优先在 `intent_prototypes.yaml` 的 `data_query` 下补同类例句。  
2. 词表扩容无法穷尽换说法时，不要无限堆 `data_markers`，用原型问句 + funnel 更合适。  
3. 改用户可见固定句只动 `clarify_texts.yaml` / `follow_up.yaml`。
