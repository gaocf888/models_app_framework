# 地降 NL2SQL 业务配置包说明（subsidence）

> 路径：`configs/nl2sql_business/subsidence/`  
> 启用：`NL2SQL_BUSINESS_DOMAIN=subsidence`（与 `CHATBOT_DOMAIN=subsidence` 独立，部署时需同时设置）  
> 加载入口：`app/nl2sql/nl2sql_business_profile.py`

## 目录一览

| 文件/目录 | 用途 | 运行时 |
|-----------|------|--------|
| `profile.yaml` | 域入口：DB 默认、NL2SQL 开关、表白名单路径、RAG 命名空间 | **必读** |
| `table_scope.txt` | 沉降表白名单（8 表） | **必读** |
| `table_scope_om_result.txt` | 运维表白名单（8×`t_om_*`） | **必读** |
| `join_whitelist.txt` | 人工补充 JOIN：`事实表.project_name=t_station.name` | **必读** |
| `scope_lexicon.json` | 行政区 / 监测类型 / 站点别名（规则解析） | **必读** |
| `entity_rules.json` | 生成后语义校验（沉降勿查水位表等） | **必读** |
| `semantic/` | 语义资产（指标、同义词、层位字典等） | **必读**（`semantic_link_enabled=true`） |
| `rag/` | RAG 摄入源 Markdown（schema / 业务知识 / QA 种子） | 运维 **re-ingest** 时使用 |

## profile.yaml 关键字段（摘要）

- **db.\***：业务库连接默认；密码禁止写入；显式 `DB_*` / `DB_URL` 优先。
- **schemas.\***：PostgreSQL schema 路由（见下节）。
- **nl2sql.semantic_dict_path**：语义目录。
- **nl2sql.fcb_layer_map_file**：分层标层位字典；`semantic_layer` 加载后注入层位 0 `preferred_station_names`。
- **nl2sql.device_station_map_file**：监测方式站点覆盖；按 `device_type` 注入 `project_names` allowlist（与 `t_station.name` 匹配；区县仍用 `t_station.area`）。
- **nl2sql.scope_lexicon_file / entity_rules_file**：范围词表与实体规则。
- **nl2sql.prompt_default_version**：默认 `v2_subsidence`。
- **tables.\***：沉降 `allowlist_file` + 运维 `om_result_allowlist_file` + JOIN 白名单；意图收窄分域取用。
- **rag.biz_source_files**：业务知识摄入清单（含层位 0 索引）。

## PostgreSQL schema 路由

| 数据域 | 配置键 / 环境变量 | 默认 | 取数 |
|--------|-------------------|------|------|
| 准实时沉降 | `settlement_realtime` / `SUBSIDENCE_SCHEMA_REALTIME` | **public**（文档 `default`） | 与校核 **互斥** |
| 人工校核沉降 | `settlement_calibrated` / `SUBSIDENCE_SCHEMA_CALIBRATED` | 空（未就绪） | 与准实时 **互斥** |
| 当前沉降源 | `settlement_data_source` / `SUBSIDENCE_DATA_SOURCE` | `realtime` | — |
| 运维中间库 | `om_result` / `OM_RESULT_SCHEMA` | `om_result` | **始终**该 schema |

实现：`app/nl2sql/schema_routing.py` + `om_intent.py`。

- 执行：`search_path`→沉降 schema；裸 `t_om_*` 执行前改写为 `om_result.t_om_*`。
- 反射：沉降 schema +（若 om 白名单非空）`om_result`。
- 白名单：`table_scope.txt`（沉降）与 `table_scope_om_result.txt`（运维）分列；问句意图收窄（运维词→仅 om）。
- 校验：schema×表组合；运维 SQL 须含 `snapshot_time` 最新批过滤。
- 报告：`om_ops_rates_by_type.sql` / `om_ops_offline_list.sql` / `om_alert_*.sql`（含分类型告警台数）；运行/预警章已接最新批次，非占位；compose 强制 `sql_template`，禁止 NL2SQL 生成器当运维附表。
- 校验/改写：运维 SQL 须最新 `snapshot_time`（`max` 取自**当前主表**，勿为取批次硬引用 `t_om_data_alarm_summary`）；`t_om_offline_device_list` 须 `status=0`（缺则注入）。
- 查询台：无 om library；运维问句 `ops_use_chatbot`。
- RAG：改 schema/biz/qa md 后需 **re-ingest**。

## 配置权威（解析 vs 语义）

| 用途 | 权威源 | 说明 |
|------|--------|------|
| 区 / 站 **首轮解析** | `scope_lexicon.json` | 规则最长匹配；智能问答与数据查询共用 |
| 站点语义维度 | `semantic/dimensions/station.yaml` | **占位**（`entries` 可空）；补全前勿当作解析词表 |
| 库 id ↔ 洗数表 | `semantic/dimensions/device_type.yaml` + `synonyms.yaml` | 查询台 catalog 强制对齐；问答沉降锁库复用同一 catalog |
| 区后置绑定 / filters | `semantic/dimensions/district.yaml` | 语义对齐后写入 `suggested_filters` |
| 时间窗 | `time_intent_display`（代码规则） | 不读 semantic/dimensions |

智能问答查数（沉降）：运维问句不锁沉降表；沉降路径可 `forced_tables` + 规则 scope；站点+区间时间优先 `period_sql`，失败回退 LLM。不照搬查询台 HITL。

## 维护提示

1. 改口径 / 层位 / QA / Prompt 后：同步相关文件并 **RAG re-ingest**。  
2. 站点增删：优先更新 `scope_lexicon.json`（可从 `t_station` 导出）；监测方式覆盖名单同步 `device_station_map.yaml`。  
3. 层位变更：更新 `fcb_layer_map.yaml`，并视需要同步 `nl2sql_biz_knowledge_fcb_layer0_stations.md`。  
4. 监测方式站点分布变更：更新 `device_station_map.yaml`（来源 `站点列表-除了gnss.xls`）；fcb 码集宜与层位字典交叉校验。  
5. 重点监测区变更：更新 `dimensions/key_monitoring_areas.yaml`（与季报表 4-1 / 自动报告板块对齐）。  
6. 详细方案见 `docs/基于地降所项目改造/`（P7 见 `NL2SQL基座改造.md` §7.5）。
