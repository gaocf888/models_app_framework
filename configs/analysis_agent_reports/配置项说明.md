# 综合分析报告规格说明（analysis_agent_reports）

> 路径：`configs/analysis_agent_reports/`  
> 加载：`app/analysis_agent/report_spec.py` → `load_report_spec()`  
> 详细命名约定亦见同目录 `README.md`

## 目录一览

| 文件 | 用途 | 运行时 |
|------|------|--------|
| `*.analysis_agent.json` | 报告规格兜底：章节 + 可选内嵌 `plan`；地降为 schema 3 + compose | **必读**（按 analysis_type） |
| `{type}.{plan_template_version}.json` | 带逻辑版本号的优先规格（可选） | 有则优先于兜底 |
| `section_library/` | 地降可复用板块（cover/平原/分区循环/压缩层/附表等） | schema 3 展开 |
| `sql/` | 确定性 SQL 模板（窗初窗末、典型曲线时序）；绑定参数，无生成器 | `executor=sql_template` |
| `README.md` | 命名与结构说明 | 文档 |

## 当前报告类型（文件名 → analysis_type）

| 文件 | 业务 |
|------|------|
| `overheat_guidance.analysis_agent.json` | 锅炉超温指导 |
| `leakage_burst_analysis.analysis_agent.json` | 泄漏爆管分析 |
| `maintenance_strategy.analysis_agent.json` | 检修策略 |
| `four_tube_health_interpretation.analysis_agent.json` | 四管健康解读 |
| `subsidence_daily/weekly/monthly/quarterly/yearly.analysis_agent.json` | 地降日/周/月/季/年报 |

## 加载顺序

```text
{analysis_type}.{ANALYSIS_AGENT_PLAN_TEMPLATE_VERSION}.json
→ {analysis_type}.analysis_agent.json
```

默认版本 env：`ANALYSIS_AGENT_PLAN_TEMPLATE_VERSION`（如 `analysis_agent_v1`）。

## JSON 结构（摘要）

- **schema_version 2（锅炉）**：直接 `chapters[]` + 可选 `plan.items[]`。  
- **schema_version 3（地降）**：`compose[]` 引用板块库，运行时展开为 chapters/plan/tables/charts。  
- 确定性取数：`executor=sql_template|python|placeholder`；附表真源禁止 NL2SQL 生成器。

### 前端契约（地降自动报告）

只传 `analysis_type` + 可选 `options.start_time/end_time/area/issue_no` 即可；`query` 可空。  
未传日期 → 上一完整周期。非法 `area` → 422。首帧 `started.period` 含时间窗。

## 维护提示

1. 改章节结构、outline、constraints：**地降改板块库/compose**；锅炉仍只改本目录 JSON。勿再写回 `prompts.yaml` 的 report 块。  
2. 改口径只改 `sql/*.sql`、`deterministics/formulas.py` / `fcb_compress.py` 与层位/覆盖字典。  
3. 地降/锅炉报告与当前 `NL2SQL_BUSINESS_DOMAIN` 对齐，避免跨域表白名单。
