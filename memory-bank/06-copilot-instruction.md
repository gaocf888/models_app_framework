第一阶段：图像预处理与增强
	在机器“阅读”之前，必须先让文档变得清晰可读。这一步完全依赖传统的计算机视觉技术，不涉及大模型。

	纠偏与矫正： 如果扫描件是歪的，算法会检测边缘并旋转拉直。
	超分辨率： 如果图片模糊，使用生成对抗网络进行图像放大和锐化，确保小字也能看清。
第二阶段：版面分析与 OCR
	这是最关键的基础步骤。系统不仅要认出字，还要知道字在哪里、是什么类型的元素。
	OCR：
		现代 OCR 不仅仅是把图转成字，它还能输出每个字的坐标信息。
	版面分析：
		系统会利用目标检测模型（如 YOLO 系列或专门训练的 LayoutLM 等）对页面进行切割。
		它会识别出：“这块区域是标题”，“那块区域是表格”，“这里是页眉”，“那里是印章”。
		目的： 避免把跨栏的文字读串了，或者把表格里的数据当成普通段落处理。
第三阶段：结构化重组
	这时候我们手里有一堆零散的文字块和坐标，需要把它们拼成人类能读懂的逻辑顺序。
	阅读顺序排序： 根据坐标（从上到下，从左到右），结合版面分析的结果，将文字块重新拼接成完整的句子和段落。
	表格还原： 这是一个难点。专门的表格识别算法会根据网格线或单元格位置，重建表格的 HTML 或 Markdown 结构，保留行和列的关系。
第四阶段：核心提取策略 (这里才用到模型)
	到了这一步，我们有了清洗后的文本和结构。针对不同的需求，后台会有不同的处理逻辑，并不总是直接调用超大参数量的 LLM。
	针对非固定版式/复杂文档 (如当前结构和格式不固定的检修报告)
		逻辑： 这时才会引入你提到的 LLM。
		做法：
			切片： 如果文档很长，超过 LLM 上下文窗口，系统会根据语义或章节进行切分。

			调用： 发送给 LLM 进行推理（多个切块实现并行处理）。
第五阶段：后处理与验证
	大模型可能会产生幻觉或格式错误，后台必须有严格的校验机制。
	正则校验： 比如提取“日期”，必须符合 YYYY-MM-DD 格式；提取“金额”，必须是数字。如果不符合，系统会自动重试或报错。
	逻辑互斥检查： 比如“结束时间”不能早于“开始时间”。
	置信度评分： 如果 OCR 识别某个字置信度很低，或者 LLM 输出的概率较低，系统会将该条目标记为“需人工复核”。
