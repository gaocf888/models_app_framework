## 2. 最新模板结构解析（严格条目）

最新模板仅含以下 **4 个一级章节**（无「报告基础信息」「整改验证」「附件」等独立章）：

### 2.1 超温情况概览

**全局规则（模板原文，影响取数窗与呈现）：**

1. Query 为 **某一天**（今天/昨天/前天等）→ **按日超温分析**，仅取该日数据。
2. Query 为 **周/月范围**（本周/上周/本月/上月等）→ **按周超温分析**，含区域周概览 + 测点周详情。
3. **指定机组** → 单机组表格；**未指定机组** → 查全部机组，**按机组排序、分表展示**。
4. 异常等级：**Ⅰ轻微 / Ⅱ中度 / Ⅲ严重 / Ⅳ临界爆管**（表格行级或区域汇总级均需体现）。

#### 2.1.1 按日超温分析（表格）

每个机组一块：

```
机组信息：#_N_机组
开始时间：____    结束时间：____

| 区域名称 | 测点名称 | 最大超温值 | 最小超温值 | 最大连续超温时长 | 超温日期 | 异常等级 |
| 水冷壁 限xxx℃ | 测点1 | 569℃ | 499℃ | 301分 | 2026.05.02 10:00:01 | Ⅰ级（轻微超温） |
```

**字段语义（结合模板样例与库表）：**

| 模板列 | 含义 | 主要来源 |
|--------|------|----------|
| 区域名称 | 受热面 + 限温展示「水冷壁 限540℃」 | `account_static_device.device_name` + `base_temp_device.over_hot_limit` 或 `monitor_hotarea_temp.limit_temp` |
| 测点名称 | 测点中文名/编号 | `base_temp_point.point_name` / `pi_code` |
| 最大超温值 | 模板样例为 **壁温绝对值（℃）** | `MAX(highest_temp)` |
| 最小超温值 | 超温时段内 **最低壁温（℃）** | `MIN(highest_temp)` |
| 最大连续超温时长 | **分钟** | `MAX(limit_duration)/60` |
| 超温日期 | 代表时刻（样例取起始时刻） | `MIN(start_time)` 或峰值时刻 |
| 异常等级 | 按 **监测超温差值** 定级 | `MAX(highest_temp - limit_temp)` → Ⅰ～Ⅳ |

#### 2.1.2 按周超温分析（双表）

**表 A — 周超温概览（按区域）**

| 区域名称 | 超温点数 | 周最大超温值 | 周最小超温值 | 周最大连续超温时长 | 周趋势 | 异常等级 |
|----------|----------|--------------|--------------|--------------------|--------|----------|

- **周趋势**：按日分解，如 `10日 0个 | 11日 0个 | 12日 1个 | …`（每格为当日该区域超温测点数或超温次数，需产品确认；下文 SQL 按 **测点数** 实现）。
- **异常等级**：区域内 **Ⅰ/Ⅱ/Ⅲ/Ⅳ 各档数量**，如 `Ⅰ级0个 Ⅱ级1个 Ⅲ级1个 Ⅳ级0个`。

**表 B — 周超温详情（按测点）**

列与 **按日表** 相同（测点级明细，时间窗为整周）。

### 2.2 超温原因剖析（LLM + RAG + 结构化数据）

- 对 **每台锅炉、每条超温数据** 做归因；需结合：**负荷、主汽压力、主汽温度、炉膛负压、氧量** 等工况。
- 必须给出 **集中式 / 分散式 / 混合型** 分布特征（与现 v2 第 2 章第 5 条逻辑一致，数据源改为 q1 测点明细）。
- **周分析** 时须分析 **日超温趋势**，推导核心诱因。
- 结构：**共性原因**（烟气侧/介质侧/运行操作/设备本体）+ **分区域专属原因**（按受热面逐区）。
- 多机组时按 `#1锅炉`、`#2锅炉` 分段。

### 2.3 超温风险评估（LLM + RAG）

- **关联知识片段推理**；可引用概览表中的极值、时长、等级。
- 模板为 **连续叙述**（非分条危害清单）；无独立 SQL 表。

### 2.4 总结和推荐措施（LLM + RAG）

四块：**紧急处置 / 运行优化调整 / 后续检修预防措施 / 计划长效防控方案**（模板示例文本，需结合本次超温区域与 RAG，禁止编造已执行操作）。

## 4. v3 数据计划设计（`analysis_plan_overheat_guidance` v3）

### 4.1 非 SQL 项：`q_meta`（由 `analysis_graph_runner` / 意图解析注入）

| 字段 | 说明 |
|------|------|
| `analysis_mode` | `daily` \| `weekly` |
| `t_start` / `t_end` | 与用户「今天/本周/…」对齐的闭开区间 |
| `unit_scope` | `single` \| `all` |
| `unit_keywords` | 机组关键字列表；`all` 时为空 |
| `boiler_order` | 多机组时排序键，默认 `boiler_name` |

> NL2SQL 各条 SQL 的 WHERE 子句应使用 `@t_start/@t_end/@unit_keyword` 占位，与现 v2 一致；**禁止**在 q1/q2 上使用 `LIMIT 1`（多机组场景）。

### 4.2 定级口径（全计划统一）

监测超温差值：`delta = highest_temp - limit_temp`（`limit_temp` 取自 `monitor_hotarea_temp`）

| 监测等级（内部） | 超温差值 | 模板异常等级 |
|------------------|----------|--------------|
| 轻微超温 | [5, 10) ℃ | Ⅰ级（轻微超温） |
| 中度超温 | [10, 20) ℃ | Ⅱ级（中度超温） |
| 严重超温 | ≥ 20 ℃ | Ⅲ级（严重超温） |
| 临界爆管风险 | 严重超温 **且** delta ≥ 40 ℃（与现 `_OVERHEAT_CRITICAL_DELTA_C` 一致） | Ⅳ级（临界爆管） |

### 4.3 q1 — 测点级超温明细（按日表 + 按周详情表）

**purpose**：`超温情况概览-测点明细（日/周详情共用）`

**question（NL2SQL 提示摘要）**：

> 在用户指定时间窗内，按 **机组 + 受热面 + 测点** 聚合超温记录，返回模板表格所需列。按机组名称、区域、超温差值降序。单条 SELECT，禁止 UNION。未指定机组时不加锅炉 LIMIT。

**参考 SQL**：

```sql
-- q1 测点级超温明细（按日 / 周详情共用）
-- 占位：@t_start @t_end @unit_keyword（可选，空则全厂）
SELECT
  ab.boiler_name AS 机组名称,
  CONCAT(
    IFNULL(asd.device_name, '未知区域'),
    ' 限', IFNULL(btd.over_hot_limit, t.limit_temp), '℃'
  ) AS 区域名称,
  t.pi_code AS 测点编号,
  IFNULL(btp.point_name, t.pi_code) AS 测点名称,
  MAX(t.highest_temp) AS 最大超温值_℃,
  MIN(t.highest_temp) AS 最小超温值_℃,
  ROUND(MAX(t.limit_duration) / 60, 0) AS 最大连续超温时长_分钟,
  DATE_FORMAT(MIN(t.start_time), '%Y.%m.%d %H:%i:%s') AS 超温日期,
  MAX(t.highest_temp - t.limit_temp) AS 最大监测超温差值_℃,
  CASE
    WHEN MAX(t.highest_temp - t.limit_temp) >= 40 THEN 'Ⅳ级（临界爆管）'
    WHEN MAX(t.highest_temp - t.limit_temp) >= 20 THEN 'Ⅲ级（严重超温）'
    WHEN MAX(t.highest_temp - t.limit_temp) >= 10 THEN 'Ⅱ级（中度超温）'
    WHEN MAX(t.highest_temp - t.limit_temp) >= 5  THEN 'Ⅰ级（轻微超温）'
    ELSE '正常'
  END AS 异常等级,
  asd.device_name AS 受热面名称
FROM monitor_hotarea_temp t
INNER JOIN account_boiler ab ON t.boiler_id = ab.boiler_id
LEFT JOIN account_static_device asd ON t.device_id = asd.device_id
LEFT JOIN base_temp_device btd ON t.device_id = btd.device_id
LEFT JOIN base_temp_point btp ON t.pi_code = btp.point_code
WHERE t.start_time >= @t_start
  AND t.start_time < @t_end
  AND t.highest_temp > t.limit_temp
  AND (@unit_keyword IS NULL OR @unit_keyword = '' OR ab.boiler_name LIKE CONCAT('%', @unit_keyword, '%'))
GROUP BY
  ab.boiler_name, asd.device_name, btd.over_hot_limit, t.limit_temp,
  t.pi_code, btp.point_name
ORDER BY ab.boiler_name, 最大监测超温差值_℃ DESC;
```

**槽位**：`s_overview_daily_table`（daily 模式）、`s_overview_weekly_detail_table`（weekly 模式）。

### 4.4 q2 — 区域级周概览（仅 weekly 模式）

**purpose**：`超温情况概览-周区域概览`

**question**：

> 在用户指定 **周/月时间窗** 内，按 **机组 + 受热面** 汇总：超温点数、周最大/最小壁温、周最大连续超温时长（分钟）、Ⅰ～Ⅳ 各档测点数量。单条 SELECT。

**参考 SQL**：

```sql
-- q2 区域级周概览（需应用层或二次查询拼接 q3 得到「周趋势」列）
SELECT
  ab.boiler_name AS 机组名称,
  CONCAT(IFNULL(asd.device_name, '未知区域'), ' 限', IFNULL(MAX(btd.over_hot_limit), MAX(t.limit_temp)), '℃') AS 区域名称,
  COUNT(DISTINCT t.pi_code) AS 超温点数,
  MAX(t.highest_temp) AS 周最大超温值_℃,
  MIN(t.highest_temp) AS 周最小超温值_℃,
  ROUND(MAX(t.limit_duration) / 60, 0) AS 周最大连续超温时长_分钟,
  SUM(CASE WHEN pt.max_delta >= 5  AND pt.max_delta < 10 THEN 1 ELSE 0 END) AS Ⅰ级数量,
  SUM(CASE WHEN pt.max_delta >= 10 AND pt.max_delta < 20 THEN 1 ELSE 0 END) AS Ⅱ级数量,
  SUM(CASE WHEN pt.max_delta >= 20 AND pt.max_delta < 40 THEN 1 ELSE 0 END) AS Ⅲ级数量,
  SUM(CASE WHEN pt.max_delta >= 40 THEN 1 ELSE 0 END) AS Ⅳ级数量,
  asd.device_name AS 受热面名称
FROM monitor_hotarea_temp t
INNER JOIN account_boiler ab ON t.boiler_id = ab.boiler_id
LEFT JOIN account_static_device asd ON t.device_id = asd.device_id
LEFT JOIN base_temp_device btd ON t.device_id = btd.device_id
INNER JOIN (
  SELECT pi_code, device_id, MAX(highest_temp - limit_temp) AS max_delta
  FROM monitor_hotarea_temp
  WHERE start_time >= @t_start AND start_time < @t_end AND highest_temp > limit_temp
  GROUP BY pi_code, device_id
) pt ON pt.pi_code = t.pi_code AND pt.device_id = t.device_id
WHERE t.start_time >= @t_start
  AND t.start_time < @t_end
  AND t.highest_temp > t.limit_temp
  AND (@unit_keyword IS NULL OR @unit_keyword = '' OR ab.boiler_name LIKE CONCAT('%', @unit_keyword, '%'))
GROUP BY ab.boiler_name, asd.device_name
ORDER BY ab.boiler_name, 周最大连续超温时长_分钟 DESC;
```

**槽位**：`s_overview_weekly_region_table`；**周趋势**列由 q3 + 程序拼接（见 5.2 节）。

### 4.5 q3 — 区域日趋势（仅 weekly 模式，供「周趋势」列）

**purpose**：`超温情况概览-周趋势（按日测点数）`

**参考 SQL**：

```sql
-- q3 区域 × 日期 → 当日超温测点数（用于拼接「10日 1个 | 11日 0个」）
SELECT
  ab.boiler_name AS 机组名称,
  asd.device_name AS 受热面名称,
  DATE(t.start_time) AS 超温日期,
  COUNT(DISTINCT t.pi_code) AS 当日超温测点数
FROM monitor_hotarea_temp t
INNER JOIN account_boiler ab ON t.boiler_id = ab.boiler_id
LEFT JOIN account_static_device asd ON t.device_id = asd.device_id
WHERE t.start_time >= @t_start
  AND t.start_time < @t_end
  AND t.highest_temp > t.limit_temp
  AND (@unit_keyword IS NULL OR @unit_keyword = '' OR ab.boiler_name LIKE CONCAT('%', @unit_keyword, '%'))
GROUP BY ab.boiler_name, asd.device_name, DATE(t.start_time)
ORDER BY ab.boiler_name, asd.device_name, 超温日期;
```

**程序拼接规则**（`analysis_synthesis_v2.py` 新增 renderer）：

- 对 q2 每一行 `(机组, 受热面)`，过滤 q3 子集，格式化为：  
  `{DD}日 {n}个` 多项用 ` | ` 连接；
- 若时间窗内某日无记录，显式 `0个`（与模板样例一致）。

### 4.6 q4 — 全事件运行工况（原因剖析）

**purpose**：`超温原因剖析-全事件平均工况`

**参考 SQL**（与现 q2b 同源，字段保留）：

```sql
SELECT
  ab.boiler_name AS 机组名称,
  ROUND(AVG(t.mw_value), 2) AS 平均负荷_MW,

INNER JOIN account_boiler ab ON t.boiler_id = ab.boiler_id
WHERE t.start_time >= @t_start
  AND t.start_time < @t_end
  AND t.highest_temp > t.limit_temp
  AND (@unit_keyword IS NULL OR @unit_keyword = '' OR ab.boiler_name LIKE CONCAT('%', @unit_keyword, '%'))

```

### 4.8 q6 — 吹灰运行记录（可选，原因剖析「吹灰作业/频次」）

**purpose**：`超温原因剖析-吹灰作业时间节点`

**依据表**：`monitor_soot_blower_run_record` + `base_soot_blower` + `account_static_device`（0331 / 0518 均有）。

**参考 SQL**：

```sql
SELECT
  ab.boiler_name AS 机组名称,
  asd.device_name AS 受热面名称,
  sb.blower_name AS 吹灰器名称,
  r.start_time AS 吹灰开始时间,
  r.end_time AS 吹灰结束时间,
  r.blowing_duration AS 吹灰时长_秒
FROM monitor_soot_blower_run_record r
INNER JOIN base_soot_blower sb ON r.blower_id = sb.blower_id
INNER JOIN account_boiler ab ON sb.boiler_id = ab.boiler_id
LEFT JOIN account_static_device asd ON sb.device_id = asd.device_id
WHERE r.start_time >= @t_start
  AND r.start_time < @t_end
  AND (@unit_keyword IS NULL OR @unit_keyword = '' OR ab.boiler_name LIKE CONCAT('%', @unit_keyword, '%'))
ORDER BY r.start_time;
```

**mandatory**：`false`（库中无记录时不阻塞报告）。

### 4.9 q7 — 磨煤机运行记录（可选，原因剖析「启停磨」）

### 5.2 条件执行（mode / scope）

在 `AnalysisSynthesisV2Graph` 执行前由 runner 传入：

```python
report_context = {
    "analysis_mode": "daily" | "weekly",
    "unit_scope": "single" | "all",
    "t_start": "...",
    "t_end": "...",
}
```

槽位跳过规则：

- `analysis_mode == "daily"` → 跳过 `s03_weekly_region`, `s04_weekly_detail`
- `analysis_mode == "weekly"` → 跳过 `s02_daily_table`（或 daily 表仅作为 week detail 时启用 s04）
- 所有 table 槽位：`gathered_data` 按 `机组名称` 分组渲染 **独立 Markdown 表格**（模板要求）

### 5.3 新增 renderer 要点

1. **`_render_overview_header(q_meta, q1)`**  
   - 输出：`机组信息：{name}`、`开始时间/结束时间`；多机组时循环表头。

2. **`_render_weekly_region_table(q2_rows, q3_rows)`**  
   - 合并 q3 生成 `周趋势`；  
   - 将 `Ⅰ级数量～Ⅳ级数量` 格式化为模板字符串：  
     `Ⅰ级（轻微超温）{n}个 Ⅱ级（中度超温）{n}个 …`

3. **`_partition_rows_by_boiler(rows, key="机组名称")`**  
   - 多机组分表核心工具函数。

4. **LLM prompt（s05/s06/s07）**  
   - 删除九段式、q 编号、置信度/依据；  
   - s05 必须输出：分布特征 + 周模式日趋势一句 + 分锅炉分区原因；  
   - s06/s07 注明「知识片段不足时写待补充」。

## 6. 无法匹配数据计划（SQL）的模板内容

以下条目在 **0331 库表 + 0518 流程** 下 **无可靠、可自动化 SQL**，必须在方案与报告中显式标注：

| 模板要求 | 原因 | 建议处理 |
|----------|------|----------|
| **煤质波动**（挥发分、灰分等） | 0331 **无煤质分析表** | 原因剖析写「煤质数据未接入，待补充」；可 RAG 泛化原理，**禁止编造数值** |
| **主汽温度、炉膛负压、氧量** 精确时序 | `monitor_hotarea_temp` 无此三列；仅当 `sis_pi_data` + `base_temp_point` **存在对应命名测点** 时可由 q5 部分覆盖 | q5 问句保留 LIKE 匹配；无行则「待补充」 |
| **减温水开度 / 调节响应速度** | 库中多为流量或笼统 DCS 点，**无统一开度字段** | 有测点则 q5 展示；无则待补充 |
| **同区域「正常测点」对比** | 模板原因段提及，但 **未定义正常测点选取规则**，且无「未超温测点快照」标准 SQL | v3 **不单独设 q**；LLM 仅允许基于 q1 已超温测点做区域对比，**禁止编造正常测点数值** |
| **历史同类案例对标** | 最新模板 **已删除** 附件对标表 | v3 不再实现 q6c |
| **整改效果 / 已执行调控操作** | 最新模板 **已删除** 第七章 | 不再实现 q5b；措施章 **禁止** 写「已执行」 |
| **现场检查照片** | 非结构化 | 不实现 |
| **报告编号 GL-CW-*** | 程序生成，非 DB | s01 表头可选展示，不占用 NL2SQL |
| **周趋势「0个」语义** | 产品需确认是 **测点数** 还是 **超温次数** | 本文按 **测点数**；若需次数，q3 改为 `COUNT(*)` |
