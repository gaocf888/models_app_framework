# 知识图谱基座能力完善计划（临时 · 可执行清单）

> 目标：在 **不影响现有在线业务** 的前提下，完善 GraphRAG / Neo4j 基座能力（阶段 1 + 阶段 2），补齐运维 API、Schema 加载、**LLM 实体关系抽取** 与部署初始化脚本。  
> 后续落地实现 **严格按本文 Todo 顺序** 执行；每完成一项可在 `[ ]` 处打勾。

---

## 0. 硬性原则（全程遵守）

| # | 原则 | 落地要求 |
|---|------|----------|
| P1 | **零影响在线业务** | 仅 **新增** 文件/接口/配置项；**不修改** Chatbot / 综合分析 / NL2SQL / 小模型等现有默认行为与响应结构 |
| P2 | **知识图谱默认关闭** | `GRAPH_RAG_ENABLED=false`（保持现状）；Hybrid 检索默认 `GRAPH_RAG_MODE=vector`（纯向量，与现网一致） |
| P3 | **RAG 联动写图默认关闭** | 新增独立开关 `GRAPH_RAG_INGEST_ON_RAG=false`；即使开启 GraphRAG，RAG 摄入 **也不写图**，除非显式打开 |
| P4 | **抽取必须用 LLM** | 图摄入默认走 **LLM 实体关系抽取链**；规则抽取仅作 **可配置回退**（默认关闭，`GRAPH_EXTRACTION_FALLBACK_RULE=false`） |
| P5 | **失败不阻断主链路** | 图写入/重建/LLM 抽取失败 **仅记日志 + 运维 API 返回明确错误**，不抛到 RAG 主流程、不改变 `/chatbot` 等接口语义 |
| P6 | **懒加载 / 条件初始化** | `GRAPH_RAG_ENABLED=false` 时：不建 Neo4j 连接、不加载 Schema、不注册 LLM 抽取链；`graph_admin` 路由可挂载但统一返回 **503 + 说明** |

## 1. 现状基线（实现前确认）

| 模块 | 路径 | 现状 |
|------|------|------|
| 图摄入 | `app/graph/ingestion.py` | `GraphIngestionService`：规则抽取 + Cypher 写 Neo4j；由 `RAGIngestionService.post_index_hook` 触发 |
| 图查询 | `app/graph/query_service.py` | `GraphQueryService`：规则实体 + 轻量 Cypher |
| 混合检索 | `app/rag/hybrid_rag_service.py` | `HybridRAGService`：`GRAPH_RAG_ENABLED=true` 且 mode≠vector 时才走图 |
| 配置 | `app/core/config.py` | `GraphRAGConfig`；`GRAPH_SCHEMA_CONFIG_PATH` 字段已有，**加载器未实现** |
| RAG 管理 API | `app/api/rag_admin.py` | `/rag/*`；Graph 仅 namespace 迁移时可选异步修复 |
| Neo4j 部署 | `graphrag_db-deploy/` | Compose + README；**无 init 约束/索引脚本** |
| 应用路由 | `app/main.py` | **无** `/graph/*` 路由 |

**当前联动写图条件（待改造）**：`GRAPH_RAG_ENABLED=true` → 初始化 `GraphIngestionService` → `post_index_hook` 自动写图。  
**目标**：写图需 **同时** 满足 `GRAPH_RAG_ENABLED=true` **且** `GRAPH_RAG_INGEST_ON_RAG=true`。

## 2. 目标架构（阶段 1 + 2 完成后）

```
graphrag_db-deploy/          Neo4j 容器 + init 约束/索引
        │ bolt
        ▼
app/graph/
  client.py                  Neo4j 连接封装（懒加载）
  schema_loader.py           YAML → GraphSchemaConfig
  extraction/
    llm_extractor.py         LLM 三元组/实体关系抽取（默认）
    rule_extractor.py        规则回退（可选，默认关）
  ingestion.py               编排：LLM 抽取 → 写图
  query_service.py           查询（可复用 schema）
  admin_service.py           统计 / 健康 / 重建 / Schema 热加载
app/api/graph_admin.py       /graph/* REST 运维（对齐 /rag/* 风格）
app/rag/ingestion.py         post_index_hook 增加 ingest_on_rag 门控
configs/graph_schema.yaml    领域本体模板（示例，默认 schema.enabled=false）
```

**与业务链路关系**（默认全部不生效）：

```
/rag/jobs/ingest  ──► 向量库（必走，不变）
                   ╳  post_index_hook 写图（GRAPH_RAG_INGEST_ON_RAG=false 时跳过）

/chatbot / /analysis  ──► HybridRAGService ──► RAGService（GRAPH_RAG_MODE=vector 时与现网一致）
```

## 3. 统一环境变量设计（知识图谱配置段）

> 实施时同步更新：`app/core/config.py`、`app/app-deploy/.env.example`、`graphrag_db-deploy/project-env/graph-neo4j.env.example`。

### 3.1 总开关与 Neo4j 连接（已有，保持默认关）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `GRAPH_RAG_ENABLED` | `false` | **总开关**；false 时整个 Graph 子系统不初始化 |
| `NEO4J_URI` | （空） | Bolt 地址，如 `bolt://graph-neo4j:7687` |
| `NEO4J_USERNAME` | （空） | Neo4j 用户名 |
| `NEO4J_PASSWORD` | （空） | Neo4j 密码 |
| `NEO4J_DATABASE` | `neo4j` | 数据库名 |

### 3.2 新增：联动与抽取（本次重点）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `GRAPH_RAG_INGEST_ON_RAG` | `false` | RAG 摄入成功后是否 **联动写图**（`post_index_hook`） |
| `GRAPH_RAG_MODE` | `vector` | 检索模式：`vector` \| `graph` \| `hybrid`（默认 vector，不改变现网） |
| `GRAPH_SCHEMA_CONFIG_PATH` | `configs/graph_schema.yaml` | Schema YAML 路径；文件不存在时走 schema-less |
| `GRAPH_SCHEMA_HOT_RELOAD` | `false` | 是否允许 Admin API 热加载 Schema（默认关，仅运维显式开启） |
| `GRAPH_EXTRACTION_MODE` | `llm` | 抽取模式：`llm`（默认）\| `rule`（仅调试） |
| `GRAPH_EXTRACTION_FALLBACK_RULE` | `false` | LLM 抽取失败时是否回退规则抽取（默认否） |
| `GRAPH_LLM_ENDPOINT` | （空，回退 `LLM_DEFAULT_ENDPOINT`） | LLM 抽取用的 OpenAI 兼容 endpoint |
| `GRAPH_LLM_MODEL` | （空，回退默认 chat 模型） | 抽取模型 ID |
| `GRAPH_LLM_TIMEOUT_S` | `120` | 单次抽取超时 |
| `GRAPH_LLM_MAX_TOKENS` | `2048` | 抽取输出 token 上限 |
| `GRAPH_LLM_BATCH_SIZE` | `4` | 每批 chunk 数（控制并发与成本） |
| `GRAPH_LLM_MAX_RETRIES` | `2` | 抽取失败重试次数 |

### 3.3 检索与融合（已有，保持默认偏向量）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `GRAPH_RAG_VECTOR_WEIGHT` | `0.6` | hybrid 模式向量权重 |
| `GRAPH_RAG_GRAPH_WEIGHT` | `0.4` | hybrid 模式图权重 |
| `GRAPH_RAG_USE_INTENT_ROUTING` | `false` | 意图路由（默认关，避免行为变化） |

### 3.4 `.env.example` 知识图谱段目标形态（示意）

```env
# ━━ 应用进程 · 知识图谱 / GraphRAG（默认全部关闭）━━━━━━━━━━━━━━━━━━━━
GRAPH_RAG_ENABLED=false
GRAPH_RAG_INGEST_ON_RAG=false
GRAPH_RAG_MODE=vector
# NEO4J_URI=bolt://graph-neo4j:7687
# NEO4J_USERNAME=neo4j
# NEO4J_PASSWORD=
# NEO4J_DATABASE=neo4j
GRAPH_SCHEMA_CONFIG_PATH=configs/graph_schema.yaml
GRAPH_SCHEMA_HOT_RELOAD=false
GRAPH_EXTRACTION_MODE=llm
GRAPH_EXTRACTION_FALLBACK_RULE=false
# GRAPH_LLM_ENDPOINT=          # 空则复用 LLM_DEFAULT_ENDPOINT
# GRAPH_LLM_MODEL=
GRAPH_LLM_TIMEOUT_S=120
GRAPH_LLM_BATCH_SIZE=4
```

## 7. 风险与回滚

| 风险 | 应对 |
|------|------|
| LLM 抽取增加 RAG 摄入延迟 | 默认 `GRAPH_RAG_INGEST_ON_RAG=false`；开启后走异步 rebuild 而非同步 hook（后续优化项，首版保持 hook + 失败不阻断） |
| 误开 Graph 导致 Hybrid 行为变化 | 默认 `GRAPH_RAG_MODE=vector`；文档强调三开关：`ENABLED`、`INGEST_ON_RAG`、`MODE` |
| Neo4j init 与已有数据冲突 | init 脚本幂等（`IF NOT EXISTS`）；README 标明仅空库首次执行 |
| 新 API 暴露攻击面 | 与 `/rag` 相同 `require_service_api_key`；enabled=false 返回 503 |

**回滚**：任一阶段问题 → 设 `GRAPH_RAG_ENABLED=false` 并重启应用，即恢复纯向量 RAG，无需删代码。
