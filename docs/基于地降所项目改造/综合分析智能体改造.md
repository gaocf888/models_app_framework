## 0. 改造结论摘要

### 0.1 目标能力画像

将智能体从「**按章串行：取数→合成→推送**」演进为：

```text
全量并行取数（acquire_data）
  → 轻量质量门（重试 / 降级，无 HITL）
  → 按章合成（叙述真流式；表/图配置化程序渲染优先）
  → 顺序 SSE 推送（合成可有限并行）
```

并补齐：**流式 stop、Redis/ES Trace 运维面、地降 `subsidence_*`（季报实装）、NL2SQL 基座开关打穿、可选轻量会话辅助**。

### 0.2 与现网综合分析的关系

| 维度 | 现网 `/analysis` | 改造后 `/analysis-agent` |
|------|------------------|---------------------------|
| 取数 | `acquire_data` 分层并行 | **对齐**：统一 `acquire_data` |
| 合成 | v1 整篇 / v2 多槽 | **按章**合成 + 顺序 emit |
| HITL | 看图诊断 scope | **去掉**缺数 HITL |
| 规划前三库 RAG | 有（喂 intent/plan LLM） | **本期不做**（见 §4） |
| 业务 | 锅炉 + 地降 + 看图 | 锅炉四类 + **地降五类**；**不含**看图诊断 |

### 0.3 明确不做（本期）

- 不接入看图诊断（`img_diag`）  
- 不增加「规划前 NL2SQL 三库 RAG」节点（基座 `NL2SQLService` 内已有三库召回）  
- 不强制对齐现网超温 v2 日/周程序模板（锅炉超温专项另立对齐项，非本文主线）  
- 不以客服式指代消解改写主 `query` 作为取数意图源  

### 0.4 改造后目标主图（总览）

```text
POST /analysis-agent/run-stream
  → initialize
  → intent_rag              （业务 RAG；可选近 N 轮摘要辅助，不改写 query）
  → acquire_data            ★ 全量 plan q* 去重；dependency 分层并行
  → data_quality            ★ 轻量质量门：mandatory 重试 / 降级 / strict 失败
  → chapter_pipeline        （按 chapters[]；合成可有限并行，emit 保序）
        → chapter_prepare   （读 gathered 切片；程序表/图按 JSON 配置先渲染）
        → chapter_synthesize（llm_section：优先 stream_chat；emit 工具章可 ReAct）
        → chapter_emit      （SSE：delta / table / chart / chapter_complete）
  → finalize
```

协作中断：`POST /analysis-agent/stream/stop`（`stream_id`）。

## 1. HITL 移除与缺数策略（对应思路 1）

### 1.1 决策

- **删除**主路径 `slot_human` / `interrupt` / `resume-stream` 依赖（API 可保留兼容但默认关闭）。  
- `ANALYSIS_AGENT_ENABLE_HUMAN_IN_THE_LOOP` 默认改为 **`false`**；生产建议关闭。  
- Checkpoint 不再因缺数 HITL 成为硬前置（仍可用于可选断点，非必须）。

### 1.2 缺数策略（重试耗尽后）

| 条件 | 行为 |
|------|------|
| mandatory 空/失败且重试未耗尽 | 清空该 `item_id` 缓存 → 重跑 NL2SQL（次数：`ANALYSIS_AGENT_SLOT_NL2SQL_MAX_RETRIES`，建议改名为全局 `ACQUIRE_MAX_RETRIES`） |
| 重试耗尽且 `options.strict=true` | `abort` → `analysis_agent_error` / finalize 失败态 |
| 重试耗尽且默认 `strict=false` | 写入 `task_status=mandatory_empty|mandatory_failed`；章节合成时强制「待补充」约束；继续后续章 |

### 1.3 实现要点

- `orchestrator.run_slot_quality`：去掉 `needs_human_interrupt` 分支。  
- `builder.py`：去掉 `slot_human` 节点与边。  
- Trace / metrics：保留 `degrade_reasons`（如 `mandatory_empty_continue`）。

## 2～3. 取数并行化统一方案（对应思路 2+3）

### 2.1 现状结论（必须写清）

| 场景 | 是否重复调 `NL2SQLService` |
|------|---------------------------|
| **章内**多 `q*` | 否（`asyncio.gather` 各调一次） |
| **跨章** `source_item_ids` 重叠，且**章串行** | **否**（`plan_item_resolved` 会话缓存） |
| **跨章**重叠，且**章流水线并行**且无统一预取 | **会**（竞态下重复调用） |

因此：**禁止**「章节全流水线并行且各自取数」；统一改为：

> **全量先并行取数（`acquire_data`）+ 章节合成有限并行 / 串行保序推送**

### 2.2 新增节点 `acquire_data`

位置：`intent_rag` → **`acquire_data`** → `data_quality` → `chapter_pipeline`。

行为：

1. 自 `plan_tasks`（见 §4）得到全量 `item_id`。  
2. 按 `dependency_ids` **分层**（对齐现网 `_execute_data_plan`）；无依赖则一层全并行。  
3. 并行度：`ANALYSIS_AGENT_ACQUIRE_MAX_PARALLEL`（默认对齐现网 8）。  
4. 结果写入 `gathered_data` / `task_status` / `nl2sql_calls`；SSE 推送 `analysis_agent_nl2sql_done`（含 `cached` 仅用于层内去重场景）。  
5. 原 `slot_nl2sql`：**删除或退化为只读校验**（发现缺失且非终态才补漏，默认不应发生）。

### 2.3 章节并行策略（合成侧）

| 阶段 | 策略 |
|------|------|
| 取数 | **全量并行**（已在 `acquire_data`） |
| 合成 | 可选有限并行：`ANALYSIS_AGENT_CHAPTER_SYNTH_MAX_PARALLEL`（默认 1=串行；建议生产 2～3） |
| Emit | **必须按 `chapters[]` 顺序**推送，避免 SSE 乱序 |

静态章 / 纯程序表图章可与相邻 LLM 章流水重叠，但对外事件序不变。

### 2.4 与「章节串行改并行」表述的收敛

对外文档统一写：

- **取数**：全量并行（不再按章取数）。  
- **成稿推送**：顺序章节流；合成计算可有限并行。  

不再宣传「整章 nl2sql→synth→emit 全并行」。

## 4. 数据计划加载与规划前 RAG（对应思路 4）

### 4.1 数据计划优先级（必须落地并写进简版）

```text
1) configs/analysis_agent_reports/{type}.*.json
     └─ 若存在非空 plan.items（或顶层 plan_items）→ 用作 plan_tasks
2) 否则回退 configs/prompts.yaml
     └─ scene: analysis_agent_plan_{type}（version=ANALYSIS_AGENT_PLAN_TEMPLATE_VERSION）
```

加载入口：`app/analysis_agent/context_loader.py` → `load_analysis_run_context`（已具备该优先级，改造期保持并加强文档/联调说明）。

**推荐地降季报**：把 q\* **内嵌进 report JSON 的 `plan.items`**，与章节、图表同文件维护；yaml 仅作锅炉旧专项兜底。

### 4.2 规划前 NL2SQL 三库 RAG：**本期不做**

| 点 | 说明 |
|----|------|
| 现网用途 | 喂 `intent_llm` / `plan_llm` 或拼问句附录 |
| 智能体 | 无动态 plan LLM；每个 `NL2SQLService.query` **内部已走** schema/biz/qa 召回 |
| 决策 | **暂不增加** `plan_context_rag` 节点；准确率优先靠问句质量、QA 沉淀、五元组、语义链接（基座改造） |

## 5. 轻量质量门（对应思路 5）

对齐现网「有质量门」，但**不原样搬**覆盖率/异常率全套阈值（报告场景默认应降级继续写）。

### 5.1 策略分级

| 级别 | 检查项 | 默认动作 |
|------|--------|----------|
| L0 | mandatory 终态失败/空 | 重试 → strict 失败 / 标注待补充 |
| L1 | 解析意图缺关键锚点（地降：`time`+`zone`；锅炉超温：`time` 等） | 记 `degrade_reasons`；非 strict 继续 |
| L2（可选，`strict` 或专项开关） | 行级缺关键列比例超阈 | 降级或失败 |

配置建议：

- `ANALYSIS_AGENT_QUALITY_PROFILE=light|strict_like`  
- 地降季报默认 `light` + L1 锚点检查  

质量门节点名：`data_quality`（替代原按章 `slot_quality` 的主职责；章级仅消费 `task_status`）。

## 6. 地降 `subsidence_*`（对应思路 6）

### 6.1 类型清单

| `analysis_type` | 优先级 | 说明 |
|-----------------|--------|------|
| `subsidence_quarterly` | **P0 实装** | 对齐季报 docx |
| `subsidence_daily` / `weekly` / `monthly` / `yearly` | P1 占位 | 最小 chapters + plan 骨架，synthesis 可复用短模板 |

前置：部署 `NL2SQL_BUSINESS_DOMAIN=subsidence`（见 NL2SQL 基座改造）。

### 6.2 季报结构（依据《北京市地面沉降监测季度报告》目录）

报告规格：`configs/analysis_agent_reports/subsidence_quarterly.analysis_agent.json`。

建议章节（可微调编号，语义对齐 docx）：

| 章 | 标题意图 | 典型数据 / 图 |
|----|----------|----------------|
| 封面/标题 | 静态 Markdown | — |
| 一、前言 | LLM：任务依据、站点规模、本季极值摘要 | q 汇总 + 可选表 |
| 二.（一）全市平原沉降成果 | LLM + **柱/条形图**（各区升降极值） | 行政区汇总 q |
| 二.（二）分区沉降成果 | 按区叙述；可多小节或循环区划 | 分区站点统计 |
| 二.（三）分层标（四含水层） | 各层沉降特征 + **图/表** | 分层标序列/差值 |
| 二.（四）重点区域 | 表格（docx 表 4-1 类）+ 解读 | 重点区站表 |
| 二.（五）小结 | LLM | 复用前述 q |
| 附录 | 程序表（全市站点清单等） | 附录 q |

### 6.3 Plan 建议

优先 **内嵌 `plan.items`**；可参考现网 `analysis_plan_subsidence_quarterly`（q1～q4）扩展为季报专用 `q*`（全市/分区/分层/重点/附录）。  
`plan_template_version` 使用 `analysis_agent_v1`（与锅炉 `/analysis` 的 v1/v2 **隔离**）。

### 6.4 图表必须配置化

见 §12：季报图（如「全市平原…统计图」「分区统计图」）在 report JSON 的 `charts[]` / `tables[]` 声明，**程序渲染**，LLM 只写解读，禁止纯靠 ReAct 手搓关键图。

## 7. 流式 Stop（对应思路 7）

对齐现网：`POST /analysis/stream/stop`。

| 项 | 设计 |
|----|------|
| 路由 | `POST /analysis-agent/stream/stop` |
| 入参 | `user_id` / `session_id` / `stream_id` |
| 首帧 | `run-stream` 立即下发 `started`（含 `stream_id`、`request_id`） |
| 实现 | 复用或旁路现网 `StreamController`；`acquire_data` / 章合成循环检查取消标志 |
| SSE | `analysis_agent_cancelled` + `terminate_reason=user_cancelled` |

注意：已发出的章节 delta **不撤回**；取消后尽快结束 gather / LLM。

## 9. 首 token / 流式优化（对应思路 9）

### 9.1 落地策略（按优先级）

1. **取数前置**：`acquire_data` 完成后立即开写第 1 章（消除「等前章取数」）。  
2. **叙述章真流式**：无 `use_emit_tools` 的 `llm_section` 默认 `VLLMHttpClient.stream_chat`，边生成边 `summary_delta`。  
3. **ReAct 限用**：仅 `use_emit_tools=true` 且需要动态表图时；或「先 stream 正文 → 再工具补表图事件」。  
4. **禁用**「整章 `ainvoke` 后再 `_chunk_text` 假流式」作为叙述主路径。  
5. （可选）章合同有限并行：缩短总时长；emit 仍保序。

### 9.2 配置

- `ANALYSIS_AGENT_USE_REACT_AGENT`：默认 `false` 或仅工具章开启  
- `ANALYSIS_AGENT_NARRATIVE_STREAMING=true`  
- `stream_live` 字段：与真流式绑定，不再空置

## 10. NL2SQL 基座开关打穿（对应思路 10）

| 项 | 现状 | 改造 |
|----|------|------|
| `analysis_type` + `plan_item_id` + `plan_template_version` | 已传 | 保持；地降新 type 走独立五元组空间 |
| `time_intent_text` | 已传用户 `query` | 保持；**禁止**被历史会话改写 |
| `ANALYSIS_AGENT_NL2SQL_DISABLE_QA_SLOT_REPLAY` | config 有、executor **已打穿** | **`nl2sql_executor` → `NL2SQLQueryRequest.disable_qa_slot_replay` → chain**；agent 路径默认跳过 strict replay |
| QA 自动写入 | 依赖全局 `NL2SQL_QA_FEEDBACK_ENABLED` | 文档标明；联调地降季报后开启沉淀 |

验收：日志/trace 可见五元组；关闭 replay 时即使 QA 命中仍走生成链路（与配置一致）。

## 11. 会话上下文（明确不做）

综合分析智能体以**一次性报告**为主，**不提供**客服式多轮 `enable_context`。  
取数意图仅来自本轮 `query`（及 NL2SQL 基座内召回），禁止用历史改写 `time_intent_text`。

若产品后续需要「接着上季」类口头补充，应改写本轮 query 后重跑，或另立需求。

## 13. 改造后主图与文档交付（对应思路 13）

### 13.1 LangGraph 节点说明（简要）

| 节点 | 职责 |
|------|------|
| `initialize` | 加载 report + plan（§4 优先级）；初始化 state / `stream_id` |
| `intent_rag` | 业务 RAG；可选历史摘要辅助 |
| `acquire_data` | 全量 NL2SQL；依赖分层并行 |
| `data_quality` | 轻量质量门；重试；strict/降级 |
| `chapter_pipeline` | 按章 prepare/synthesize/emit；可有限并行合成，emit 保序 |
| `finalize` | `report_complete` + `finished`；写 Trace（含 abort/failed） |

条件边：`data_quality` → 重试 `acquire_data`（局部 item）或进入 `chapter_pipeline` 或失败 finalize。

`chapter_pipeline` 内部步骤：`chapter_prepare` → `chapter_synthesize` → `chapter_emit`（SSE：`analysis_agent_chapter_start` / `summary_delta` / `table|chart_payload` / `chapter_complete`）。

### 13.2 文档同步清单

| 文档 | 动作 |
|------|------|
| 本文 `docs/基于地降所项目改造/综合分析智能体改造.md` | **方案真源** |
| `.../系统整体逻辑、配置说明-简版.md` §2 | **极简**改为改造后链路 + plan 优先级 + 关键 env |
| `.../综合分析智能体(analysis_agent)实现逻辑说明.md` | 按客服 LangGraph 文档风格，写清目标态流程（供评审） |
| `.../实现逻辑说明(代码).md` | 实施过程中按代码对照回写；改造完成前顶部增加「目标态见改造方案」指针 |

### 13.3 API 一览（改造后）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/analysis-agent/run-stream` | 主入口 SSE |
| POST | `/analysis-agent/stream/stop` | ★ 中断 |
| GET | `/analysis-agent/trace/{request_id}` | 单条 |
| GET | `/analysis-agent/traces` | ★ 列表 |

## 14. 分期实施计划

## 16. 风险与依赖
