## 0. 结论：V2 相对 V1 改什么

V1 已具备：`initialize → intent_rag → acquire_data → data_quality → chapter_pipeline → finalize`，report JSON 驱动章节，表/图程序渲染。地降五类目前多为占位，季报未对齐 Word。

V2 **只在 V1 主图上加能力**，不新造报告引擎：

| 增量 | 做什么 |
|------|--------|
| 板块库 + 模版拼装 | 五类报告引用可复用板块；循环/变体展开成 `chapters[]` |
| 结构化周期/区划 | `options.start_time/end_time/area/issue_no`；默认**上一完整周期** |
| 确定性计划项 | 窗初/窗末 SQL 走基座 **执行器**；层间差/附表/典型曲线在工程算 |
| 设备/地图 | 占位骨架，不造假数 |

**压缩层口径（防走偏）**：先查边界标初末，再程序算层间差。查数用确定性 SQL + `SQLExecutor`（NL2SQL **执行器**）。**生成器不当附表真源**。不是「不连基座」，也不是「让 LLM 写出 compress_mm」。

## 2. 运行时主图（V1 节点 + V2 钩子）

```text
POST /analysis-agent/run-stream
  initialize
      ★ resolve_period / resolve_area
      ★ 空 query 补规范问句（喂 L1 与 NL2SQL 叙述项）
      ★ compose 展开 → ordered_slots + plan_tasks 并集
  intent_rag                         （不变；不算数）
  acquire_data                       ★ 按 task.executor 分支
      nl2sql        → NL2SQLService.query（生成+执行）
      sql_template  → SQLExecutor.execute（绑定参数，无生成器）
      python        → 读 gathered_data 做切片/层间差/择优
      placeholder   → 空行 + 待补充状态
  data_quality                       ★ 结构化起止视为已有 time 锚点
  chapter_pipeline                   合成默认串行；cover 占位符替换
  finalize
```

锅炉四类：无 `compose`、无新 options 时行为与 V1 完全一致。

| 周报 | cover(short) → station_ops → plain_monitoring → key_area → device_alert |

`key_area` 季报：`{ "section": "key_area", "variant": "with_table" }`。

### 3.4 展开算法（`compose.py`）

输入：模版 raw + 板块库 + `period`/`area`/`issue_no`。  
输出：与 V1 `ReportSpec` 同构的 `chapters` / `plan_items` / `tables` / `charts`（`load_report_spec` 之后即可走现网 `slots_from_spec_dict`）。

1. 读取 `shared_plan_items`（至少含 §5 的 `q_fcb_endpoints` 及衍生项）。  
2. 按 `compose[]` 顺序：加载板块；若有 `variant` 深合并；若有 `iterate`，对每个 item 克隆一章。  
3. chapter `id`：无循环用板块 id；循环用 `{section_id}__{item.id}`（如 `district_results__chaoyang`）。  
4. 表/图 `id` 同样加后缀，避免 SSE 碰撞；`attach_to_chapter` 指向展开后 chapter id。  
5. 循环章的 `source_item_ids` 仍指向共享 `q_layer0` / `q_compress`，渲染时用 `filter_field` + iterate 值过滤行（`configured_viz` 增加可选 `row_filter`）。  
6. `plan_items` 并集按 `item_id` 去重；`source_item_ids` 必须 ⊆ 并集（沿用现网校验）。  
7. `cover`：`kind=static_markdown`，`static_body` 含 `{title}{issue_no}{period_label}{report_date}`，在 `initialize` 或 `chapter_prepare` 替换。  
8. 无 `compose` 或 `schema_version < 3`：**原样 V1 加载**，禁止走展开器。

`_index.yaml` 示例：

```yaml
plain_districts:
  - { id: chaoyang, name: 朝阳区 }
  - { id: haidian, name: 海淀区 }
  - { id: tongzhou, name: 通州区 }
  - { id: shunyi, name: 顺义区 }
  - { id: changping, name: 昌平区 }
  - { id: daxing, name: 大兴区 }
  - { id: pinggu, name: 平谷区 }
  - { id: yanqing, name: 延庆区 }
compress_groups:
  - { id: l01, name: 第一压缩层组, layer_from: 0, layer_to: 1 }
  - { id: l12, name: 第二压缩层组, layer_from: 1, layer_to: 2 }
  - { id: l23, name: 第三压缩层组, layer_from: 2, layer_to: 3 }
```

## 4. 结构化入参与默认周期

### 4.1 API（兼容旧客户端）

`POST /analysis-agent/run-stream` 不变。`AnalysisAgentRunRequest.query` 改为 **可选**（默认 `""`）。`AnalysisAgentOptions` 增加：

| 字段 | 类型 | 说明 |
|------|------|------|
| `start_time` | `str` 可选 | ISO8601 或 `YYYY-MM-DD`；与 `end_time` 成对 |
| `end_time` | `str` 可选 | **半开**上界；缺省则按模版算上一完整周期 |
| `area` | `str` 可选 | `t_station.area` 标准名；空/「全市」「北京市」= 不按区过滤 |
| `issue_no` | `str` 可选 | 封面「第 XX 期」；空则文案「第 XX 期」 |

校验：只传一个起止 → 400；`area` 非空且不在 `district.yaml` 且不是全市别名 → 400；禁止把未校验字符串拼进 SQL。

### 4.2 周期解析（`period.py`）

时区：配置/服务器本地日（与现网 NL2SQL `CURRENT_DATE` 一致即可，代码写清用 `date.today()` 或 `Asia/Shanghai`，全项目统一一处）。半开区间 `[start, end)`。

| `analysis_type` | 未传起止时的窗 |
|-----------------|----------------|
| `subsidence_daily` | 昨天 0 点 ～ 今天 0 点 |
| `subsidence_weekly` | 上一自然周：上周一 0 点 ～ 本周一 0 点（Python `weekday()` 周一=0） |
| `subsidence_monthly` | 上一自然月月初 ～ 本月月初 |
| `subsidence_quarterly` | 上一自然季季初 ～ 本季季初 |
| `subsidence_yearly` | 去年 1 月 1 日 ～ 今年 1 月 1 日 |

传入起止则覆盖（仍半开：若客户端传闭区间日期，把 `end` 理解为次日 0 点或文档约定「end 当天 24 点」——**实现取：日期-only 的 end 视为次日 0 点**）。

`period_label` 例：`2026年8月13日` / `2026年8月11日—8月17日` / `2026年7月` / `2026年第二季度` / `2026年`。  
`report_date`：生成日，用于封面落款。

写入 `state["options"]["_resolved"]`：

```json
{ "t_start": "2026-04-01T00:00:00", "t_end": "2026-07-01T00:00:00", "area": null, "period_label": "2026年第二季度", "issue_no": "XX" }
```

确定性 SQL 与 python 项只读 `_resolved`，**不**再从 query 猜时间。

### 4.3 规范 query

若 `query` 为空或仅空白，`initialize` 设为：

`生成{area_or_全市}{period_label}地面沉降监测{日报|周报|月报|季度报告|年报}`。

L1：地降若 `_resolved.t_start/t_end` 已有，视为 **time 锚点已满足**；`area` 空视为全市（zone 满足）。有结构化窗时不要因问句解析失败而 degrade。

## 5. 数据计划与 executor 分支

### 5.1 plan item 扩展字段

```json
{
  "item_id": "q_fcb_endpoints",
  "executor": "sql_template",
  "sql_file": "fcb_period_endpoints.sql",
  "mandatory": true,
  "dependency_ids": [],
  "purpose": "边界标窗初窗末累计沉降"
}
```

| `executor` | 行为 |
|------------|------|
| 缺省 / `nl2sql` | 现网 `run_nl2sql_for_plan_item`（叙述辅助、非附表真源） |
| `sql_template` | 读 `sql_file`，绑定 `_resolved` + 字典标号列表，`SQLExecutor.execute` |
| `python` | `python_fn` 指定注册函数，输入依赖项 rows，输出本项 rows |
| `placeholder` | `gathered_data[id]=[]`，`task_status=optional_empty`，不失败 |

地降模版 **禁止** 用 `nl2sql` 项作为 `annex_*` / `layer_results` / 表 4-1 的 `source_item_ids`。

### 5.2 共享计划项（所有需要沉降数字的模版）

| item_id | executor | 依赖 | 产出 |
|---------|----------|------|------|
| `q_fcb_endpoints` | sql_template | — | 每边界标：area, project_name, station_name, settle_start, settle_end, time_start, time_end |
| `q_layer0` | python `slice_layer0` | q_fcb_endpoints | 层位 0 行 + `delta_mm=start-end`；缺初/末丢弃 |
| `q_compress` | python `layer_compress` | q_fcb_endpoints | 连续层对 compress 行 |
| `q_key_area` | python `join_key_areas` | q_layer0, q_compress | 表 4-1 结构行 |
| `q_typical` | python `typical_curve` | q_layer0, 及可选 sql 时序项 | 择优后的双轴序列 |
| `q_ops_placeholder` | placeholder | — | 空 |
| `q_alert_placeholder` | placeholder | — | 空 |

日报/周报没有分层附表也可拉 `q_fcb_endpoints`+`q_layer0`（平原区叙述用）。月报加 `q_typical`。季报/年报加 `q_compress`+`q_key_area`+附表绑定。

日/周若仍配 `nl2sql` 问句，**不得**替代 `q_layer0`；叙述章 `source_item_ids` 指向 `q_layer0`。

### 5.3 acquire_data 改动（`orchestrator._run_one_plan_item`）

```text
ex = task.get("executor") or "nl2sql"
if ex == "sql_template": 跑模板 SQL，nl2sql_calls.sql=实际 SQL，event 仍用 analysis_agent_nl2sql_done（加 executor 字段）
elif ex == "python": 调注册表；依赖未 success 则本项 failed/skipped（沿用 dependency 逻辑）
elif ex == "placeholder": 空成功或 optional_empty（占位章不阻断）
else: 现网 NL2SQL
```

`SQLExecutor.execute` **增加可选 `params: dict`**（默认 None，旧调用不变）。用 `sqlalchemy.text(sql).bindparams(...)` 或 `conn.execute(text(sql), params)`。**禁止**把用户 `area` 未校验拼进字符串。

标号列表来自 `fcb_layer_map`：仅 `monitor_layer is not None`。`station_name` 以 `J` 开头（忽略大小写）→ jyb 列表，其余 → fcb 列表。

## 6. 窗初/窗末 SQL 与压缩层计算

### 6.1 公式（与脚本、P6 一致）

```text
Δ(标) = settle_start − settle_end          # 窗内非空最早/最晚；有效点须对应两个不同 data_time
仅 monitor_layer ∈ {0,1,2,3,4}
仅 next - curr == 1
compress(i→i+1) = Δ(i) − Δ(i+1)
0-1 第一压缩层组 … 3-4 第四压缩层组
```

缺层不造对：F11 无 2-3、3-4；F9/F10 无 3-4（字典无对应 `monitor_layer` 即无键）。  
`J*` → `t_data_wash_jyb`，`F*` → `t_data_wash_fcb`。  
站点键用字典 `project_name`，不要从标号抠数字分组。

### 6.2 `fcb_period_endpoints.sql`（PostgreSQL，实施时以此为底）

绑定：`t_start`, `t_end`, `fcb_marks`（text[]）, `jyb_marks`（text[]）, `area`（text 或 NULL）。

逻辑要求（实现可用 CTE）：

1. 从 fcb / jyb 取 `station_name = ANY(:marks)` 且 `data_time >= :t_start AND data_time < :t_end` 且 `total_settle IS NOT NULL`。  
2. 每 `(project_name, station_name)`：`rn_asc`/`rn_desc` 取最早、最晚。  
3. `LEFT JOIN t_station ON t_station.name = project_name`。  
4. `:area` 非空时 `t_station.area = :area`。  
5. 初末 `data_time` 相同或缺一侧 → **不输出该标**（等同脚本 `< 2` 个有效点）。

空数组：对应 UNION 分支不选行（`COALESCE(:jyb_marks, ARRAY[]::text[])`）。

### 6.3 `slice_layer0`

字典 `monitor_layer==0` 的 `(project_name, station_name)` 与 endpoints 内连接。  
`delta_mm = settle_start - settle_end`。  
输出列：`area, project_name, station_name, delta_mm, settle_start, settle_end`。  
这就是 42 站（全市无区划过滤时）；**禁止**用 `t_station` 全表补站。

### 6.4 `layer_compress`

按 `project_name` 分组；把 endpoints 行通过字典映射到 `layer→Δ`（只含有数字层位的标）。排序后只做连续对。输出：

`area, project_name, layer_from, layer_to, mark_from, mark_to, delta_from, delta_to, compress_mm`

一侧 Δ 缺失 → 该对不输出（附表格空，不是 0）。

### 6.5 一次拉取服务两个 grain

`q_fcb_endpoints` 一次 SQL → `q_layer0`（附表 1、平原/分区/重点区总沉降）+ `q_compress`（附表 2–5、分层成果、表 4-1 层组列）。不要为压缩层再跑生成器。

## 7. 重点区、典型曲线、占位、封面

### 7.1 `join_key_areas`

读 `key_monitoring_areas.yaml`。每个配置站一行：

- `area_name, station_code, project_name, location_raw`  
- `total_delta_mm`：来自 `q_layer0`（层位 0）  
- `c01..c34`：来自 `q_compress` 对应层对；无则 `null`  

周/月 `key_area` 章只绑定叙述 + 按 `area_name` 聚合解读，**不**挂表。季报 `variant=with_table` 挂表 4-1（列：地区、监测站总数、监测站编号、总沉降、四个压缩层组）。同一 `area_name` 多站：程序表按 yaml 站序输出，地区单元格可重复（前端可合并，非必须）。

### 7.2 典型曲线（月报；季报不做除非 compose 引用）

**选站**：`q_layer0` 中 `|delta_mm|` 最大且该 `project_name` 在水位表有序列。  
**配对水位**：`t_data_wash_dxswj` 同 `project_name`；多井取窗内非空点数最多者（并列取 `station_name` 排序首个）。月报例 F21 ↔ D21-* 仅作回归对照，代码不写死 F21。

候选双轴（序列均要完整，否则淘汰）：

1. 层位 0 日序列 × 水位 `elevation`（主路径，对齐月报图 2）  
2. 层位 0 × `t_data_wash_qxz.real_time_rain`（同 `project_name`，否则淘汰）  
3. 该站 `compress 0-1` 的两端标日 Δ 或两端 `total_settle` 差序列 × `t_data_wash_kxsylj.pressure`  
4. 可选：层位 0 × GNSS `displacement_2d`（`project_name` 能对齐才保留）

时序 SQL 用 `sql_template` 项（可 `mandatory: false`），`typical_curve` python 依赖它们。  
**择优分数**（实现写死权重即可，配置化可后做）：辅助序列完整率 ×0.4 + 与沉降同窗相关绝对值 ×0.3 + `|delta_mm|` 归一化 ×0.3。月报默认 Top1；第二名低于阈值（如完整率&lt;0.5）不出。  
禁止 LLM 选站。图：`chart_type: dual_axis`（§8）。

### 7.3 设备占位

`station_ops` / `device_alert`：`static` 或 `llm_section` 但 `source_item_ids=["q_ops_placeholder"]`，`narrative_instruction` 强制输出「本期设备运行/告警数据待接入，以下为模版骨架」。  
柱图/表：`placeholder` 行 0，仍推 `table_payload`/`chart_payload`（空 data + `placeholder: true` + 表头：序号、标编号、设备类型、位置、实时值、告警内容）。  
脚注①②③写入 cover 或该章 `static` 附录，便于接数。接数前 **禁止** 用有数天数近似三率。

### 7.4 地图占位

`city_plain` 的 chart：`chart_type: map_placeholder`。payload：`{ title, stations: [{project_name, lon, lat, delta_mm}] }`。lon/lat 来自 `t_station`（可在 `q_layer0` python 里 JOIN 已取的 area 时顺带查；若 endpoints SQL 已 LEFT JOIN，可 SELECT lon,lat）。前端无地图组件时当空态。禁止把占位当热力图假数据。

### 7.5 封面 static

短封面（日周月）：内部材料 / 标题 / 第 {issue_no} 期 / 单位 / {report_date}。  
季报+年报：标题 + （{period_label}）+ 目录可用 `static` 按展开后章节 title 生成 TOC 行（页码可用 `—`）。

## 8. 表图渲染扩展

`charts_extra.chart_from_config` / `configured_viz.render_configured_chart`：

| chart_type | spec |
|------------|------|
| `bar` / `line` / `pie` | 现网 |
| `dual_axis` | `xField`, `yLeft` `{field,name,unit}`, `yRight` `{field,name,unit}`, `series[]` |
| `map_placeholder` | 见 §7.4，不走数值自动探测 |

`render_configured_table`：支持 `row_filter: { field, equals }`（循环章用）。`max_rows` 附表 1 至少 42，附表层组至少 42；空行站点仍可输出站名 + 空数值（缺层），或省略该站——**与季报一致：缺层站在该附表可不出现或格空**。实现选：**该层组无 compress 行则不出现在该附表**（F11 不出现在附表 4/5）。

附表 1：`q_layer0`，按 `area` 分组展示（程序可输出长表：区、地点/project_name、delta_mm），不必一次还原 Word 双栏排版。

## 15. 风险

| 风险 | 处理 |
|------|------|
| `project_name` 与 `t_station.name` 括号全角不一致 | JOIN 以字典 `project_name` 为准；对不齐的站 endpoints 无 area 时仍出站名，area 空 |
| 确定性 SQL 超时 | 只查边界标+时间窗；命令超时沿用 `NL2SQL_DB_COMMAND_TIMEOUT_SEC` |
| 循环 8+4 章拉长 LLM | 叙述短 outline；附表 static；并行合成仍默认关 |
| 前端未识别 `dual_axis` | payload 带左右序列，前端可先降级为两张 line |
| 把 V2 理解成「不用 NL2SQL 基座」 | 执行器必须用；生成器只用于非附表叙述（本方案地降数字以确定性项为准，叙述项尽量不再 nl2sql 取数） |

---
