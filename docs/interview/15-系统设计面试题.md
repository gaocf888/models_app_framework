# 15 · 系统设计面试题

> 白板题按「澄清 → 指标 → 架构 → 深挖 → 风险」答。每题给参考骨架，面试时用自己的项目细节填肉。

通用开场（30 秒）：

1. 用户是谁、查询类型、数据形态  
2. SLO：首字时延、正确率、并发  
3. 约束：内网、国产卡、权限、是否可微调  

---

## 题 1：企业知识库问答（RAG）

**题面**：10 万份制度/报告，多部门权限，要可引用、可更新。

**澄清**：格式（PDF/扫描）、多租户、是否多跳、是否要图。

**指标**：Recall@k、忠实度、P95 TTFT、权限零泄漏。

**架构**：

```text
接入(鉴权) → 指代/改写 → 权限过滤检索(向量+BM25+元数据)
→ RRF → 重排 → 拼引用 Prompt → 流式 LLM → 点踩/trace
摄入：解析→清洗→切块→质量门→按 ACL 写入
```

**深挖**：

- 更新：文档版本、按 doc_id 删重建  
- 扫描件：OCR/版面  
- 热点：query 缓存（绑权限与索引版本）  
- 降级：重排超时则仅 RRF；检索空则拒答  

**本项目映射**：8 步摄入、三路召回、namespace、TEI、LangGraph 客服 kb_qa。

## 题 2：智能客服（工业现场）

**题面**：问规程、问运行数据、多轮「这个再看看昨天」。

**关键设计**：

- 意图：规则 + 小模型，慎用每轮大模型分类  
- 路由：`kb_qa` / `data_query` / `clarify`  
- 状态：当前设备、时间窗显式保存  
- 指代消解后再检索/SQL  
- SSE + 停止生成  
- 低置信澄清，不编数据  

**深挖**：值班高峰排队、知识未入库、SQL 慢查询。

**本项目映射**：客服图、NL2SQL 内嵌、对话锚点、历史预算。

---

## 题 3：NL2SQL / ChatBI

**题面**：业务人员自然语言查数，库表 200+。

**必须主动提**：只读账号、AST 校验、表白名单、LIMIT、审计。

**流水线**：时间规范化 → Schema Linking → 口径/金样例 RAG → 生成 → 校验 → 执行 → 一次修正 → 解释（只基于结果）。

**深挖**：

- 相对时间缓存键带业务日  
- 大结果：聚合下推，不把百万行回灌模型  
- 同义口径：业务词典版本化  

---

## 题 4：高并发推理平台

**题面**：多应用共享模型，QPS 高、上下文长短不一。

**架构**：网关限流 → 编排集群（无权重）→ vLLM/厂商推理池（按模型分副本）→ 独立 embedding。

**深挖**：

- 长短隔离：长报告单独队列，避免饿死短问答  
- KV 打满：抢占、降 max_tokens、拒收  
- 多 LoRA：基座共享 + 适配器热加载  
- 观测：TTFT/TPOT/排队/KV 使用率  
- 国产：兼容 API，副本按卡型标签调度  

**本项目映射**：VLLMHttpClient、动态 max_tokens、训练推理分离。

---

## 题 5：领域模型微调平台

**题面**：业务要「更像我们的专家」。

**先挑战需求**：是风格问题还是知识问题？知识走 RAG。

**闭环**：标注（LabelStudio）→ 校验 → 配比 → LoRA → 自动评测 → 人工抽检 → merge → 灰度端点 → 回滚。

**深挖**：数据泄漏、遗忘、VLM 显存、多业务多 adapter。

**本项目映射**：`app/train/llm/`、JSONL、Web 启停、adapter 产物。

---

## 题 6：看图诊断 / 多模态质检

**题面**：现场照片 + 问「是否超标、怎么处理」。

**架构**：上传压缩 → 存对象存储 → 并行：检测小模型 / VLM 描述 / 查历史数据 / 查规程 → 交叉校验 → HITL 缺槽追问 → 报告。

**深挖**：无 GPS 图、光线差、模型看到但测点不支持 → 必须降级为「仅视觉意见」。

---

## 题 7：Agent 做运维助手

**题面**：查日志、查指标、建议工单。

**安全红线**：只读工具默认；写操作二次确认；每步审计；max_steps；生产变更窗口。

**设计**：Graph 固定「诊断剧本」，节点内 tool-calling 只在只读探测集。不要一上来 ReAct 连 SSH。

---

## 题 8：评测与迭代体系

**题面**：线上已经有 RAG，感觉还行，如何科学迭代。

**答**：建分层金标（检索/生成/业务）→ 周更坏例 → Prompt/模型/索引三因子一次只变一个 → A/B → 裁判+10% 人工。没有金标就先每周 50 条双人标。

## 答题时间分配（45 分钟题）

| 分钟 | 做什么 |
|------|--------|
| 0–5 | 澄清范围与 SLO |
| 5–15 | 画组件图、数据流 |
| 15–30 | 深挖面试官点的层（检索/安全/并发） |
| 30–40 | 失败、降级、观测 |
| 40–45 | 演进（评测、微调、多租户） |

## 万能降级清单（每题结尾用）

1. 检索空 / 低分 → 澄清或拒答  
2. LLM 超时 → 重试一次或返回已有证据  
3. SQL 失败 → 展示改写后的规范问句，请用户确认范围  
4. 推理过载 → 429 + 缩短上下文模式  
5. 权限不足 → 与「没有知识」区分错误码，避免暗示存在该文档  

能讲降级，比堆模型名字更像能上生产的人。

## 题 9：多模型网关与成本治理

**题面**：公司 20 个应用都直连不同厂商 API，账单失控、无法灰度。

**架构**：统一网关（鉴权、配额、虚拟模型名）→ 路由（简单/复杂/敏感）→ 语义缓存 + 前缀缓存 → 观测（按应用/模型/token）。

**深挖**：重试放大账单、推理模型思维 token、缓存跨租户泄漏。参考 [17](./17-模型生态与选型.md)、[24](./24-成本网关缓存与产品化.md)。

---

## 题 10：仓库级代码 Agent

**题面**：根据 issue 改代码并过测试。

**架构**：检索（BM25+向量+符号）定位文件 → 规划补丁 → 沙箱跑测 → 失败日志回灌 → 限制步数与可改路径。评测对标 SWE-bench 思路。安全：无生产密钥、网络白名单。

---

## 题 11：长文档 / 记忆型助手

**题面**：跨月对话要记住用户偏好，并能精读上百页合同。

**架构**：合同走解析+检索+必要时长窗精读；偏好走结构化记忆（可删除）；摘要只作导航。不把全部历史塞 1M 窗口。见 [18](./18-长上下文记忆与测试时计算.md)。

---

## 题 12：安全合规评审

**题面**：给金融 RAG 做威胁建模。

**必答**：间接注入、ACL 检索时过滤、日志脱敏、写操作禁用、红队回归、供应商数据出境。见 [20](./20-安全红队与合规.md)。
