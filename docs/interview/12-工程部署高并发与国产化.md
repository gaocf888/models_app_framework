# 12 · 工程部署、高并发与国产化

> 面试定位：应用/平台岗第二战场。能讲清进程边界、背压、安全、国产卡差异。  
> 预计：45 分钟。  
> 本项目锚点：FastAPI 异步；vLLM 独立部署；Redis 会话；Prometheus；昇腾 Atlas / 寒武纪离线镜像；训练与推理解耦。

---

## 0. 30 秒能讲清楚

生产上把系统拆成 **接入编排进程** 和 **模型推理进程**。接入层做鉴权、限流、会话、RAG、SSE；推理层做 batch 与 KV。高并发靠 **异步 IO + 连接复用 + 有界队列背压 + 推理引擎持续批处理**。国产化则是换运行时与镜像，业务尽量停在 OpenAI 兼容 API。

---

## 1. 推荐进程划分

```text
[网关/FastAPI] [RAG 嵌入/重排 TEI] [vLLM/厂商推理]
[EasySearch] [Redis] [业务 DB] [Neo4j 可选] [MinIO]
[训练 Job 独立，不与在线混部]
```

原则：

- 重模型不进 API worker 内存（嵌入也曾进程内单例化，生产更倾向独立 TEI）  
- 训练 Job 单独调度，产出 adapter 再挂推理  
- 配置中心化（环境变量 / `app/core/config.py`）

## 2. 高并发要点

### 2.1 接入层

- FastAPI + uvicorn workers；CPU 密集（分词、重排本地）要独立出去  
- `httpx.AsyncClient` **进程内复用**  
- 不在 async 里跑阻塞推理；必须用线程池也要限并发  
- 限流：按 API Key / 租户令牌桶  
- 超时：连接、读、总时长分层  

### 2.2 背压

推理满了怎么办：

1. 网关排队（有界，满则 429）  
2. 降级：关二次检索、缩短历史、切小模型  
3. 拒绝并返回重试建议  

不要无限 goroutine/task 把机器打满。

### 2.3 会话与缓存

- Redis：热会话、分布式锁、幂等 key  
- 并发写同一 session：按 session 串行或乐观版本  
- RAG/SQL 缓存带版本与权限  

### 2.4 小模型视频通道

全局短锁管映射，通道内锁管启停；有界队列；停用事件。详见架构方案。面试用来证明「你懂线程安全，不只会调 LLM」。

## 3. 流式与取消

- SSE：`started(stream_id)` / `delta` / `finished(meta)`  
- 客户端断开：尽量 cancel 下游 HTTP  
- 代理缓冲会毁掉流式，要注意 nginx `X-Accel-Buffering`

## 6. 国产算力（昇腾 / 寒武纪等）

面试稳定答法：

1. **算子与框架**：PyTorch 生态在 CUDA 最熟；NPU 靠厂商插件/图编译，个别算子需改写或降级  
2. **推理栈**：可能是 vLLM 适配版、Triton、MindIE 等，**以厂商镜像为准**  
3. **量化与精度**：FP16/BF16 支持不同；INT8 工具链不同  
4. **运维**：驱动、固件、容器 runtime（如 ascend-docker）版本要锁  
5. **业务解耦**：应用只打 HTTP，模型侧换卡不改编排  

离线：在有网机器下好 wheel，内网按厂商 base 镜像「再烤一层依赖」，本项目 `vllm-deploy` 离线文档就是这个故事。

不要贬低国产卡，讲 **适配成本与验证集**。

## 6.1 行业补充：云原生与多云

| 主题 | 要点 |
|------|------|
| K8s | 推理用 GPU device plugin；HPA 看队列深度不只是 CPU |

## 8. 高频问答

**Q：应用和 vLLM 为什么要拆开？**  
A：扩缩倍数不同、崩溃域隔离、依赖冲突（训练/torch vs 轻 API）、便于换国产运行时。

**Q：多 worker 会加载多次模型吗？**  
A：若把模型放进 FastAPI 会。所以模型放独立服务，worker 只打 HTTP。

**Q：如何保证线程安全？**  
A：无共享可变 Chain；Redis 注意并发；小模型通道分级锁；不在多线程共享 HTTP 客户端的错误用法（按官方线程安全说明复用）。

**Q：GPU 利用率低？**  
A：batch 不够、序列长度差异大、预填充饿死、CPU 预处理跟不上、同步调用。
