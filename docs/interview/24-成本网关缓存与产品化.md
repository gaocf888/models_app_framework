# 24 · 成本、网关、缓存与产品化

> 面试定位：负责人/全栈/平台岗。能算 token 账、设计网关、做语义缓存，而不只会调模型。  
> 预计：35 分钟。

---

## 0. 30 秒能讲清楚

线上费用 = **模型单价 ×（输入+输出+思维 token）× 调用次数 × 重试**，再加上 GPU 固定成本。优化顺序通常是：少调用、少 token、能缓存则缓存、简单题走小模型、难的再升级。网关负责鉴权、配额、路由、降级和统一协议。

---

## 1. 成本模型

| 项 | 注意 |
|----|------|
| 输入 vs 输出单价 | 输出常更贵；推理模型思维也算输出 |
| 缓存命中折扣 | 部分云厂商对长前缀缓存打折 |
| 失败重试 | 超时重试会双倍账单 |
| RAG | 嵌入批次便宜，重排和多次改写不便宜 |
| Agent | 步数是乘数，上限要硬编码 |
| GPU | 利用率低于 30% 时自建不一定省 |

口述公式：

\[
\mathrm{Cost} \approx N_{\mathrm{req}} \times (C_{\mathrm{in}}T_{\mathrm{in}} + C_{\mathrm{out}}T_{\mathrm{out}}) \times \mathbb{E}[\mathrm{retries}\cdot\mathrm{steps}]
\]

自建 vs API：日均 token 稳定且高、要不出域 → 自建；波动大、要最强模型 → API 或混合。

---

## 2. 省钱顺序（比换更便宜模型更先做）

1. **业务少打模型**：规则/BERT 做意图；命中 FAQ 直接回  
2. **减输入**：裁历史、少 chunk、表格转摘要  
3. **减输出**：限 max_tokens、不要无谓 CoT  
4. **缓存**：完全相同请求、语义相似、前缀 KV  
5. **路由**：小模型默认，置信低再大模型（cascade）  
6. **批处理**：离线报告走异步队列  
7. **量化/投机解码**：同模型降 GPU  
8. **最后才砍能力档**  

---

## 3. LLM 网关（行业组件）

职责：

- 统一 OpenAI 兼容入口  
- API Key、租户配额、预算熔断  
- 模型路由与灰度（5% 流量新模型）  
- 超时、重试（幂等才重试）、断路器  
- 日志脱敏、trace_id  
- 虚拟模型名（`chat-smart` → 真实后端）  

代表思路：LiteLLM、自研网关、云厂商 AI Gateway。面试讲清「为什么要这一层」，不必绑产品名。

---

## 4. 缓存层次

| 层 | 键 | 适用 |
|----|----|------|
| 精确缓存 | 规范化后的 prompt+参数哈希 | 完全重复 |
| 语义缓存 | 问句 embedding 近邻 | FAQ、内部重复问 |
| 前缀/KV 缓存 | 系统提示+模板 | 多请求共享前缀 |
| 检索缓存 | query+index_version+acl | RAG 召回 |
| SQL 缓存 | 规范化问句+schema 版本+业务日 | NL2SQL |

语义缓存陷阱：

- 「苹果股价」和「苹果食谱」可能被误命中 → 阈值要严，且按意图分桶  
- 必须带 **权限** 和 **知识版本**  
- 时效问题（股价、天气）要 TTL 或禁缓存

## 5. 产品化清单（应用岗加分）

- 流式 + 可停止  
- 引用可点开原文  
- 空结果与错误的人话提示  
- 建议追问  
- 反馈（点踩）进飞轮  
- 会话列表与标题  
- 配额用尽时的体验  
- 功能开关：关 Agent、关推理模型  
- 评测与灰度发布  

技术做完但没有反馈闭环，面试官会认为你只做了 Demo。

---

## 6. 高频问答

**Q：语义缓存安全吗？**  
A：阈值+分桶+ACL+TTL。开放域问答慎用；内部 FAQ 合适。

**Q：为什么加了网关还变慢？**  
A：多一跳、同步日志、重复鉴权。网关要异步埋点、连接复用。

**Q：如何向财务解释 GPU？**  
A：给利用率、每百万 token 成本和 API 对照，以及数据不出域的溢价。

---

## 7. 速记口诀

> **先减次数和 token，再缓存和路由，最后换模。**  
> **网关管配额与灰度；缓存必须带权限和版本。**
