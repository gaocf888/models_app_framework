# 18 · 长上下文、记忆与测试时计算

> 面试定位：2024 后高频。能讲清「窗口变长 ≠ 真会用」，以及 o1/R1 用测试时算力换正确率。  
> 预计：45 分钟。  
> 行业面：Needle-in-a-Haystack、Lost in the Middle、记忆系统、Test-Time Compute。

---

## 0. 30 秒能讲清楚

上下文窗口是模型一次能看见的 token 上限。训练外推（YaRN 等）能把 8K 拉到 128K，但 **中间段落最容易被忽略**，费用和 TTFT 随长度涨。超长知识仍优先 RAG/记忆索引，而不是整库塞进窗口。推理模型则把算力花在 **生成更长思维链或多次采样**，用测试时计算换难题正确率。

---

## 1. 长上下文：训练侧 vs 应用侧

| 手段 | 做什么 | 局限 |
|------|--------|------|
| 位置插值 / NTK / YaRN | 改 RoPE 频率，外推位置 | 外推≠理解质量 |
| 长文继续预训练 | 在长文档上再训 | 贵 |
| 窗口注意力 / 稀疏注意力 | 降 \(O(n^2)\) | 远距离依赖弱 |
| SSM / Mamba 等 | 线性复杂度序列建模 | 生态与指令能力仍不如主流 Transformer |
| Dual Chunk / 分段注意力 | 工程折中 | 实现各异 |
| RAG / 分层摘要 | 应用侧减输入 | 需要索引 |

**Needle-in-a-Haystack**：把一句话埋进超长干扰文本，看能否找回。过榜 ≠ 能做多跳推理或「整本书论证」。

**Lost in the Middle**：U 形利用率，头尾记得更好。所以关键约束、最终问题、最相关证据应靠近两端或重复一次。

---

## 2. 什么时候不该上超长窗口

- 知识经常更新 → RAG  
- 多文档各看一段 → 先检索再读  
- 多轮客服 → 摘要 + 状态槽，不要无限拼历史  
- 代码仓库 → 检索符号/文件，而不是 200 文件全塞（除非仓库级 Agent 有索引）

「模型宣传 1M context」的正确用法：一次读一份长合同或长日志的 **已筛选片段集合**，不是放弃检索。

## 3. 记忆系统（Memory）行业方案

比「Redis 存最近 20 轮」更完整的分层：

| 层 | 内容 | 实现 |
|----|------|------|
| 工作记忆 | 当前任务 state、槽位 | 图状态 / session |
| 情节记忆 | 近期对话原文 | 热存储 + 过期 |
| 语义记忆 | 用户偏好、实体事实 | 向量 + KV 表 |
| 摘要记忆 | 旧对话压缩 | 定期 LLM 摘要，防漂移要可回源 |
| 程序性记忆 | 工具用法、SOP | Prompt / 技能文档 |

常被点名的思路（知道即可）：

- **MemGPT / 操作系统式记忆**：上下文当 RAM，外存分页，模型决定读哪页  
- **Memory Bank / 长期画像**：按用户写文件或库  
- **Graph Memory**：实体关系比纯向量更稳（人-项目-设备）  
- **反思 Reflection**：对话后写记忆，读时再检索  

风险：错误记忆会自我强化；要版本、可删除（被遗忘权）、与权限绑定。

## 4. 测试时计算（Test-Time Compute）

训练时算力 vs 推理时算力。推理模型把后者做大：

| 策略 | 做法 | 代价 |
|------|------|------|
| 更长 CoT | 强制分步 | 输出 token 暴涨 |
| Self-Consistency | 多样本投票 | N 倍费用 |
| ToT / 搜索 | 树搜索+剪枝 | 更贵，难上线 |
| 过程奖励引导搜索 | 逐步打分 | 要 PRM |
| Best-of-N | 采样 N 条用 RM 挑 | 经典且有效 |
| 工具+验证 | 代码跑测试、计算器 | 高性价比 |

金句：

> 对可验证任务（代码单测、数学最终数），测试时计算 ROI 高；对开放客服，多采样常常只是更贵的同义反复。

应用侧注意：

- 流式时先藏 thinking 再出 answer（产品体验）  
- 网关要限制「思维 token」上限，防账单爆炸  
- 简单题走快模型，难的再 escalate（级联）

---

## 5. 和 RAG / Agent 的关系

```text
短问答     → 普通 Chat + 小上下文
知识问答   → RAG（不必 128K）
长文档精读 → 检索定位页 + 中长窗口精读
难题推理   → 推理模型 / Best-of-N / 工具验证
跨会话个性 → 记忆系统，而不是无限上下文
```

## 6. 高频问答

**Q：128K 模型还要 RAG 吗？**  
A：要。窗口解决「一次能看见多少」，RAG 解决「该看见什么」。长窗贵、中间丢失、权限过滤都在。

**Q：摘要记忆会不会丢关键数字？**  
A：会。对金额、时间、设备编号应结构化提取进槽位/KV，摘要只保留叙事。

**Q：o1 和普通模型差在训练还是推理？**  
A：两边都有。训练用 RL + 可验证奖励；推理允许很长思维和更多 token。产品上是「更慢更贵但难题更准」。

**Q：Self-Consistency 怎么投？**  
A：对有唯一答案的题，多样温度采样后取众数；开放文本不好投，改用裁判模型或规则。

> **测时算力只砸在可验证的难题上。**
