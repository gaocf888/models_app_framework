# 22 · 嵌入、向量库与检索引擎（行业横向）

> 面试定位：RAG 之外把 **表示学习 + 存储引擎** 讲完整。不绑定 EasySearch。  
> 预计：45 分钟。  
> 与 [07](./07-RAG检索增强生成.md) 分工：07 讲 RAG 全链路与排障，本篇讲嵌入原理、ANN、引擎选型。

---

## 0. 30 秒能讲清楚

嵌入把文本（图/音频）映射到向量，使「语义相近」在几何上接近。检索是在高维空间做 **近似最近邻（ANN）**，再常与 BM25、过滤、重排组合。引擎之争是 **向量 + 全文 + 元数据 + 运维** 的组合题，不是谁的 QPS 数字最大。

---

## 1. 嵌入模型原理（面试深度）

| 结构 | 说明 |
|------|------|
| 双塔 Bi-Encoder | query/doc 分别编码，点积/余弦；可预计算 doc |
| 交叉编码器 | 拼接后打分，准但贵，只能重排 |
| 晚交互 ColBERT | doc 存 token 级向量，查询时 MaxSim；准且可比双塔贵一点 |
| 指令式 embedding | query 带「为检索生成表示：」；doc 通常不带 |
| 多向量 / 稀疏 | SPLADE 等可学习稀疏，利于词法 |

训练目标：对比学习（InfoNCE）、难负例、蒸馏重排教师、领域微调（不要先全网乱训）。

**各向异性**：若向量挤在窄锥里，余弦区分度差。专用 embedding 会做归一化与对比目标缓解。所以不用 Chat LLM 当向量。

维度：768/1024 常见。更高维不一定更好，存储和 ANN 变贵。MTEB 只参考。

中英混合、短标题、超长段落：要分别评。短文本可加标题拼接；超长要先切。

---

## 2. 距离与归一化

- **余弦** = 归一化后的点积。生产常 **写入前 L2 normalize**，检索用点积。  
- **L2 欧氏**：未归一时语义不等价于余弦。  
- **点积（IP）**：未归一会偏向模长大的向量（往往更长文档）。  

面试追问「为什么检索全是长文档」：先查是否没归一化。

---

## 3. ANN 索引（平台岗加分）

精确 kNN 在百万级不可行。近似：

| 算法 | 要点 | 特点 |
|------|------|------|
| IVF | 先聚类再搜部分桶 | 省，召回看 nprobe |
| HNSW | 多层图贪心 | 高召回、吃内存、构建慢 |
| PQ / OPQ | 乘积量化压缩向量 | 省内存，精度掉 |
| DiskANN / 磁盘图 | 十亿级 | 延迟看盘 |
| GPU IVF-PQ | 高 QPS | 成本 |

参数权衡：**召回 vs 延迟 vs 内存**。上线要画召回-延迟曲线，不要只报 QPS。

过滤（metadata）是痛点：先滤后搜 vs 先搜后滤。高选择度过滤用「过滤感知索引」或倒排+向量混合。

## 4. 向量库 / 搜素引擎横向

| 产品 | 强项 | 弱项 / 注意 |
|------|------|-------------|
| FAISS | 算法库，研究/单机 | 无分布式业务、无全文 |
| Milvus / Zilliz | 向量原生、规模 | 全文要外挂或新版本能力 |
| Qdrant | 过滤、Rust、payload | 生态相对年轻 |
| Weaviate | 模块化、混合 | 资源占用 |
| pgvector | 事务、和业务库一体 | 超大规模 ANN 弱 |
| Elastic / OpenSearch | 全文+向量+过滤一体 | 向量极致性能不如专用库 |
| Vespa | 大规模推荐/搜索 | 运维重 |
| Chroma / LanceDB | 本地原型 | 生产要评估 HA |

选型口诀：

- 已有 ES 团队 + 必须 BM25 → ES/OpenSearch  
- 纯向量十亿级 → Milvus/DiskANN 路线  
- 强事务、百万级 → pgvector 先够  
- Demo → FAISS/Chroma，但面试要说清迁移路径

## 5. 混合检索的行业做法（不绑 RRF 一家）

| 融合 | 说明 |
|------|------|
| RRF | 不需校准分数，稳 |
| 加权分 | 要 min-max / 正态化，否则一路吞另一路 |
| 两阶段 | 词法召回再向量，或相反 |
| 学习排序 LTR | 有点击日志时上限高 |
| ColBERT 晚交互 | 质量好，存储大 |

稀疏+稠密已被论文和工业反复验证，面试说「只上向量」会被怼。

## 6. 嵌入服务化

- 独立进程（TEI、Infinity、自研 FastAPI + 单例）  
- 动态 batch、长度分桶  
- 与生成扩缩比不同（嵌入 QPS 远高于 Chat）  
- 版本：`model_id + dim + normalize + instruction` 进索引指纹，换模必须重建

## 7. 高频问答

**Q：余弦和点积何时等价？**  
A：向量都 L2 归一化时。

**Q：HNSW 构建很慢怎么办？**  
A：离线构建、增量小图、或 IVF 换吞吐；不要每条文档同步重建大图。

**Q：过滤条件很严，召回变 0？**  
A：预过滤把候选杀光。应复合索引或放宽后再用业务规则。

**Q：ColBERT 为什么香又少用？**  
A：token 级向量存储和算力高；中小库、高质量搜索值得，海量客服 FAQ 双塔+重排更常见。

**Q：换 embedding 模型要注意？**  
A：全量重嵌入；维度/度量变了索引要重建；A/B 用同一金标 Recall。
