# 04 · 量化与模型压缩

> 面试定位：能讲「精度位数怎么换吞吐/显存」，分清训练量化 vs 推理量化。  
> 预计：40~50 分钟。  
> 本项目锚点：在线默认对接 vLLM（可用 AWQ/GPTQ/FP8 等引擎能力）；应用进程不在 Python 里做权重量化。

---

## 0. 30 秒能讲清楚

量化把权重量成更少 bit（FP16→INT8/INT4/FP8），用 **校准或训练** 把误差压住，换显存和带宽。压缩还包括蒸馏、剪枝、低秩。企业推理最常见：**PTQ（GPTQ/AWQ）+ KV Cache 量化**；QLoRA 是训练技巧。

---

## 1. 精度与误差从哪来

浮点：\(x \approx s \cdot q + z\)（scale + 零点）。  
误差来源：

- **量化噪声**：分布长尾、outlier（个别通道特别大）  
- **累加误差**：深层网络逐层放大  
- **敏感层**：开头/结尾、部分 Attention 层往往不能「一刀切 4bit」

所以不是「全部 4bit 一定行」，而是 **逐层敏感度 + 校准数据**。

---

## 2. PTQ vs QAT

| | PTQ 训练后量化 | QAT 量化感知训练 |
|--|----------------|------------------|
| 成本 | 低，几百分钟级校准 | 高，要再训练 |
| 精度 | 7B/14B INT8 通常可接受；INT4 看方法 | 更稳 |
| 企业 | **默认先 PTQ** | 极端压缩或硬件绑定 |

校准：用一小批代表数据跑前向，估每层 scale。校准数据要接近线上分布，否则「官方分数好看、业务掉点」。

---

## 3. 主流推理量化方法

| 方法 | 思路 | 面试关键词 |
|------|------|------------|
| SmoothQuant | 把激活 outlier 平滑到权重 | W8A8，保激活范围 |
| GPTQ | 逐层最小二乘，用 Hessian 补偿 | 权重量化质量高，校准稍慢 |
| AWQ | 保护显著权重，按激活幅度缩放 | 常比朴素 INT4 更稳，vLLM 常用 |
| GGUF / llama.cpp | k-quants（Q4_K_M 等） | 端侧/CPU，不是数据中心主力 |
| bitsandbytes NF4 | 4bit 正态浮点 | QLoRA 训练 |
| FP8（E4M3/E5M2） | 硬件 FP8 张量核 | H100/部分国产新卡，训练+推理都在走 |

**W4A16 vs W4A8 vs W8A8**：W=权重，A=激活。激活量化更难（动态范围）。先 W4A16（权 4、算 16）是稳妥故事。

---

## 4. KV Cache 量化

生成长、并发高时，**KV 往往比权重大**。KV 量化（8bit/4bit）直接涨并发。

权衡：质量敏感任务（SQL、法律引用）先 A/B；客服可更激进。本项目上下文预算本身就在减 KV 增长。

---

## 5. 蒸馏、剪枝、投机（压缩大家族）

| 手段 | 一句话 |
|------|--------|
| 知识蒸馏 | 大模型教小模型（logits / 特征 / 思维链） |
| 结构化剪枝 | 砍头、砍层、砍专家（需恢复训练） |
| 投机解码 | 小模型草稿 + 大模型一次验证，是**加速**不是压权重 |
| 早退 | 简单 token 浅层结束（研究多、生产少） |

应用岗一句话：

> 线上要小模型，优先 **蒸馏出专用小模型** 或 **路由到小模型**；量化是同一模型的「瘦身」，不是换能力档。

本项目大小模型协同：意图可用 BERT/轻量 LLM；检测用 YOLO；生成仍走大模型。

---

## 5.1 行业补充：更多格式与蒸馏

| 名称 | 一句话 |
|------|--------|
| HQQ / Quanto / bitsandbytes | 校准更轻或训练向量化工具 |
| AutoRound / 厂商工具 | 国产或 Intel 等栈上的自动量化 |
| SmoothQuant | 把激活 outlier 乘到权重，利于 W8A8 |
| 权重量化 vs 激活量化 | W4A16 稳；A8/A4 更吃 kernel 与校准 |
| 蒸馏类型 | logits 蒸馏、特征蒸馏、CoT/指令蒸馏、On-policy 蒸馏 |
| 投机草稿模型 | 常由同系列小模型或蒸馏而来，分布要近 |

剪枝：非结构化稀疏在通用 GPU 上不易加速；**结构化剪枝（层/头/专家）** 才好落地，且通常要恢复训练。MoE 可丢低负载专家换吞吐。

## 6. 怎么选（面试答题模板）

1. 卡型和引擎：vLLM 是否支持该量化 checkpoint  
2. 质量底线：有没有业务评测集  
3. 目标：降显存（上更大模型）还是涨吞吐（同模型）  
4. 路径：FP16 基线 → AWQ/GPTQ INT4 或 FP8 → 再考虑 KV 量化  
5. 不在应用容器里现量化，**预量化权重 + 固定镜像**

国产卡：以厂商支持的量化格式为准（Atlas/寒武纪各有图编译与量化工具链），不要假设 NVIDIA 的 AWQ 能直接跑。

---

## 7. 高频问答

**Q：INT8 和 INT4 差在哪？**  
A：INT8 接近 FP16 的情况多；INT4 必须 GPTQ/AWQ 一类方法 + 敏感层保护，否则常识/数学先掉。

**Q：GPTQ 和 AWQ 怎么选？**  
A：都是 INT4 主力。AWQ 往往校准更快、对激活 outlier 友好；GPTQ 优化目标更「层内重建误差」。以 **你引擎官方推荐格式 + 业务评测** 为准。

**Q：量化后首字变慢？**  
A：可能反量化/kernel 不优，或 batch 不够。量化主要省带宽，kernel 不好会更慢。要看具体后端。

**Q：能边训边用 GPTQ 模型吗？**  
A：一般不行。GPTQ 权重面向推理。要继续训用 BF16/QLoRA。

**Q：Per-tensor 和 per-channel？**  
A：scale 的粒度。per-channel（按输出通道）更准、更常用在权重量化。

## 8. 速记口诀

> **位数换带宽；outlier 是敌人。**  
> **先 PTQ 再谈 QAT；KV 量化涨并发。**  
> **训练用 QLoRA，上线用 AWQ/GPTQ/FP8。**
