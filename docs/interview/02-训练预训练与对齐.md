# 02 · 训练、预训练与对齐

> 面试定位：分清「预训练 / 监督微调 / 对齐」三阶段，能讲目标函数和并行。  
> 预计：60~90 分钟。  
> 本项目锚点：在线侧用现成基座模型；训练侧主要做 **SFT/LoRA**，不是从零预训练。

---

## 0. 30 秒能讲清楚

大模型能力分三层炼出来：

1. **预训练（PT）**：海量无标注文本，学「下一个 token」，得到通用基座。  
2. **监督微调（SFT）**：高质量「指令-回答」对，学会听话、格式、领域话术。  
3. **对齐（Alignment）**：用偏好数据（RLHF / DPO / GRPO 等）让输出更安全、更符合人类偏好或可验证奖励。

应用岗要能说清：**业务微调通常停在 SFT/LoRA**；做推理模型/拒答安全才会上对齐。

---

## 1. 预训练

### 1.1 目标

标准 Causal LM：

\[
\mathcal{L} = -\sum_t \log P(x_t \mid x_{<t})
\]

数据：网页、书籍、代码、论文、多语言；现代还会做 **数据配比与清洗**（质量过滤、去重、PII 擦除）。

### 1.2 面试常问的工程点

| 主题 | 要点 |
|------|------|
| 数据质量 > 盲目堆量 | 去重（MinHash/语义）、质量分类器、领域上采样 |
| Token 预算 | 「看了多少 token」比「训练了多少 epoch」更关键 |
| 学习率 | Warmup + cosine / WSD；峰值 lr 与 batch 相关 |
| 稳定性 | 梯度裁剪、loss spike 回滚、混合精度（BF16/FP8） |
| 上下文长度 | 先短后长（curriculum）；RoPE 基频调整 |

### 1.3 分布式并行（算法/平台岗必会）

| 策略 | 切什么 | 适用 |
|------|--------|------|
| DP / DDP | 数据 | 模型能单卡放下 |
| ZeRO-1/2/3 (FSDP) | 优化器/梯度/参数分片 | 大模型单卡放不下但还能「逻辑完整」 |
| TP 张量并行 | 一层内的矩阵 | 单层太大、要降单卡计算 |
| PP 流水线并行 | 按层切卡 | 层数多、通信模式不同 |
| EP 专家并行 | MoE 专家放到不同卡 | MoE 必备 |
| CP 上下文并行 | 序列维切开 | 超长上下文 |

金句：

> 并行不是一种，是 **算力、显存、通信** 的拼图。先看模型是否单卡放得下，再决定 ZeRO 还是 3D 并行。

**通信**：AllReduce（DP 梯度）、AllGather（ZeRO）、AllToAll（MoE）。带宽不够时，增大计算/通信比（更大 micro-batch、梯度累积）。

## 2. 继续预训练（CPT / 领域自适应）

把基座再在 **领域语料**（电力规程、企业文档）上跑因果 LM，不是指令对。

| 对比 | CPT | SFT |
|------|-----|-----|
| 数据 | 领域原文 | 指令-回答 |
| 目的 | 补领域语言模型 / 术语 | 学任务形态 |
| 风险 | 遗忘通用能力 | 过拟合话术、不会「新知识检索」 |

企业里：私有知识常变更 → **优先 RAG**；术语/文风极强且稳定 → 可 CPT + SFT。本项目知识库走 RAG，不靠 CPT 灌全库。

---

## 3. SFT（监督微调）

数据形态：`messages`（system/user/assistant）或多轮。本项目统一 JSONL：`id/modality/task_profile/messages/images/meta`。

要点：

- **只对 assistant 段算 loss**（user/system 做 mask），否则模型学会「复述问题」。
- 数据质量：少而准优于多而脏。1k~10k 精品往往够改风格。
- 多样性：任务配比（闲聊 / 拒答 / 工具 / 领域）避免模式坍缩。
- 与 RAG 叠加：SFT 教「如何引用、如何说不知道」；事实仍来自检索。

过拟合信号：训练 loss 很低，通用基准掉点，只会套模板。

## 4. 对齐家族

### 4.1 RLHF（经典三件套）

1. SFT 模型  
2. **奖励模型 RM**：对同一 prompt 的回答两两比较，学人类偏好  
3. **PPO**：策略模型生成，RM 打分，KL 惩罚防止离 SFT 太远

痛点：PPO 不稳、要在线采样、RM 会 hack（奖励虚高）。

### 4.2 DPO（Direct Preference Optimization）

不用单独 RM + PPO。在偏好对 \((y_w, y_l)\) 上直接优化策略，使其相对参考模型更偏向 \(y_w\)。

直觉损失（面试能写到这种程度即可）：

\[
\mathcal{L}_{\mathrm{DPO}} = -\log \sigma\Big(\beta \big(\log\frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)} - \log\frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}\big)\Big)
\]

\(\beta\) 越大越贴参考模型。chosen/rejected 差距过小或 rejected 太弱，都会学不动。

面试说：

> DPO 把 RLHF 的最优策略闭式解写进分类损失，**离线偏好数据就能训**，工程简单，是很多开源对齐的默认选项。

代价：偏好数据质量决定上限；没有在线探索；可能过拟合偏好对（IPO 等变体在缓解）。

### 4.3 其他缩写（认得即可）

| 方法 | 一句话 |
|------|--------|
| ORPO / KTO | 不必严格成对偏好，实现更省 |
| IPO | 缓解 DPO 过拟合偏好对 |
| Rejection Sampling / RFT | 生成多条，挑高分再 SFT |
| GRPO | 组内相对奖励，无独立 Value 模型，DeepSeek 推理模型常用叙事 |
| Process Reward | 对推理步骤打分，不只看最终答案 |
| RLAIF | 用 AI 当标注员 |
| Constitutional AI | 用原则让模型自批自改，再训，少依赖人类标有害数据 |
| PRM / ORM | 过程奖励 vs 结果奖励；过程更细但标注贵、会错判 |

**推理模型（o1 / R1 路线）**：可验证奖励（数学对错、代码单测）+ RL（常叙事 GRPO）+ **测试时计算**。应用侧区分 thinking 与最终答案，并限制思维 token。展开见 [18](./18-长上下文记忆与测试时计算.md)。数据配比与污染见 [19](./19-数据工程与合成数据.md)。

## 5. 和「应用微调」的边界

| 你在企业最可能做的 | 通常不做的 |
|--------------------|------------|
| 领域 SFT / LoRA | 千卡预训练 |
| 少量偏好 DPO | 完整 PPO 平台 |
| 数据清洗与配比 | 从零训 RM |
| 训完挂 vLLM | 自己实现 Megatron |

面试被问「你们怎么训基座」时诚实说：用开源/商用基座，我们做 **数据与 SFT 闭环**。

## 6. 高频问答

**Q：SFT 和 RLHF 谁更重要？**  
A：没有 SFT，RL 很难起步。格式、工具调用、领域骨架主要靠 SFT；偏好、安全、推理强度靠对齐。数据差时先修 SFT。

**Q：PPO 里 KL 散度干什么？**  
A：限制新策略不要离参考（SFT）太远，防止为刷高奖励而胡言或模式崩坏。

**Q：DPO 还要不要 reference 模型？**  
A：标准 DPO 需要冻结的 ref（常为 SFT），用来形成隐式奖励。有些变体弱化这一点。

**Q：灾难性遗忘怎么缓解？**  
A：混入通用数据、降学习率、LoRA 只改少量参数、经验回放、先 CPT 再轻量 SFT。

**Q：预训练和微调的学习率？**  
A：微调通常小 1~2 个数量级。LoRA 可略大，因为只训适配器。

**Q：什么叫 Reward Hacking？**  
A：策略钻奖励模型空子（超长、谄媚、表面格式正确但内容空），所以要对齐多种奖励 + 人工抽检。
