```text
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
              应用编排层           知识与数据层          工程运维层
           Prompt / Agent         RAG / NL2SQL         部署 / 并发
           MCP / 结构化输出        嵌入 / 向量库         网关 / 成本
           记忆 / 测试时计算       安全 / 评测基准       监控 / 国产卡
```

面试官通常从**三条主线**追问，你要能在任意一条上「往下挖两层」：

| 主线 | 往下挖两层的例子 |
|------|------------------|
| **模型本身** | Transformer → Attention 复杂度 → KV Cache 为什么省算力 |
| **怎么用模型** | RAG → 混合检索 + RRF → 为什么还要 CrossEncoder 重排 |
| **怎么上生产** | vLLM → PagedAttention → 显存碎片和 batch 利用率 |

## 2. 岗位画像：他们在考什么

### 2.1 大模型应用开发（本项目最对口）

**要证明的能力**：能把 LLM 做成**可靠业务系统**，而不是 Demo 聊天。

常问：

- RAG 全链路：切块、召回、融合、重排、引用、幻觉治理（不限某一向量库）
- Agent / MCP / 结构化输出：何时用图，何时自由工具
- Prompt / 长上下文 / 记忆分层 / 多轮指代
- NL2SQL 安全（只读、Schema Linking、自修正）
- 流式、会话、可观测、降级、成本与缓存
- 安全：注入、越权、红队

**加分**：能讲「召回差 vs 生成差」；能离开本项目讲一套行业方案（如 ColBERT、PD 分离、语义缓存）。

### 2.2 LLM 算法 / 微调

**要证明的能力**：懂训练目标、数据、PEFT、评测，不只会点 UI。

常问：SFT vs 对齐、LoRA 秩与 α、灾难遗忘、过拟合、DPO 损失、数据配比。

### 2.3 推理 / 平台工程

**要证明的能力**：吞吐、时延、显存、批处理、量化、国产卡适配。

常问：PagedAttention、Continuous Batching、投机解码、TP/PP、KV Cache 量化。

### 2.4 综合 / 架构

**要证明的能力**：分层、边界、降级、成本、安全、大小模型协同。

常问：为什么 RAG 和 NL2SQL 是两个基座；大小模型为何分开设计、接入层统一。

## 4. 标准口述模板（背下来）

### 4.1 自我介绍（2 分钟，应用开发）

> 我主要做企业级大模型应用。最近一套系统是 **FastAPI 接入 + LangGraph 编排 + vLLM 推理** 的大小模型基座。  
> 应用侧落地了智能客服、综合分析、看图诊断、NL2SQL；知识侧是 **混合检索 RAG**（语义+关键词+metadata，RRF 融合，CrossEncoder 重排），支持 namespace 与 GraphRAG。  
> 模型侧对接 vLLM OpenAI 兼容接口，训练侧有 **LoRA 代码通道**（PEFT + HF Trainer）。  
> 工程上补了会话预算、SSE 流式、Prometheus/LangSmith 观测，以及国产卡离线部署。  
> 我比较关注「检索质量、编排可控、上线可观测」这三件事。

按你真实参与模块删减，**不要报没做过的模块**。

### 4.2 深挖时的答题骨架（STAR + 技术）

1. **场景**：业务要解决什么（客服问数 / 报告分析 / 知识库）  
2. **方案**：选型一句话（LangGraph 而不是单 Prompt；混合检索而不是纯向量）  
3. **关键设计**：2~3 个硬点（SQL 只读校验、chunk 策略、历史裁剪对齐 max-model-len）  
4. **结果 / 权衡**：效果、时延、失败怎么降级  
5. **复盘**：还差什么（评测集、缓存、幻觉引用）

### 4.3 「不会」的安全答法

> 这个我没有在生产里完整落地。原理上是……；如果要做，我会先……（数据/指标/灰度）。我们项目里相近的是……

## 5. 面试官常见追问链（提前演练）

1. 你们 RAG 效果不好，你怎么排查？  
   → 先分「没召回 / 召回了但没用上 / 模型胡编」→ 看 chunk、query、重排分、引用、Prompt。  
2. 为什么上 Agent，不上不行吗？  
   → 多工具、多分支、要状态机才上图；单轮问答不要 Agent。  
3. 微调和 RAG 怎么选？  
   → 知识常变/需引用 → RAG；风格/格式/领域话术稳定 → 微调；常两者叠加。  
4. 推理慢怎么优化？  
   → 输入长度、KV、batch、量化、前缀缓存、投机解码、业务侧少调用。  
5. 国产卡和 NVIDIA 差在哪？  
   → 算子完备度、框架成熟度、量化/图编译、运维镜像；业务要兼容 OpenAI API 降低绑定。

## 6. 建议的「作品集叙事」顺序

用本项目讲故事时，按这条线最顺：

1. 统一推理网关 `/llm/infer`（RAG + 会话可开关）  
2. 客服：意图 → RAG 或 NL2SQL → 流式回复  
3. RAG 基座：摄入 8 步 + 多路召回  
4. 综合分析 / 看图诊断：LangGraph 并行  
5. 训练：LoRA 与推理解耦  
6. 部署：vLLM + 监控 + 国产化
