# 11 · 评测、对齐效果与可观测性

> 面试定位：能建立「离线指标 + 线上观测 + 人工抽检」闭环，而不是感觉调 Prompt。  
> 预计：40 分钟。  
> 本项目锚点：LangSmith 可选埋点；Prometheus/Grafana/Loki；分析执行轨迹；RAG job 状态；训练 metrics/logs API。

---

## 0. 30 秒能讲清楚

大模型系统要分层评： **检索有没有把对的找来、生成有没有用上、业务结果对不对、系统稳不稳定。** 离线用金标集，线上用 trace 和用户反馈。没有评测的 RAG/Agent 无法迭代。

---

## 1. 分层指标

### 1.1 检索

| 指标 | 含义 |
|------|------|
| Recall@k | 金标文档是否出现在前 k |
| MRR / nDCG | 排序质量 |
| Hit@k | 至少一条有用 |

没有金标时：人工点「这几条是否相关」，或用 LLM-as-judge（要抽样校准）。

### 1.2 生成 / RAG 答案

| 指标 | 含义 |
|------|------|
| 忠实度 Faithfulness | 是否能从证据推出 |
| 答案相关性 | 是否在回答问题 |
| 引用率 / 引用正确率 | 编号是否对得上 |
| 拒答正确率 | 不该答时是否拒 |

### 1.3 NL2SQL

执行准确率（结果集）、口径错误率、校验拦截率、空结果澄清率。

### 1.4 Agent

任务成功率、平均步数、工具失败率、超时率、费用/请求。

### 1.5 推理系统

TTFT、TPOT、错误率、排队时长、GPU 显存、抢占次数。见 [05](./05-推理加速与服务化.md)。

### 1.6 传统生成指标

BLEU/ROUGE 适合摘要对照；开放问答意义有限。业务更认 **正确/部分对/错** 三级人工。

---

## 2. 评测集怎么建

- 覆盖：简单 QA、多跳、拒答、注入、指代、时间窗、敏感问题  
- 与线上同分布，定期加「逃逸 case」  
- 版本化，和 prompt_version、模型名一起存  
- 训练集和评测集按文档/日期切分，防泄漏  

**LLM 裁判**：快但不稳。固定裁判模型、低温、量表、抽 10% 人工对齐。

---

## 3. 幻觉治理与「对齐」在应用侧的含义

对齐不仅是 RLHF。应用侧对齐：

- 检索不足则拒答/澄清  
- 输出 schema 校验  
- 安全策略（越权、违规操作）  
- 人机协同  

评测要包含 **应该失败的题**，否则只优化「能侃」。

---

## 4. 可观测性三件套

| 层 | 看什么 | 本项目 |
|----|--------|--------|
| 日志 | 请求、错误、SQL、截断 | Loki |
| 指标 | QPS、时延、GPU、队列 | Prometheus + Grafana |
| 链路 | 每个节点耗时与输入输出 | LangSmith / 自研 trace |

**Trace 最小字段**：trace_id、scene、model、prompt_version、rag_namespace、retrieved_ids、rerank_scores、token_in/out、TTFT、工具调用、最终是否降级。

分析轨迹方案：能回答「这篇报告为什么这么写」——面试很加分。

---

## 5. 从观测反推优化

- TTFT 高 + prompt 长 → 裁历史/少 chunk  
- 召回分高但用户踩 → 生成 Prompt 或证据没用上  
- 召回分低 → 切块/索引/query  
- SQL 校验拦截多 → Schema Linking 或用户超范围  
- Agent 步数多 → 图该写死的还在让模型选  

---

公开基座榜（MMLU、Arena、SWE-bench、MTEB 等）怎么读见 [21](./21-评测基准与行业榜单.md)，不要和本篇的 **业务分层指标** 混为一谈。

可观测再补行业件：OpenTelemetry 统一 trace；Langfuse / Helicone / Phoenix 等与 LangSmith 同类；幻觉检测可用 NLI/ entrail 小模型做线上抽检。

## 6. 高频问答

**Q：没有标注怎么评 RAG？**  
A：先做小规模人工（每周 50 条），同时记用户点踩；再迭代金标。不要只用「看起来通顺」。

**Q：线上如何 A/B Prompt？**  
A：按 user_id 哈希分流，同一指标看板，至少跑过统计功效再定胜负。

**Q：LangSmith 和 Prometheus 谁替代谁？**  
A：不替代。前者看语义链路，后者看资源与 SLO。
