# 21 · 评测基准与行业榜单

> 面试定位：能报出主流榜 **测的是什么、不能说明什么**，并知道业务集更重要。  
> 预计：35 分钟。  
> 与 [11](./11-评测对齐与可观测性.md) 分工：11 讲系统分层指标与观测，本篇讲 **公开基准与怎么读榜**。

---

## 0. 30 秒能讲清楚

公开榜用来 **横向对比基座能力**；业务金标用来 **决定上不上线**。读榜要看：是否泄漏、是否零样本、上下文多长、是否允许工具、裁判是人类还是模型。只背「MMLU 多少」而不说设定，会被追问穿。

---

## 1. 通用能力

| 基准 | 测什么 | 误区 |
|------|--------|------|
| MMLU / MMLU-Pro | 多学科选择题 | 记忆题多，Pro 更难更抗刷 |
| C-Eval / CMMLU / AlignBench | 中文综合 | 中文产品应看这类，不只 Arena 英文 |
| GPQA | 专家级题 | 更接近「真难」 |
| IFEval / IFBench | 指令遵循（格式约束） | 应用岗很加分，很多模型这里掉链 |
| MT-Bench / Arena-Hard | 对话质量 | 裁判偏差、风格讨好 |
| LMSYS Arena Elo | 人类盲选 | 口味≠事实正确；更新快 |

---

## 2. 数学、代码、推理

| 基准 | 测什么 |
|------|--------|
| GSM8K | 小学应用题，已偏饱和 |
| MATH / AIME | 竞赛数学 |
| HumanEval / MBPP | 函数级代码生成 |
| LiveCodeBench | 更新题，抗污染更好 |
| SWE-bench / SWE-bench Verified | 真实仓库修 bug，Agent 岗常问 |
| BigCodeBench | 更复杂库调用 |
| ARC / BBH | 各类推理集 |

推理模型要问：**是否含思维链、是否限时、是否用工具**。同一套 MATH，开/关计算器差很多。

---

## 3. 检索、嵌入、RAG

| 基准 | 测什么 |
|------|--------|
| MTEB / C-MTEB | 嵌入：检索/分类/聚类/STS |
| BEIR | 零样本检索 |
| MIRACL | 多语言检索 |
| CRAG / RGB / MultiHop-RAG | RAG 端到端（忠实度+正确） |
| Needle-in-a-Haystack | 长上下文找回 |

嵌入榜第一 ≠ 你的领域检索第一。必须用 **自家语料抽 200 问** 做 Recall@k。

---

## 4. SQL、Agent、多模态、安全

| 方向 | 基准 |
|------|------|
| Text-to-SQL | Spider、Spider 2.0、BIRD（更贴近脏库和业务口径） |
| Agent 工具 | AgentBench、τ-bench、ToolBench、WebArena、GAIA |
| 浏览器/电脑 | OSWorld、AndroidWorld、Computer Use 内部集 |
| 视觉 | MMBench、MMMU、OCRBench、DocVQA、MathVista |
| 语音 | 看 ASR WER + 指令跟随，别只看 TTS 主观 |
| 安全 | HarmBench、ToxiGen、内部红队集；还要测虚假拒绝 |

NL2SQL 面试：BIRD 强调 **效率与脏值**，比 Spider 更接近企业。

---

## 5. 怎么科学用榜

1. **先定任务再选子集**，不要用 Arena 决定 SQL 模型。  
2. **对齐设定**：shot 数、温度、是否 CoT、是否工具。  
3. **防污染**：优先 Live/Verified/自建。  
4. **统计**：小集要看方差，不要 0.3 分宣布胜利。  
5. **人味**：抽 50 条看失败模式（格式、拒答、幻觉）。  
6. **回归套件**：升模型版本必须跑同一套。  

LLM-as-judge：固定裁判、低温、量表、对金标校准；成对比较比绝对分稳。

---

## 6. 业务评测最小集（任何公司都能做）

- 100 条「必须对」+ 50 条「必须拒」+ 30 条注入  
- RAG：每条带金标 doc_id  
- SQL：带结果集或等价 SQL  
- Agent：成功标准可脚本化（测过、文件在）  
- 延迟：P50/P95 TTFT，和正确率一起看  

---

## 7. 高频问答

**Q：MMLU 高为什么业务还差？**  
A：MMLU 偏知识选择；业务要检索、权限、格式、多轮、工具。对不上任务。

**Q：Arena 第一能上生产吗？**  
A：只能说明聊天偏好。还要看幻觉、安全、价格、延迟、合规。

**Q：SWE-bench 和高 HumanEval 关系？**  
A：HumanEval 是单函数；SWE-bench 要定位文件、改多处、跑测试。Agent 工程能力另算。

**Q：如何向老板解释换模型？**  
A：同一业务金标的正确率/引用率/费用/P95，而不是「新模型榜上高 2 分」。
