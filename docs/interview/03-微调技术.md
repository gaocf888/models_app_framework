# 03 · 微调技术（PEFT / LoRA / 数据闭环）

> 面试定位：能讲清「为什么不全参」、LoRA 公式、秩怎么选、数据和评测怎么闭环。  
> 预计：45~60 分钟。  
> 本项目锚点：`app/train/llm/trainer.py` 的 **Code + LoRA**（PEFT + HF Trainer）；`modality=text|vision`；产物是 adapter，与在线 vLLM 解耦。

---

## 0. 30 秒能讲清楚

全参微调要更新全部权重，显存和遗忘都贵。**LoRA** 认为增量权重是低秩的：冻结 \(W\)，只训 \(BA\)（\(r \ll d\)），推理时可把 \(BA\) 合并回 \(W\)，不增加延迟。企业领域适应默认先 LoRA；显存更紧上 QLoRA（4bit 基座 + LoRA）。

---

## 1. 微调方式对比

| 方法 | 训什么 | 显存 | 效果上限 | 典型场景 |
|------|--------|------|----------|----------|
| Full FT | 全部参数 | 最高 | 通常最高 | 大资源、要大幅改能力 |
| LoRA | 低秩旁路 | 低 | 多数任务够用 | **企业默认** |
| QLoRA | 4bit 基座 + LoRA | 更低 | 接近 LoRA | 单卡 7B~72B 视显存 |
| DoRA | 幅度+方向分解 | 略高于 LoRA | 部分任务更好 | 想榨精度 |
| AdaLoRA | 自适应分配秩 | 中 | 预算固定时更优 | 研究/精细调 |
| Prefix / Prompt Tuning | 前缀或软提示 | 极低 | 上限较低 | 多任务轻量切换 |
| Adapter | 插入小 FFN | 低 | 成熟但推理多一层 | 早期 PEFT |

金句：

> 选微调方法先问三件事：**单卡显存、要改的能力幅度、推理是否允许额外模块。**

---

## 2. LoRA 原理（要能写）

原始更新：\(W' = W + \Delta W\)。  
LoRA：\(\Delta W = BA\)，\(B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k},\ r \ll \min(d,k)\)。

前向：

\[
h = Wx + \frac{\alpha}{r} BAx
\]

| 超参 | 含义 | 经验 |
|------|------|------|
| `r`（rank） | 旁路容量 | 8/16/32 常见；风格/格式小 r，复杂推理/多任务加大 |
| `alpha` | 缩放 | 常设 `alpha ≈ 2r` 或与 r 相等，关键是稳定 \(\alpha/r\) |
| target_modules | 插在哪些矩阵 | 常 `q_proj/v_proj`，要更强再加 `k/o/gate/up/down` |
| dropout | LoRA dropout | 小数据防过拟合 |
| bias | 是否训 bias | 默认不训 |

**合并（merge）**：部署时 `W ← W + (α/r)BA`，变成普通模型，vLLM 当稠密权重加载。本项目产物目录：`outputs/llm_train/{job_id}/adapter`，可合并后再挂推理。

**多适配器**：同一基座挂多个 LoRA（不同业务），服务化可用动态加载；本项目当前更接近「一任务一产物」。

---

## 3. QLoRA 与量化微调

QLoRA：基座 **NF4/4bit** 存储，反向时反量化到 BF16 算 LoRA 梯度；再用 paged optimizer 防峰值 OOM。

对比 GPTQ/AWQ（那是**推理量化**，一般不再训）：QLoRA 是 **训练期量化基座**。详见 [04](./04-量化与模型压缩.md)。

---

## 4. 数据：比算法更决定成败

本项目闭环：

```text
LabelStudio 标注 → 导出转换 → 校验 → YAML + LLMTrainer → adapter
```

统一 JSONL 字段：`id / modality / task_profile / messages / images / meta`。  
内置 profile：`chat_sft`、`vl_ops`、`defect_vl`。

面试要主动讲的数据原则：

1. **只对 assistant 计算 loss**  
2. **先做校验**：空回答、图文缺失、超长、模板不一致  
3. **train/val 按业务切片**，不要随机泄漏同一文档  
4. **配负例**：拒答、检索不足时说不知道，避免幻觉被强化  
5. **和 RAG 对齐**：微调教引用格式，不把会过期的事实写死进权重

数量直觉（口述用，非绝对）：

- 改语气/格式：几百到两三千高质量  
- 领域任务：数千到数万，注意去重  
- 想「灌知识」：优先 RAG，而不是堆 SFT 事实题

## 5. 训练工程要点

| 项 | 建议 |
|----|------|
| 精度 | BF16；消费卡可 FP16 |
| batch | 全局 token batch 比「条数」更有意义；梯度累积凑大 batch |
| 学习率 | LoRA 常用 1e-4~2e-4 量级，全参更小 |
| 调度 | cosine + warmup |
| 序列长 | 覆盖业务分位数，过长浪费；VLM 还要算图像 token |
| 断点 | HF Trainer `save_steps` + resume |
| 评测 | 固定 dev 集 + 业务人工抽检，不要只看 train loss |

**VLM 微调**（本项目 `modality=vision`）：Processor + 图文 collator；图像分辨率/tile 数直接吃显存。看图诊断类任务适合「缺陷描述 + 规范引用」样本，而不是只标类别。

---

## 5.1 行业补充：更多 PEFT 与合并

| 方法 | 一句话 |
|------|--------|
| LoRA+ / rsLoRA | 调整 A/B 学习率或缩放，缓解秩崩 |
| PiSSA / LoRA-FA | 初始化或冻结策略不同，收敛可能更快 |
| IA3 | 用学习到的向量缩放激活，参数更少 |
| BitFit | 只训 bias，极轻 |
| 多 LoRA 路由 | 运行时按任务加载 adapter，不必合并 |
| 模型合并 | TIES/DARE 拼多个已训模型，见 [19](./19-数据工程与合成数据.md) |

全参仍适合：要从基座「换一种能力分布」、有充足数据和算力、且能接受遗忘风险。多数企业领域适应 **LoRA 足够**。

上线形态对比：merge 成整权（运维简单）vs 动态 LoRA（多业务共享基座）。vLLM / SGLang 等支持后者，注意热加载与显存碎片。

## 6. 微调 vs RAG vs 提示词（必考）

| 手段 | 改什么 | 适合 | 不适合 |
|------|--------|------|--------|
| Prompt | 当下行为 | 格式、角色、少样本 | 大量私有知识 |
| RAG | 外挂知识 | 常更新、要引用 | 稳定风格/复杂操作习惯 |
| SFT/LoRA | 权重里的行为 | 格式、术语、工具习惯 | 每天变的制度条文 |

最佳实践：**Prompt 保底 + RAG 供事实 + 轻量 LoRA 定风格/流程**。本项目就是这条组合。

## 7. 高频问答

**Q：r 是不是越大越好？**  
A：不是。r 过大接近全参，过拟合和显存都升。先 r=8/16 看 val，不够再加模块或加 r。

**Q：LoRA 为什么有效？**  
A：过参网络的任务增量往往落在低维子空间（intrinsic dimension 小）。用低秩旁路就能逼近 \(\Delta W\)。

**Q：合并后还能再训吗？**  
A：可以当新基座继续 LoRA；注意多次合并的数值漂移，重要节点留 adapter 备份。

**Q：如何避免训完通用能力崩？**  
A：混通用指令、早停、小 lr、小 r、评测加通用集（不是只看业务 BLEU）。

**Q：LLaMA-Factory 和自己写 Trainer？**  
A：Factory 适合快速实验多配置；自研通道适合与业务数据/权限/UI 集成。本项目 **code 通道为主，Factory 留骨架**。

**Q：训完怎么上线？**  
A：merge 或 vLLM LoRA 模块 → 独立推理服务 → 应用只改 `LLM_DEFAULT_MODEL/ENDPOINT`。训练镜像与推理镜像分离，避免把 PEFT 打进在线包。

---

## 8. 本项目怎么答

> 我们大模型训练在 `app/train/llm/`：Web/API 启动，`LLMTrainer` 走 PEFT LoRA + HF Trainer，支持文本和 VLM。数据从 LabelStudio 转到统一 JSONL，校验后再训。产物是 adapter，和在线 vLLM 进程分离。小模型 YOLO 训练在另一套包，避免依赖打架。

---

## 9. 速记口诀

> **Frozen W + 低秩 BA；r 控容量，α 控步长。**  
> **数据质量 > 秩；知识外挂 RAG，行为再微调。**
