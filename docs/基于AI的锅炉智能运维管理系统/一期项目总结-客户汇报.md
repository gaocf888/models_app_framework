## 一、汇报摘要（开场 1 分钟）

一期已建成一套**可部署、可扩展、可管控**的锅炉智能运维 AI 应用体系，而不是「单一聊天机器人 Demo」。

系统以统一技术基座承载大模型推理、企业知识检索（RAG）与自然语言问数（NL2SQL），并在此之上交付：

1. **智能客服（AI 问答）**：规程/案例问答 + 台账/测点查数，一入口分流；  
2. **综合分析-超温分析**：多源取数，生成超温原因分析与处置建议类结构化报告；  
3. **综合分析-看图诊断-缺陷识别**：现场照片 + 描述 → 缺陷研判、风险等级与处置建议；  
4. **综合分析-看图诊断-泄爆分析**：泄漏/爆管场景溯源分析与防控建议；  
5. **检修报告结构化抽取**：Word/PDF 自动转为可入库缺陷数据；  
6. **生产级配套能力**：流式交互、人机协同确认、只读 SQL 安全边界、会话与监控可运维。

**一期结论建议表述**：平台底座与核心业务应用已具备现场联调与业务试用条件；下一阶段重点是场景深耕、效果度量与生产运维闭环。

## 二、建设背景与一期目标

### 2.1 业务痛点

| 痛点 | 现状影响 |
|------|----------|
| 规程、案例、经验分散 | 查找慢，依赖老师傅口口相传 |
| 台账/测点查询依赖写 SQL 或固定报表 | 临时问数成本高、响应慢 |
| 超温研判依赖人工拼数 | 报告口径不一，响应时效不足 |
| 现场缺陷研判依赖人工对照历史与规程 | 现场到办公室决策链路长 |
| 泄漏/爆管溯源依赖经验拼凑 | 原因分类与防控建议难标准化 |
| 检修报告人工录入 | 效率低、字段不统一、难复用 |

### 2.2 一期建设目标

| 目标维度 | 一期达成标准（摘要） |
|----------|----------------------|
| **统一入口** | 自然语言即可完成「查知识 / 查数据」 |
| **双轮驱动** | 非结构化知识（RAG）+ 结构化数据（NL2SQL）同源复用 |
| **场景落地** | 智能客服、综合分析-超温分析、综合分析-看图诊断-缺陷识别、综合分析-看图诊断-泄爆分析、检修报告抽取可演示可联调 |
| **生产可控** | SQL 只读、知识域隔离、Prompt 版本化、基础可观测（指标与执行摘要） |
| **可复制部署** | 容器化交付，支持 NVIDIA / 昇腾等推理环境适配路径 |

### 4.2 智能客服（AI 问答）— 一期重点入口

**能力说明**

- **意图分流**：自动区分知识问答、结构化查数、需澄清三类路径；  
- **知识问答**：规程、操作、案例等文档经 RAG 召回后作答，降低幻觉；  
- **数据查询（NL2SQL）**：如「查询昨日锅炉超温的测点数据」→ 自动生成只读 SQL → 执行 → Markdown 整理返回；  
- **多轮对话**：支持指代类追问（「它」「刚才那个」等）；  
- **流式交互**：回答边生成边展示；支持中断；  
- **人机协同**：意图边界模糊、查数失败等场景可弹确认/改问/重试。

**典型业务问法**

| 类型 | 示例 |
|------|------|
| 查数据 | 「#2 机组水冷壁最近一次超温发生在什么时候？」 |
| 查知识 | 「锅炉四管泄漏的应急处置流程是什么？」 |
| 多轮追问 | 「它的检修周期是多久？」 |

### 4.3 综合分析-超温分析

**能力说明**

针对锅炉受热面超温事件，按机组、受热面、时间范围等条件，从运行/台账数据库并行取数，结合业务知识，生成结构化超温分析报告（概况、趋势、可能原因、处置建议、运行监护要点等）。

**一期能力要点**

- 分析计划驱动，多任务并行取数，一次请求覆盖多维数据；  
- 分析前可检索相关业务知识与历史案例，丰富研判上下文；  
- 多槽位结构化报告输出，口径相对统一；  
- 取数质量门控：数据不足时降级提示，避免强行编造；  
- 支持流式报告输出；单次执行可带基础执行摘要（节点耗时等字段），便于联调排障。

**典型用法**：输入机组、受热面、时间范围 → 自动取测点与历史超温等相关数据 → 输出结构化超温分析报告。

### 4.4 综合分析-看图诊断-缺陷识别

**能力说明**

面向停机或巡检场景：检修/运行人员上传现场照片，并配合自然语言描述（机组位置、管段、时间等），系统完成视觉缺陷判定、历史数据关联与知识库检索，输出缺陷风险等级与分风险处置方案。

**一期能力要点**

- 三路并行：视觉理解 ‖ 历史/测点取数（NL2SQL）‖ 业务知识检索 → 合成报告；  
- 范围不确定时可人机协同确认（机组/受热面等），降低误判；  
- 覆盖缺陷历史、壁厚、运行工况等多维数据计划；  
- 支持流式报告输出；单次执行可带基础执行摘要，便于联调排障。

**典型用法**：上传受热面管壁裂纹、腐蚀、磨损等现场照片，并描述位置与发现时间 → 输出缺陷类型、风险等级与处置建议。

### 4.5 综合分析-看图诊断-泄爆分析

**能力说明**

面向锅炉受热面泄漏、爆管等事故场景：结合自然语言事故描述与可选现场照片，关联运行数据库与业务知识，进行泄爆溯源分析，输出分类原因分析与防控建议类结构化报告。

**一期能力要点**

- 按设计制造、安装检修、运行操作、燃料品质、外部环境等方向开展溯源分析；  
- 支持直接原因 / 中期原因 / 根因等层次化表述；  
- 可对照事故案例与规程条文，形成可落地的运行防控建议；  
- 支持流式报告输出；单次执行可带基础执行摘要，便于联调排障。

**典型用法**：录入机组、部位、事故时间等描述（可选上传爆口等照片）→ 输出泄爆溯源分析与防控建议。

### 4.6 检修报告解析

- 支持 Word / PDF 等检修报告上传；  
- 自动抽取缺陷位置、类型、壁厚、检测方法等字段；  
- 输出标准化 JSON，便于对接缺陷台账与后续统计分析；  
- 对彩色标注类工业表格具备增强处理能力（提升抽取可用性）。

### 4.7 基座与安全可控能力（一期已具备）

| 能力 | 领导关注点 |
|------|------------|
| **只读 SQL 边界** | 问数链路限制写操作，降低误操作与越权风险 |
| **知识域隔离** | 按业务命名空间分隔规程/案例/问数知识，减少串库串域 |
| **Prompt 版本治理** | 场景提示词集中管理，可迭代可回退 |
| **会话热冷分层** | 近期会话快速读写，历史可归档回查 |
| **API 鉴权** | Service API Key 统一接入，便于与现有系统集成 |
| **可观测** | 应用 Prometheus 指标（`/metrics`）已具备；综合分析单次执行可落基础执行摘要。面向运维的统一「关键节点 Trace」查询/看板体系在本分支尚未作为完整交付，不以一期主成果对外承诺 |

## 五、部署与集成情况

### 5.1 部署形态

一期采用**容器化分栈部署**，主要组件包括：

| 组件 | 作用 |
|------|------|
| 大模型推理服务（vLLM 等） | 文本/多模态生成 |
| EasySearch（向量 + 全文） | 知识库检索与索引 |
| 应用服务（FastAPI） | 智能客服、综合分析-超温分析、综合分析-看图诊断-缺陷识别、综合分析-看图诊断-泄爆分析、问数、抽取等业务 API |
| Redis | 会话、任务与协同状态 |
| 业务数据库 | NL2SQL 只读查询目标（锅炉台账、测点、缺陷等） |
| 对象存储（按需） | 报告/图片等文件 |

支持按现场条件适配 **NVIDIA / 昇腾** 等推理硬件路径，满足国产化与算力多样性要求。

### 5.2 与客户系统的集成方式

- 以上层业务系统（或门户）调用 **REST / SSE 接口** 为主；  
- 统一鉴权后分别接入：智能客服、综合分析-超温分析、综合分析-看图诊断-缺陷识别、综合分析-看图诊断-泄爆分析、检修报告解析等能力；  
- 知识库与业务库按现场数据完成配置与灌库后即可业务试用。

## 八、下一阶段建议（二期方向）
