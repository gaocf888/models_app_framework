## schema：om_result

> 面向使用方：从中间库直接查询运维中心指标数据的第三方。
> 来源、计算口径与平台"运维中心"页面完全一致。

## 二、数据总览（8 张表 = 平台运维中心 11 项指标）

| 表名 | 内容 | 行数规模 |
|---|---|---|
| t_om_data_alarm_summary | 数据告警总览（总仪器数/告警/正常/7 天与 30 天平均） | 固定 1 行 |
| t_om_device_alarm_list | 告警仪器列表（当前有警的仪器） | 几十行量级 |
| t_om_device_online_by_type | 各类仪器在线情况（按仪器类型汇总） | 每类型 1 行 |
| t_om_complete_rate_by_type | 各类仪器数据完整率（按类型汇总，近 4 天窗口） | 每类型 1 行 |
| t_om_effective_rate_by_type | 各类仪器数据有效率（按类型汇总，近 4 天窗口） | 每类型 1 行 |
| t_om_offline_device_list | 离线仪器列表 | 与当前离线设备数一致 |
| t_om_month_complete_list | 仪器数据月完整性列表（近 30 天，**仅含完整率 < 92%** 的设备） | 百行量级 |
| t_om_month_effective_list | 仪器数据月有效性列表（近 30 天，**仅含有效率 < 90%** 的设备） | 百行量级 |

## 三、各表字段说明

通用列（每张表都有）：

| 列 | 含义 |
|---|---|
| snapshot_time | 本批次刷新时间。**同一批数据所有表该列完全相同**；用它判断数据新旧 |

### 1. t_om_data_alarm_summary（数据告警总览，1 行）

| 列 | 含义 |
|---|---|
| total_count | 总仪器数 |
| alarm_count | 当前告警仪器数 |
| normal_count | 正常仪器数（= 总数 − 告警数） |
| week_avg | 近 7 天告警仪器占比（%） |
| month_avg | 近 30 天告警仪器占比（%） |
| snapshot_time | 数据批次(使用日期) |

### 2. t_om_device_alarm_list（告警仪器列表）

| 列 | 含义 |
|---|---|
| id | 平台告警记录号；告警存续期内该值不变，可用作跨批次追踪 |
| device_id | 设备编号 |
| device_name | 标编号（仪器名称） |
| data_type | 告警指标（如：孔隙水压力井_绝对值） |
| source | 传感器名（部分仪器类型有值） |
| type | 仪器类型 |
| area_name | 位置（行政区划） |
| status | 告警状态，本表恒为"有警" |
| ss_value | 实时值（最近一次刷新时解析，个别可能为空） |
| yj_value | 预警阈值描述 |
| content | 告警内容 |
| off_time | 告警起始时间（= 触发数据的采集时间，个别可能为空） |
| create_time | 平台判定告警的时间 |
| snapshot_time | 数据批次(使用日期) |

**持续时间需自行计算**：查询时刻 − off_time（off_time 为空按未知处理）。见第五节。

### 3. t_om_device_online_by_type（各类仪器在线情况）

| 列 | 含义 |
|---|---|
| type | 仪器类型 |
| total | 该类型设备总数 |
| online | 在线数 |
| offline | 离线数 |
| online_rate | 在线率（%） |
| snapshot_time | 数据批次(使用日期) |

### 4. t_om_complete_rate_by_type（各类仪器数据完整率）与 5. t_om_effective_rate_by_type（各类仪器数据有效率）

| 列 | 含义 |
|---|---|
| type | 仪器类型 |
| device_count | 该类型设备数 |
| actual_count | 窗口内实际采集数（按设备小时数计） |
| invalid_count | 无效数据数（仅有效率表有；平台判定为异常值处理的数据） |
| theory_count | 窗口内应采集数（设备数 × 窗口小时数；GNSS 类按天计） |
| rate | 完整率/有效率（%）=（实际 − 无效）÷ 应采 × 100 |
| window_start / window_end | 统计窗口起止日期（T−5 ~ T−2，即不含最近两天的完整 4 天） |
| snapshot_time | 数据批次(使用日期) |

窗口不含最近两天是平台口径设计（保证窗口数据已稳定）。

### 6. t_om_offline_device_list（离线仪器列表）

| 列 | 含义 |
|---|---|
| id | 行标识（仅批次内有效，跨批次请用 device_key + snapshot_time） |
| device_key | 设备编号 |
| name | 标编号 |
| area_name | 位置 |
| sn | 仪器机身号 |
| type | 仪器类型 |
| status | 设备状态原始值（0=离线） |
| create_time | 设备台账建档时间（当前为空，见下方说明） |
| data_collect_time | 最后数据采集时间 |
| snapshot_time | 数据批次(使用日期) |

**离线时长需自行计算**：查询时刻 − data_collect_time。见第五节。
（说明：平台页面"创建时间"列显示的是写死的常量 2025-06-23，不代表任何真实时间；本表 create_time 取自设备台账的建档时间，生产实测当前批次全部为空，请勿依赖该列。）

### 7. t_om_month_complete_list（月完整性列表）与 8. t_om_month_effective_list（月有效性列表）

| 列 | 含义 |
|---|---|
| id | 行标识（仅批次内有效，跨批次请用 device_key + snapshot_time） |
| device_key / name / area_name / sn / type / station_id / project_key | 设备标识与归属信息 |
| data_collect_time | 最后数据采集时间 |
| monitor_count | 窗口内实际采集数 |
| invalid_count | 无效数据数（仅有效性表有） |
| theory_count | 窗口内应采集数（小时计，GNSS 类按天计） |
| complete_rate | 完整率/有效率（%） |
| window_start / window_end | 统计窗口起止日期（约 T−32 ~ T−2，近 30 天，不含最近两天） |
| snapshot_time | 数据批次(使用日期) |

注意：这两张表**只含低于阈值的设备**（完整性 < 92%、有效性 < 90%），与平台页面列表一致；不在此表的设备即为达标设备。

## 四、数据更新节律

- 每小时 **20 分左右**整批刷新一次，8 张表同一时刻一起更新。
- 判断数据新旧：`SELECT max(snapshot_time) FROM t_om_data_alarm_summary;`
- 若 snapshot_time 超过 **2 小时**未更新，说明刷新链路异常，请联系我方。
- 单批次内数据自洽：任一时刻查询看到的都是完整的一批（不会出现几张表新几张表旧）。

## 五、时长类计算（自行计算）

所有时间列均为**北京时间**，格式 `YYYY-MM-DD HH:MM:SS`。

- 告警持续时间 = 查询时刻 − off_time（告警仪器列表；off_time 为空视为未知）
- 离线时长 = 查询时刻 − data_collect_time（离线仪器列表）

示例（PostgreSQL）：

```sql
SELECT device_key,
       name,
       data_collect_time,
       now()::timestamp - data_collect_time::timestamp AS offline_duration
  FROM t_om_offline_device_list
 ORDER BY offline_duration DESC;
```

## 六、常用查询示例

当前各类型在线情况：

```sql
SELECT * FROM t_om_device_online_by_type ORDER BY type;
```

当前告警仪器（按告警时间倒序）：

```sql
SELECT id, device_name, data_type, type, area_name, ss_value, off_time, content
  FROM t_om_device_alarm_list
 ORDER BY off_time DESC NULLS LAST;
```

近 30 天完整率最低的 20 台仪器：

```sql
SELECT name, type, area_name, complete_rate, monitor_count, theory_count
  FROM t_om_month_complete_list
 ORDER BY complete_rate ASC
 LIMIT 20;
```
