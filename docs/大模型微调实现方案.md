# 大模型微调实现方案（基于 Code + LoRA 完善落地）

> **目标**：在本仓库现有「代码训练通道」上，参考 `QwenVL_demo` 的 LabelStudio → 数据转换 → LoRA 微调闭环，落地一套**结构简单、文件尽量少、全 Web UI 可操作**的 LLM / 多模态 VLM LoRA 微调能力。  
> **原则**：遵循 `models_app_framework` 分层；**大模型训练统一落在 `llm` 命名空间**（便于后期与小模型 `yolo`/small-model 训练隔离）；训练与在线推理解耦；默认不影响现网。  
> **参考项目**：`F:\workspace\developer\pythonspace\QwenVL_demo`（`README_TRAINING.md`、原 `run_safety_training.py` / `SafetyTrainer` — 本方案落地时统一更名为 **`run_llm_training.py` / `LLMTrainer`**，代码与配置中**不出现 `safety` 前缀命名**）。

## 0. 结论摘要

| 项 | 说明 |
|----|------|
| 主通道 | **Code + LoRA**（`LLMTrainer` / `LLMTrainingService`）；LLaMA-Factory 通道保留骨架，本方案不强制落地 |
| 命名 | CLI：`run_llm_training.py`；训练器：`LLMTrainer`；包路径一律带 **`llm`** |
| 标注 | **LabelStudio**（独立部署）；本仓库只做「导出转换 + 校验 + 训练」 |
| 模型 | **LLM（纯文本）** + **VLM（图文）**，同一套任务/配置/UI，按 `modality` 分流 |
| 数据 | 参考 QwenVL_demo 图文结构化样本，抽象为**全业务统一 JSONL**（见 §4）；业务场景用 `task_profile`，不用 `safety_*` 类名 |
| 交互 | 数据工具 / 启停训练 / 过程监视 / 结果 → **统一 LLM 训练 Web UI** |
| 现状 | 现有文件仍在 `app/train/*.py`、`train_admin.py`、`models/train.py`；落地时**迁移/重命名**到下文 §5 结构 |

## 4. 全业务统一数据集

### 4.1 设计思路

参考项目样本：`image_path` + 结构化标注 → 拼成 user/assistant。  
本方案：统一 JSONL + **`task_profile`**（业务模板），训练引擎不出现安全专用类名。

### 4.2 统一样本 Schema

```json
{
  "id": "sample_001",
  "modality": "vision",
  "task_profile": "vl_ops",
  "images": ["data/llm_train/images/001.jpg"],
  "messages": [
    {"role": "user", "content": "<image>\n请分析图中作业与风险，并给出措施建议。"},
    {"role": "assistant", "content": "## 特殊作业\n- 高处作业 ...\n## 风险等级\n较大风险\n..."}
  ],
  "meta": {
    "source": "labelstudio",
    "project": "ops-2026",
    "structured": {
      "special_operations": [{"operation_type": "高处作业", "bbox": [100, 200, 150, 280], "description": "..."}],
      "risk_level": "较大风险",
      "risk_points": [{"risk_type": "个人防护缺失", "description": "未佩戴安全帽"}],
      "measures": [{"measure_type": "个人防护", "description": "佩戴安全帽"}]
    }
  }
}
```

纯文本示例：`task_profile=chat_sft`，`modality=text`，`images=[]`。

**约定**：assistant-only loss；VLM 按基座 chat template；`meta.structured` 可选。

### 4.3 内置 `task_profile`（第一期）

| profile | modality | 业务用途 | 说明 |
|---------|----------|----------|------|
| `vl_ops` | vision | 作业/风险/措施类图文（兼容 QwenVL_demo 导出语义） | **替代原 safety 命名** |
| `defect_vl` | vision | 缺陷识别 / 看图诊断 | |
| `chat_sft` | text | 客服/话术等纯文本 SFT | |

### 4.4 从 QwenVL_demo 导出字段的映射

| 原导出字段（仅数据兼容） | 统一格式 |
|--------------------------|----------|
| `image_path` | `images[0]` |
| `safety_analysis.*`（导入时解析） | `meta.structured` + 渲染进 `messages`（转换器内部可读旧字段，**对外 profile 名用 `vl_ops`**） |
| bbox xywh | 保留在 structured；是否写入 assistant 由 profile 开关控制 |

## 6. 训练核心设计（`LLMTrainer`）

### 6.1 职责划分

| 组件 | 职责 |
|------|------|
| `LLMTrainingConfig` | 配置 dataclass / 从 YAML 加载 |
| `LLMTrainingService.start_training(cfg)` | 服务入口（被 Orchestrator / API 调用） |
| `LLMTrainer` | 实际 LoRA 训练（对齐参考项目 Trainer 角色） |
| `run_llm_training.py` | CLI：读 YAML → 校验 → `LLMTrainer.train()` |

### 6.2 配置字段（要点）

`base_model`、`dataset_path`、`output_dir`、`modality`、`task_profile`、`mode=lora`、LoRA 超参、epoch/batch/lr/`max_length`、`resume_from_checkpoint`、`save_steps` / `logging_steps`。  
默认：`configs/llm_train/train_lora.yaml`。

### 6.3 实现要点

1. HF `Trainer` + `TrainingArguments`。  
2. LLM：`AutoModelForCausalLM`；VLM：第一期 Qwen2.5-VL + Processor/collator。  
3. PEFT LoRA；`target_modules` 按模型族预设。  
4. metrics → `outputs/llm_train/{job_id}/metrics.jsonl`。  
5. 失败必须抛错到 Orchestrator（禁止静默成功）。

### 6.4 与 Orchestrator

- job：`log_path`、`metrics_path`、`progress`。  
- 支持 stop flag。  
- 类名：`LLMTrainingOrchestrator` / `LLMTrainingJob`。
