# 智能客服 · 意图识别 HITL 触发测试数据（Hybrid 改造后）

> 对应实现：`should_trigger_intent_hitl` + `hybrid_qa`（场景 B）+ 策略 D 四钮/二次消歧。  
> 产品拍板：**清晰混合不再强制弹 HITL**，改为 Hybrid 直答；HITL 留给 **真模糊**。

---

## 0. 改造前后对照（先看这张表）

| 问法类型 | 改造前 | 改造后（默认 `CHATBOT_INTENT_BACKEND=rules` + 已开 `hybrid_qa`） |
|----------|--------|------------------------------------------------------------------|
| 一句里同时「查数词 + 知识词」且两边都清晰 | **弹意图 HITL**（三钮） | **不弹** → `hybrid_qa` 双臂直答 |
| 纯查数 / 纯知识 | 不弹 | 不弹（不变） |
| 过短 / 指代不清（无足够历史） | 走 `clarify` 话术，**不弹**意图 HITL | 不变 |
| 有历史时的指代续问（`ambiguous_pattern_resolved_by_ctx`） | 可弹 | **仍可弹（真模糊主路径之一）** |
| 低置信 / LLM·BERT 标签与问句冲突 | 可弹 | **仍可弹（真模糊）**；首轮四钮含「综合查数+知识」 |
| 首轮选「我先补充问题」后仍不清 | 二次消歧 HITL | **仍保留**；选项=拆开查数 + 拆开知识 + **可选综合** |

**记一句：**  
旧文档那批「查出…并说明原因/标准/如何预防」= **清晰强混合**，现在用来验 **Hybrid 直答**，不要再当 HITL 用例。

## 1. 前置条件

- `CHATBOT_HITL_ENABLED=true`
- `CHATBOT_INTENT_HITL_ENABLED=true`
- `CHATBOT_INTENT_OUTPUT_LABELS` 含 `hybrid_qa`（默认已含）
- 首轮意图 HITL 按钮应为四项：  
  `route_data_query` / `route_kb_qa` / **`route_hybrid_qa`（综合查数+知识）** / `route_clarify`

默认规则后端下，**「一句双标」几乎不再进 HITL**；测 HITL 请优先用 §3，或切 `CHATBOT_INTENT_BACKEND=llm` / `bert` 测 §4。

## 2. 回归：旧「可触发 HITL」示例 → 现应 **Hybrid 直答（不弹）**

下列问法原先靠「查数说法 + 知识说法」混在一句里弹 HITL；改造后规则判 `hybrid_qa` / `mixed_hybrid`，**应跳过意图 HITL**。

### 缺陷 / 台账 / 工单

- 「1号炉当前负荷是多少，为什么负荷波动影响燃烧？」
- 「查询主汽温度记录，超标标准是什么？」
- 「查询最近缺陷记录，为什么会频繁出现裂纹？」
- 「列出本月缺陷单有多少条，常见原因是什么？」
- 「台账里工单有多少，处理依据是什么？」

### 检修

- 「查询上次检修记录，检修周期标准是什么？」
- 「列出#3炉检修记录，如何预防同类缺陷？」
- 「统计本季度检修工单数量并说明为什么延期」

### 壁厚 / 四管健康

- 「统计水冷壁壁厚测点有多少，减薄机理是什么？」
- 「列出壁厚不合格测点，危害和风险有哪些？」

### 泄漏 / 泄爆

- 「今天有多少泄漏报警，什么原因？」
- 「查询最近泄漏记录有多少，爆管原理是什么？」
- 「列出泄爆相关台账，如何预防？」

### 运行参数 / 清单

- 「列出受热面设备清单，材质定义是什么？」
- 「查出超温点列表并结合规程说明如何处置」

**期望：** `intent_label=hybrid_qa`，SSE **无** `chatbot_hitl_required`；可出现 `meta.used_nl2sql` + `used_rag`（或 `hybrid_degraded` 降级）。

### 对照：仍不 HITL 的纯意图（不变）

- 「查询最近缺陷记录」→ 纯查库 `data_query`
- 「过热器爆管常见原因是什么？」→ 纯知识 `kb_qa`
- 「锅炉四管泄漏的应急处置流程是什么？」→ 纯知识
- 「上次检修是什么时候？」→ 纯查库

## 3. 当前可触发意图 HITL 的问法（真模糊 · 规则后端可稳定复现）

### 3.1 有会话历史时的指代 / 歧义续问（推荐首轮 HITL 演示）

先发一轮清晰知识问答（写入历史），再发短指代句。规则 reason 含 `ambiguous_pattern_resolved_by_ctx`，且标签不是 `clarify` → **会弹** `intent_route_confirm`。

**准备（上一轮用户问，任选）：**

- 「过热器爆管常见原因有哪些？」
- 「水冷壁减薄的危害有哪些？」

**本轮（期望 HITL=YES）：**

- 「这个怎么办」
- 「那个啥意思」
- 「怎么弄」

**不期望弹意图 HITL（走续写知识或过短闸，供对照）：**

- 「这个」（短续写 `short_followup_continues_thread`，高置信续 `kb_qa`，通常不弹）
- 无历史时单独发「这个怎么办」→ `clarify`，**不弹**意图 HITL（产品设计：规则 clarify 不进意图确认面板）

### 3.2 二次 HITL（消歧 · `intent_disambiguation_suggest`）

路径（需先进入过首轮意图 HITL）：

1. 用 §3.1 触发首轮四钮；
2. 点 **「我先补充问题」**，`refined_query` 仍故意写含糊，例如：  
   - 「超温相关，你看着办」  
   - 「数据和原因都行」  
   - 「还是那个事，再帮我看看」
3. 若重分类后仍满足 `should_trigger_intent_hitl` → 进入二次消歧。

**期望：** `hitl_kind=intent_disambiguation_suggest`；选项含 `route_hint` ∈ `{data_query, kb_qa, hybrid_qa}`（兜底第三项多为「综合查数+知识」）。

> 若补充后规则已能判成清晰 `hybrid_qa` / 纯查数 / 纯知识，则**直接作答、不再二次 HITL**——这也是「清晰不强弹」的预期。

## 4. 真模糊 · 依赖 LLM / BERT 后端（或低置信）时的问法

当 `CHATBOT_INTENT_BACKEND=llm` 或 `bert` 时，下列更容易落到「低置信 / 标签与问句不完全一致」，从而弹首轮 HITL（规则后端往往直接 `default_kb_qa` 高置信而不弹）。

### 4.1 边界短问 / 主题笼统（期望低置信 → HITL）

- 「超温相关情况」
- 「帮我看看超温」
- 「缺陷情况怎么样」
- 「泄漏的事」
- 「测点异常」
- 「1号炉有点问题」

### 4.2 「像混合但表述不清」（可能判 hybrid 低置信，或判成单路但仍冲突）

- 「查数还是问原因都行，关于超温」
- 「超温数据和原因随便哪个」
- 「台账和规范」（词面上像混合，意图却空）

**期望：** 若 `label=hybrid_qa` 且 conf 较低（&lt; 约 0.75）或非 `mixed_hybrid` 清晰理由 → **仍可弹 HITL**；  
若被规则/模型打成清晰 `mixed_hybrid` → **不弹**、走 Hybrid。

### 4.3 标签与问句冲突（常见于 LLM 改判后）

模型给出 `kb_qa` 但问句仍带查数侧词，或给出 `data_query` 却带原因/标准侧词时，HITL 仍会按「双标记 / mixed_* / 低置信」收口。可用手工或日志确认 `intent_label` + `intent_confidence` 后再断言。

示例问句（在 llm 后端下观察，勿在纯 rules 下当必现用例）：

- 「当前负荷为什么波动」（规则多为纯知识高置信→不弹；llm 低置信或冲突时可弹）
- 「查一下超温原因」
- 「台账规定是什么」

## 5. 触发条件备忘（实现口径）

意图 HITL **会**触发（摘要）：

1. `conf < CHATBOT_INTENT_HITL_MIN_CONF`（默认 0.75）
2. reason 含 `ambiguous_`（且不是被 `clarify` 提前短路）
3. reason 含 `mixed_` 但 **不是** `mixed_hybrid`（历史/LLM 旧口径）
4. `label=data_query` 且问句仍命中概念侧，或 `label=kb_qa` 且仍命中查数侧
5. 问句同时命中 HITL 双侧 hint 词（查数侧：多少/列表/查询/当前/台账/…；知识侧：为什么/原因/机理/标准/…）——且未被高置信纯意图提前豁免
6. **`label=hybrid_qa` 的清晰混合不触发**（`mixed_hybrid` 或足够置信）

意图 HITL **不会**触发：

- 清晰 `hybrid_qa`（场景 B）
- 高置信纯 `structured_query_heuristic` / `conceptual_qa_heuristic` / `default_kb_qa`
- `intent_label=clarify`
- 已有 `confirmed_route`、带图、轮次用尽等

## 7. 一句话版本（给测试同学）

- **旧「查出 X 并说明为什么/标准/如何预防」→ 现在验 Hybrid，不要验 HITL。**  
- **要验 HITL（默认 rules）：同一会话先发一轮知识问，再发指代短句。**

### 可稳定触发首轮意图 HITL 的 5 条完整示例（两轮）

在**同一会话**按顺序发送；第 2 轮期望出现 `chatbot_hitl_required` / `intent_route_confirm`（四钮含「综合查数+知识」）。

| # | 第 1 轮（先发，写入历史） | 第 2 轮（再发，触发 HITL） |
|---|---------------------------|----------------------------|
| 1 | 过热器爆管常见原因有哪些？ | 这个怎么办 |
| 2 | 水冷壁减薄的危害有哪些？ | 那个啥意思 |
| 3 | 锅炉启停有哪些注意事项？ | 怎么弄 |
| 4 | 四管泄漏应急处置流程是什么？ | 这个怎么办 |
| 5 | 蠕变寿命损耗机理是什么？ | 那个啥意思 |

说明：第 2 轮单独开新会话发「这个怎么办」只会走 `clarify`、**不弹**意图 HITL；必须接在第 1 轮之后。
